## 2. Summary

- **No `URGENT` findings.** Nothing inspected suggested fabricated provenance, fabricated locators, unsafe clinical overclaiming, or an immediately unreliable release surface.
- **One high-confidence `ISSUE`: parallel unversioned ATOM → validation → SEA lineages exist for the same source.** `ciag422.pdf` has two materially different ATOM sets from the same source hash, each with its own passing validation and SEA, but without versioning or canonical-lineage signaling. This is tracked in [#2 — Normalize duplicate LiteratureAtom lineages for identical source artifacts](https://github.com/cfowla/knowledge/issues/2).
- **Validation durability remains a `WATCH`.** At least one newly repository-visible production-like ATOM+SEA pair (`NEJMoa0802743`) has no validation companion under the repository's common validation naming patterns. The lightweight review cannot yet distinguish a legacy/import exception from a true validation omission.
- **Source traceability is generally strong inside artifacts but repository-only reinspection is limited.** Sampled artifacts carry source filenames/hashes and detailed provenance, while primary PDFs are intentionally excluded from Git. The external retrieval/reinspection path is therefore important to durability.
- **Sampled SEA framing and structure were good.** Evidence, interpretation, scope limits, figures/tables, and appraisal were visibly separated in inspected HTML; the review did not perform pixel-level browser rendering.
- **Naming/relationship drift is not isolated.** The synced corpus contains multiple role suffix conventions (`-atoms`, `_atoms`, `.atoms`, `-ATOM`; multiple validation forms; `-sea`, `_SEA`, `.sea`). A cleanup commit during the interval (`Fix artifact naming and remove copied tools`) plus residual drift indicates maintenance debt rather than a single anomalous filename.

## 4. Escalations

### Created

- [`ISSUE` #2 — Normalize duplicate LiteratureAtom lineages for identical source artifacts](https://github.com/cfowla/knowledge/issues/2)
  - **Evidence:** same `ciag422.pdf` SHA-256; 69-atom and 30-atom unversioned ATOM sets; separate passing validations; separate unversioned SEAs; broader suffix drift in the synced corpus.
  - **Impact:** ambiguous canonical evidence representation and ATOM→validation→SEA lineage; downstream tools can choose different representations of the same source.
  - **Acceptance criteria:** define canonical naming/versioning, reconcile `ciag422`, scan other same-source duplicate roles, stop sync/generation from silently reintroducing unversioned alternates, and add a lightweight duplicate-lineage guard.

Open-issue searches for `ciag422 duplicate ATOM SEA naming`, `duplicate artifact naming validation SEA ATOM`, and `artifact lineage corpus consistency naming` returned no equivalent open issue before #2 was created.

### Not escalated this week

- **Validation durability (`WATCH`):** `NEJMoa0802743` demonstrates a repository-visible ATOM+SEA pair without a common validation companion, but this pass did not establish whether synced historical/legacy artifacts are expected to satisfy the same current production validation contract. Escalate next review if coverage sampling shows repeated unexplained missing validation among artifacts intended as current production outputs.
- **Repository-only source reinspection (`WATCH`):** PDFs are intentionally outside Git; no issue was created without first establishing that the external source-retrieval convention is insufficient or broken.
- **HTML render verification (`WATCH`):** semantic structure was inspected, but a browser-render pass was not part of this lightweight review.
