One-page synthesis

Verdict: Read first for agent-harness design; do not treat as proof that coding agents generally replicate science.
The paper is highly relevant if you are building evaluation workflows, RAG/agent evidence systems, reproducibility checklists, or structured appraisal artifacts. Its strongest contribution is not the headline success rate; it is the target-level evidence contract that separates paper claims, generated outputs, provenance, comparisons, and final report coverage.

Core thesis. The authors argue that direct prompts are inadequate for paper replication because an agent can lose state, confuse progress with evidence, reuse paper assets, substitute methods, or declare completion in a final message. Their proposed workflow, Paper-replication, makes each selected paper claim a target and requires an evidence bundle before the target can be marked matched: generated output, run record, provenance, comparison against the paper claim, and report coverage.

Main evidence. The case study evaluates 12 independent Codex workspaces across 4 scientific machine-learning papers: PIFT, PINN-I, PINN-II, and SINDy. The authors report that all 12 workspaces passed the completion gate, all 158 recorded targets reached MATCHED, and every matched target had report coverage. The workspaces also show variability in target decomposition, numerical fidelity, elapsed time, correction work, and acceptance-rule type.

Main limitation. Completion is explicitly relative to the target list recorded by the agent and the validation checks applied to that list. The study has no no-skill baseline, no ablation, no independent human audit of omitted claims, only four papers, one coding-agent interface/model setting, and a self-evaluation structure in which the authors evaluate their own skill. The result supports a useful harness pattern, not a general claim that agents can autonomously reproduce the scientific literature.

Best useBlueprint for durable agent workspaces: source inventory, target matrix, task ledger, run recorder, provenance records, output/paper-asset separation, comparison checks, and report-coverage gates.
Do not use forCapability benchmarking without a baseline, proof of exact numerical reproducibility, evidence that all paper claims were captured, or operational replacement of expert reproducibility review.

Task, method, and validation design

Task definitionReconstruct computational claims from paper materials, regenerate supporting results, and record evidence for each claim. The paper distinguishes this from simply rerunning an existing author package.
Agent settingCodex with GPT-5.4 at Extra High reasoning, using the Paper-replication skill. Author code was not allowed. Some runs used local MacBook Pro compute; some PINN targets used Purdue cluster jobs.
Evaluation corpusFour scientific machine-learning papers: PIFT, PINN-I, PINN-II, and SINDy. Each had three independent runs under the same prompt templates, materials, tools, compute environment, and no-author-code policy.

Evidence contract

For each target, the agent must record the claim location, source support, method component, required output, acceptance rule, current status, and report location. A target can be marked matched only when the workspace contains the generated output, successful run record, provenance, comparison evidence, and report coverage. The paper’s central control move is that the agent’s final message is not accepted as evidence; the workspace state is.

Target-level evidence bundle:
E_j = (generated candidate result, execution record, provenance record, comparison evidence, report coverage)

Completion gate:
Specification check passes AND progress/evidence check passes AND report-coverage check passes AND every recorded target is MATCHED AND no active target remains AND final report PDF exists.

Section-by-section condensation

Abstract

The abstract frames scientific machine-learning papers as collections of computational claims, such as error thresholds or uncertainty-coverage claims. It states that a coding agent can attempt replication from paper materials but that prompts alone do not reliably preserve progress or verify evidence.

The proposed Paper-replication workflow converts selected claims into evidence targets and implements this as a coding-agent skill. In twelve runs across four SciML papers, all workspaces passed the completion gate and all 158 recorded targets had matched report coverage, but repeated runs still differed in decomposition, fidelity, elapsed time, correction work, and acceptance rules.

Introduction

The introduction situates the problem in computational reproducibility for scientific machine learning, where reported results depend on code, data, solvers, preprocessing, stochastic training, seeds, and implementation choices. It distinguishes paper-only replication from rerunning an author-provided package and reviews related code-generation and paper-reproduction benchmarks.

The gap is framed as an evidentiary one: existing agent and benchmark work shows agents can write code or run experiments, but paper replication needs durable target records, provenance, comparison evidence, and completion checks. The authors present Paper-replication as harness engineering: add a persistent workspace and validation checks instead of relying on prompt instructions or final-message claims.

Methods — target and evidence model

The methods define a paper as materials available to the agent, including LaTeX, figures, tables, bibliography, appendices, and data references. The agent records a finite target set of computational claims, where targets may be scalars, figures, tables, learned fields, posterior distributions, trajectories, discovered equations, or structural statements.

Each target receives an evidence bundle with candidate result, execution record, provenance, comparison evidence, and report coverage. Acceptance rules are claim-specific: numeric targets use metrics and tolerances, distributional targets compare statistical properties, structural targets compare patterns or relationships, and visual targets require visual comparison when appearance is the claim.

Methods — persistent workspace and validation

The persistent workspace records the source inventory, hashes, reproduction matrix, task ledger, specification files, run records, provenance records, comparison evidence, report coverage, and final report. The agent is constrained to one active target at a time and must keep paper-provided assets separate from generated outputs.

Validation checks reject missing specifications, inconsistent target state, copied paper assets based on path/hash, missing provenance, insufficient comparison evidence, and absent report coverage. Completion requires all checks to pass, every target to be matched, no active target, and a final report PDF. The paper acknowledges that this does not prove every possible paper claim was included or that exact numerical equality is attainable.

Methods — case-study analysis

The case study uses four SciML papers and three independent runs per paper under the same paper materials, prompts, tools, compute environment, and no-author-code rule. Follow-up prompts reopen the same workspace and continue until the completion gate passes.

The analysis measures paper-level completion, target coverage, scalar fidelity using paper-anchored thresholds, elapsed replication time, tracked/superseded executions, and judgment variation in acceptance rule type. Bayesian models describe target counts, scalar headroom, and elapsed effort, but the paper treats these models as corpus descriptions rather than definitive rankings of difficulty.

Results

All twelve workspaces passed the completion gate, and all 158 recorded targets reached MATCHED with report coverage. Target decomposition varied: PIFT had 8, 8, and 25 targets; PINN-I had 8, 8, and 8; PINN-II had 9, 9, and 15; SINDy had 20, 20, and 20. The extra targets reflected different decomposition choices rather than incomplete workspaces.

For scalar anchors, 37 of 39 observations fell within fixed paper-anchored thresholds. Two were outside: Schrödinger run 3 relative L2 error of 4.8 × 10^-2 against a 1% threshold, and Navier-Stokes λ2 run 1 coefficient error of 16.4% against a 10% threshold. Elapsed replication time ranged from 1.2 to 13.0 hours, with most superseded executions occurring in the PINN papers. Acceptance-rule agreement varied from 0.46 for PINN-II to 0.95 for SINDy.

Discussion and conclusion

The discussion emphasizes that completion is a workspace state relative to the recorded target set and checks, not proof that all possible aspects of a paper were replicated. The workspaces preserve not just completion labels but also decomposition differences, correction paths, numeric fidelity variation, and judgment variation.

The conclusion states that Paper-replication supports inspectable replication by decomposing papers into targets and linking generated outputs to provenance, comparisons, and report coverage. It explicitly frames the approach as an inspectable process, not a guarantee of exact reproduction or proof that the completed workspace covers every possible paper claim.

Evaluation and appraisal

Bottom line. Strong as a workflow-design paper and useful as a template for agent evidence governance. Moderate as empirical evidence. Weak for broad capability claims because the evaluation is small, self-contained, non-comparative, and dependent on an agent-selected target list.
Relevance9 / 10

Directly relevant to agent harnesses, scientific curation, reproducibility workflows, and deterministic evidence gates. Evidence basis: target matrix, provenance checks, completion gate, and case-study workspaces. Limiting factor: less relevant to clinical practice or ordinary ML benchmarking. Higher if paired with an audited public implementation; lower if the reader only needs model-performance benchmarks.

Novelty8 / 10

The target-level evidence contract and workspace-completion framing add practical structure beyond prompt-only replication or code-generation benchmarks. Evidence basis: explicit target/evidence model, persistent workspace, and report-coverage gate. Limiting factor: many ingredients build on known reproducible-research and agent-evaluation practices. Higher with clearer contrast to existing harnesses; lower if similar systems already implement equivalent target/provenance gates.

Method strength5.5 / 10

The repeated-run case study is useful but narrow and lacks a baseline or ablation. Evidence basis: 12 runs, 4 papers, standardized prompt templates, recorded workspaces, and Bayesian descriptive summaries. Limiting factor: no no-skill comparator, no independent target-list audit, one agent/model/interface, and self-evaluation. Higher with randomized baseline comparisons and external reviewers; lower if released workspaces cannot be reproduced.

Evidence strength5.5 / 10

The data support the narrower claim that this workflow can produce completed workspaces in this corpus, but not the broad headline that agents can generally replicate papers. Evidence basis: 158 recorded targets, completion gate results, scalar headroom, elapsed-time and correction-work analyses. Limiting factor: completion is conditional on recorded targets and acceptance rules. Higher with independent validation of every target and omitted-claim search; lower if target selection or acceptance rules are found permissive.

External validity4 / 10

Generalization outside similar scientific machine-learning papers and the specific Codex setup is uncertain. Evidence basis: corpus restricted to four SciML papers, three runs each, one agent interface/model setting, high-resource compute. Limiting factor: no clinical, wet-lab, statistical, social-science, or heterogeneous document corpus evaluation. Higher with multi-domain, multi-agent, multi-site evaluations; lower if performance depends on paper type or expensive compute.

Implementation value8 / 10

The workflow is build-useful even if the empirical claims are preliminary. Evidence basis: concrete artifacts named throughout the paper: manifest, matrix, ledger, specs, run recorder, provenance records, comparison checks, and report coverage. Limiting factor: operational details require repository audit and adaptation. Higher with schema definitions and validator examples; lower if the code is hard to run or not maintained.

Strengths

  • Defines completion as a verifiable workspace state rather than an agent message.
  • Separates target identification, method reconstruction, output generation, provenance, comparison, and report coverage.
  • Records negative path information through failed or superseded executions.
  • Distinguishes scalar, structural, distributional, and visual evidence instead of forcing all claims into exact numeric equality.
  • Openly states key limitations: completion is relative to recorded targets and checks; hash checks do not detect every transformed copy; accepted evidence is not proof of unique implementation.

Limitations and bias risks

  • No baseline. The paper does not compare Paper-replication against direct prompting, a simpler checklist, PaperBench-style grading, or another agent workflow.
  • No ablation. The contribution of the target matrix, task ledger, provenance records, report coverage, and completion gate cannot be separated.
  • Self-evaluation. The authors built the workflow and evaluated it; an independent audit would be more persuasive.
  • Target completeness remains vulnerable. If the agent omits a claim or defines a target too coarsely, the completion gate can still pass relative to that target set.
  • Acceptance-rule plasticity. Runs differ in rule type for the same aligned claim, especially in PINN papers, which can weaken comparability.
  • Compute and model dependence. Results use a specific Codex configuration and high-resource local/cluster environment.

Confidence in appraisal

Moderate. The uploaded PDF provides enough detail to evaluate the conceptual workflow, case-study design, results, and stated limitations. Confidence is not high because the released code, prompts, workspaces, and analysis scripts were not independently inspected or rerun.

Implementation and practice takeaways

Adopt the evidence bundle patternFor any agent-generated scientific appraisal, require: source claim, generated artifact, command/run record, code/config/seed provenance, comparison rule, and final report location.
Use a target matrixDo not let an agent summarize progress narratively. Store claims, source locations, status, acceptance rules, outputs, and report coverage in a structured file.
Keep one active targetA task ledger with one active target reduces drift, partial completion, and accidental reuse of stale outputs.
Separate paper assets from outputsUse directory separation plus hashes to prevent paper-provided figures/tables from being counted as generated evidence.
Validate before reportingCompletion should be blocked until specification, progress/provenance, comparison, and report-coverage checks pass.
Record disagreementWhen acceptance-rule type varies across runs, preserve that variation; it is evidence about judgment instability.

Useful adaptations for your reference-HTML workflow

  • Add a manifest gate before drafting: exact title, source type, sections, figures, tables, workflows, omissions.
  • Require figure/table/workflow reconciliation before appraisal scores are assigned.
  • Use provenance fields for generated artifacts: evaluated file, extraction method, visual strategy, known omissions, and QA checks.
  • For AI/ML papers, record whether claims are numeric, structural, distributional, visual, or workflow-level.
  • Separate “matched under the source’s stated rule” from “externally convincing under a stricter appraisal rule.”

What would make the paper stronger

  • A no-skill baseline and a simpler-workflow baseline.
  • Ablations of the matrix, ledger, provenance, asset checks, and report-coverage gate.
  • Independent expert review of target completeness and acceptance-rule adequacy.
  • Cross-agent replication using different coding agents and model families.
  • Adversarial tests for transformed paper-asset reuse and method substitution.
  • Evaluation across more domains, including non-SciML computational papers and papers with incomplete or messy supplementary materials.

What not to overclaim

Tempting claimSafer interpretation
“Coding agents can replicate scientific machine-learning papers.”In this study, a specific Codex setup using the Paper-replication skill completed 12 recorded workspaces across 4 selected SciML papers under the authors' completion gate.
“All claims were replicated.”All recorded targets were matched. The paper itself notes that completion is relative to the recorded target set and checks.
“The numerical results were reproduced exactly.”Most scalar anchors fell within fixed thresholds, but exact equality is not expected when seeds, sampled training sets, optimizer states, and preprocessing details are missing.
“The workflow prevents copied or substitute evidence.”The workflow reduces this risk through directory separation, hashes, provenance, and comparison checks; it does not prove all transformed copying or method substitution is impossible.
“This is a validated benchmark of agent ability.”The paper is better read as a workflow and case-study report. It does not include broad benchmark coverage, baseline comparison, or independent grading.
