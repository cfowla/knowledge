One-page synthesis

Core thesis: “verbalized confidence vs token likelihood” is not a single comparison. The preferred signal can change when the exact answer, scoring context/slot, token readout, or evaluation criterion changes—even while the question, answer string, and correctness label are held fixed.

The paper’s strongest design move is its prediction-event invariant: verbalized confidence, token score, and correctness label must all refer to the same exact answer on the same item. The authors generate one answer with a confidence prompt, fix its label, and teacher-force that answer into alternative valid token-scoring contexts. This isolates measurement protocol from answer-generation changes.

The most consequential operational choice is context/answer slot. In the main 12 settings, moving the token readout from the bare assistant turn to the confidence prompt’s Guess: slot changes the ECE comparison by mean |Δg| 0.254 and the AUROC comparison by 0.158. By contrast, substituting the canonical reference for the model’s own answer moves the ECE gap by 0.077; switching span likelihood to first-token probability moves it by 0.052; alternative calibration-error estimators move it only 0.006–0.026 in the bare context.

The result is not just score rescaling: macro AUROC for token confidence rises from 0.604 in the bare turn to 0.762 in the Guess: slot, which implies item reordering because AUROC is invariant to any common order-preserving transformation. The Guess: slot also rewards answers generated in that slot by +0.216 relative to bare-origin answers, whereas the bare turn shows essentially no origin advantage (−0.002). Thus, its strong discrimination partly reflects an in-context effect rather than a portable property of the answer position.

Verbalized confidence is also answer-formulation sensitive. Supplying the canonical TriviaQA reference instead of the first accepted alias raises confidence by +0.072 despite both answers being correct. Across supplied-answer tests, canonical gold averages 0.850 confidence versus 0.783 for plausible wrong answers; the paired separation is only +0.031. These findings weaken any interpretation of a confidence number as a context-free correctness probability.

High-value contribution: the paper turns a broad “prompt sensitivity” concern into a concrete measurement-validity rule and reporting checklist. For benchmark design, evaluator construction, uncertainty pipelines, or agent abstention systems, the actionable message is to validate the full answer/context/readout/metric protocol—not merely the model or scalar confidence method.

Section-by-section condensation

Abstract & Introduction

The paper argues that head-to-head comparisons of verbalized confidence and token likelihood are under-specified unless they define the exact prediction event and measurement protocol. Token likelihood varies with the scored string, prompt, answer position, and aggregation. The authors identify the question + exact answer + correctness label as the invariant object that both confidence signals must evaluate.

They motivate the study with a targeted audit of 12 published comparisons and preview the main empirical result: changing only the token-scoring context can reverse which signal appears better under ECE, AUROC, or AURC. Additional tests vary the scored string and token readout, while a supplied-answer experiment tests whether verbalized confidence tracks correctness independently of wording.

2. Related Work & 2.1 Targeted Audit

The related-work section separates verbalized confidence elicitation, token-based confidence construction, calibration estimators, and answer/ownership effects. The paper positions itself as a same-answer measurement study: instead of changing a prompt and allowing a new answer, it fixes one answer and asks whether its measured confidence comparison survives a change in scoring context.

The targeted audit screens 22 candidates and includes 12 studies that evaluate a self-reported/verbalized signal and a probabilistic signal tied to one candidate answer while making a comparative claim. All 12 specify the rated answer, 10/12 the scored string, 6/12 aggregation, and only 7/12 the conditioning context/answer slot. Of those seven, four use a generation-style context and three an elicitation/self-report context. The authors explicitly frame this as an included-set finding, not a prevalence estimate for the field.

3.1 Models, Data, and Elicitation

Main models are Llama-3-8B-Instruct, Mistral-7B-Instruct-v0.3, and Qwen2.5-7B-Instruct. Datasets are TriviaQA (1,000 items), SciQ (1,000), TruthfulQA (817), and four MMLU subjects totaling 1,155 items. Qwen2.5 14B/32B/72B runs are robustness checks rather than a scaling study; matching base checkpoints form a separate instruction-tuning check.

Models use greedy decoding and return a short answer after Guess: plus a decimal probability after Probability:. Correctness uses a fixed normalized-string rule with containment; SciQ/MMLU use correct option text rather than letters in the main analysis. Main-setting joint parse rates are at least 0.966. A native multiple-choice control later uses exact option letters.

3.2 Same Answer Across Token Contexts

The core experiment generates one answer-confidence pair, fixes the answer and its correctness label, then teacher-forces that same answer in three token-scoring positions: the start of a bare assistant turn, an assistant-side Answer: slot, and the confidence prompt’s Guess: slot. The boundary-matched Answer: condition addresses tokenization/boundary differences; an invalid direct-prefix position is explicitly excluded because the prompt expects a marker there.

The primary token score is the mean log probability across the answer span; a first-answer-token probability is a secondary readout. A reciprocal control begins from an answer generated by a probability-free prompt and then moves that fixed answer into alternative contexts. The authors correctly distinguish this reciprocal analysis from a causal origin test because the two directions use different answers and different confidence-elicitation procedures.

3.3 Evaluation and Uncertainty

For each context, the paper computes a paired gap between verbalized-confidence performance and token-confidence performance. ECE captures numerical reliability, AUROC correctness discrimination, and tie-aware AURC selective-prediction risk. The primary calibration estimator is equal-width 10-bin ECE, with KDE-ECE, KS-Cal, and Smoothed ECE as checks.

All comparisons use matched rows and paired nonparametric bootstrap intervals. The authors are careful about semantics: the verbalized value is solicited as a correctness probability, whereas span likelihood is a probability of the answer string. Accordingly, raw ECE is treated as a comparison used in prior work, not proof that token likelihood is intrinsically a correctness probability. A cross-fitted Brier-loss transfer test asks whether a mapping learned in one token context remains valid in another.

3.4 Supplied-Answer Diagnostic

To test answer sensitivity, the model receives a candidate after Guess: and generates only Probability:. Candidates include canonical gold answers, plausible wrong answers produced by another model when available, off-type wrong answers, and the model’s own answer re-supplied as a formatting control.

Correctly answered items also compare confidence on the generated answer with confidence on the canonical gold string, while TriviaQA permits a stronger formulation test between two accepted references. This design isolates whether confidence changes when correctness does not.

4.1 Context Changes the Preferred Signal

Moving token scoring from the bare turn to Guess: changes the ECE winner in 4/12 settings and the AUROC winner in 9/12; the corresponding paired contrast excludes zero in 11/12 ECE settings and 9/12 AUROC settings. The boundary-matched Answer: → Guess: comparison yields 3/12 ECE and 9/12 AUROC winner changes. AURC changes winner in 3/12.

The macro AUROC result is particularly diagnostic: token AUROC increases from 0.604 (bare) to 0.762 (Guess:), proving that context changes item ranking rather than simply applying a monotone rescaling. The origin control finds essentially no advantage for prompted-origin answers in the bare turn (−0.002, 95% CI −0.005 to +0.001) but a +0.216 advantage in the Guess: slot, so part of the latter’s strength is context-specific.

4.2 Measurement-Choice Sensitivity

Context/slot is the largest measured source of movement: mean |Δg| 0.254 under ECE and 0.158 under AUROC. Scoring the canonical reference instead of the model answer moves the gap by 0.077 ECE / 0.041 AUROC and changes the winner in 2/12 / 3/12 settings. Replacing answer-span likelihood with first-token probability moves it by 0.052 / 0.049 and changes the winner in 1/12 / 4/12.

Calibration-estimator choice is substantially smaller: alternative ECE estimators move the bare-context gap by only 0.006–0.026 on average, with no bare-context winner changes; Smoothed ECE changes one prompted-context winner. Strict-format parsing, integer 0–100 confidence, native multiple-choice formatting, post-hoc calibration transfer, larger Qwen checks, and base-model checks all retain evidence of context dependence.

4.3 Verbalized Confidence Depends on the Answer Presented

Mean verbalized confidence is 0.850 for canonical gold, 0.783 for plausible wrong, and 0.240 for off-type wrong answers. After question-level pairing and removal of semantically correct “wrong” candidates, gold exceeds plausible wrong by only +0.031 (95% CI +0.025 to +0.038). In a 223-case benchmark-verified wrong subset, gold is not higher in 64.6% of pairs.

TriviaQA provides the strongest same-correctness formulation test: replacing the first accepted alias with the canonical reference raises confidence by +0.072 overall and +0.096 when the strings actually differ. Re-supplying a model’s own answer changes mean confidence by at most 0.011, so a simple prefill-formatting artifact does not explain the effect.

4.4 Reporting Implications

Crossing three answer slots, two scored strings, and two readouts produces 12 measured token protocols. Across this grid, the ECE gap spans 0.391 on average and leaves the sign of the comparison undetermined in 6/12 settings. For answer-span AUROC protocols, the gap spans 0.219 and is undetermined in 10/12 settings. These are lower bounds because only measured variants are included.

The paper therefore proposes five reporting requirements after first enforcing prediction-event alignment: answer provenance; exact scored answer string; token readout/aggregation; conditioning context and answer slot; and evaluation criterion/estimator. It further distinguishes self-abstention from candidate verification: the correct protocol must attach confidence and correctness to the answer actually being acted upon.

5. Conclusion

The paper concludes that confidence-signal ordering is partly a property of the measurement protocol. The main context intervention changes the point-estimate winner in 4/12 ECE, 9/12 AUROC, and 3/12 AURC settings; scored-string and readout choices can also reverse conclusions, while estimator choice is smaller.

The recommended remedy is not to declare one confidence signal superior but to define the prediction event first and report the complete protocol. Confidence values and thresholds should be revalidated in the exact context where they will be used.

Limitations

External validity is constrained to English, short-answer QA, greedy decoding, three main open 7–8B Instruct models, and benchmark correctness rules. Larger-model checks are confined to one Qwen family; base-model checks have low, nonrandom retention and one nearly degenerate Mistral label distribution. Long-form generation, dialogue, code, tool use, closed models, multilingual tasks, and judge-based semantic correctness remain untested.

The primary context contrast combines instruction text, chat-turn boundary, and answer marker, so it does not identify a single causal prompt feature. The reciprocal control is a transfer check rather than a causal origin manipulation. The targeted protocol audit has one rater, only 12 included studies, and does not estimate field-wide prevalence. None of ECE, AUROC, or AURC establishes a coherent epistemic uncertainty quantity or deployment-safe threshold.

Ethical Considerations

The experiments use released models and public QA benchmarks without training, deployment, user data, or human participants. The authors identify over-interpretation of confidence scores as the central risk: a favorable number can encourage misplaced trust when the number is protocol-dependent.

The paper accordingly emphasizes reporting and target-domain validation rather than recommending either confidence signal as a standalone reliability measure. The benchmark setting also does not support broader fairness, truthfulness, or real-world safety claims.

Evaluation and appraisal

Verdict: Read first. The paper is highly useful as a measurement-validity and evaluator-design reference. Its main contribution is not a new calibration algorithm but a defensible protocol for deciding what is actually being compared.
9/10
Relevance

Directly addresses LLM reliability evaluation, confidence measurement, benchmark validity, and reproducible evaluator design.

Evidence basis: same-answer protocol, audit, robustness grid. Limiter: not an agent/tool-use or clinical-domain study. Would increase: replication in long-form, agentic, and domain-specialized settings.

8/10
Novelty

The prediction-event alignment rule and systematic cross-protocol comparison provide a clear conceptual advance over generic prompt-sensitivity warnings.

Evidence basis: controlled context/slot intervention and 12-protocol grid. Limiter: prompt/context sensitivity itself is established territory. Would increase: mechanistic decomposition of why contexts reorder confidence.

8.5/10
Method strength

Strong matched design, teacher-forced same-answer comparisons, paired bootstrap intervals, multiple metrics, reciprocal/boundary/native-format/larger/base-model controls, and explicit invalid-position exclusion.

Limiter: main context contrast still bundles instruction, boundary, and marker changes; audit is single-rater. Would increase: factorial isolation of prompt components and independent audit annotation.

8/10
Evidence strength

Claims are tightly scoped to measured protocol sensitivity and supported by consistent main and robustness analyses with uncertainty intervals.

Limiter: benchmark-only evidence and limited model/task diversity. Would increase: independent replication across additional families and operational tasks.

6/10
External validity

The effect appears across three Instruct models, four QA datasets, same-family larger models, and some base-model checks, but remains centered on English short-answer QA.

Limiter: no long-form generation, code, agents, tools, multilingual tasks, closed models, or real deployment. Would increase: broader task/model/domain replication with semantic judges and sampled decoding.

9/10
Implementation value

The alignment rule and five-part reporting checklist can be directly incorporated into evaluator specs, abstention systems, confidence benchmarks, and regression tests.

Limiter: it does not prescribe a universal confidence method or threshold. Would increase: packaged protocol tests/reference implementation for common inference stacks.

Strengths

  • Excellent construct alignment. The answer and label are frozen before token context is changed, preventing a common confound.
  • Metric-aware interpretation. The authors distinguish numerical calibration, discrimination, and selective risk rather than treating one scalar as “confidence quality.”
  • Strong negative controls. Boundary-matched placement and exclusion of the invalid direct-prefix position prevent a superficially dramatic but malformed comparison from entering the claims.
  • Useful robustness hierarchy. The study demonstrates that protocol choices do not all matter equally; context/slot is much larger than estimator choice.
  • Transparent correction history. The appendix explains an earlier misaligned analysis and why the revised same-answer comparison changes the conclusion.

Principal limitations / risks of overclaiming

  • The paper demonstrates protocol dependence, not that verbalized confidence or token likelihood is generally poor.
  • The Guess: slot’s strong AUROC/AURC cannot be generalized to supplied candidates because it confers a measurable in-context origin advantage.
  • ECE comparisons are semantically awkward because token answer likelihood is not intrinsically a correctness probability; the paper acknowledges this and uses AUROC/AURC and transfer tests to reduce dependence on that interpretation.
  • The targeted audit is useful for specification examples but too small and single-rater to support prevalence claims about the literature.
  • Deployment claims should be capped: short-answer benchmark correctness is substantially simpler than long-form factuality, multi-step reasoning, or tool-execution reliability.
Appraisal bottom line: high confidence in the internal claim that measured confidence comparisons can reverse under defensible protocol changes. Moderate confidence that the same magnitude/frequency of reversals will generalize outside short-answer QA. The paper is build-useful immediately as an evaluator specification and QA reference, but not sufficient by itself to choose a production confidence signal.

Implementation / research takeaways

1. Define the prediction event first
Persist the exact question/item, exact answer string, and correctness label. Do not compare confidence signals that refer to different answers.
2. Treat confidence as protocol-bound
Store prompt/template version, answer slot/marker, tokenization boundary, scored string, aggregation rule, model checkpoint, and decoding policy as measurement provenance.
3. Separate objectives
Use calibration/reliability metrics, discrimination metrics, and selective-risk metrics separately. Do not collapse ECE, AUROC, and AURC into one “better confidence” verdict.
4. Build counterfactual protocol tests
For a fixed answer and label, rescore under plausible alternative contexts. A result that changes sign should be reported as protocol-sensitive rather than model-intrinsic.
5. Validate the use case
Self-abstention should score the model-generated answer; candidate verification/reranking should score the supplied candidate and its own correctness label.
6. Regression-test wording sensitivity
Include semantically equivalent accepted answers/aliases. Large confidence shifts under correctness-preserving reformulations are a reliability warning.

PredictionEvent:
  item_id

  exact_answer
  correctness_label

ConfidenceMeasurement:
  answer_provenance
  scored_string
  conditioning_prompt_hash/version
  answer_slot + marker
  token_readout / aggregation
  model + tokenizer + chat template
  decoding settings

Evaluation:
  reliability metric + estimator
  discrimination metric
  selective-risk metric
  matched-row policy
  uncertainty / bootstrap procedure
  target use case

Validation rule:
  every score and label used in one comparison must point to the same PredictionEvent
  unless the analysis is explicitly labeled as a substitution/transfer diagnostic
Do not infer from this paper: that the Guess:-slot token score is universally best; that verbalized confidence is unusable; that token likelihood is calibrated probability of correctness; or that one benchmark-derived threshold will transfer across prompts, answer formulations, models, or deployments.
