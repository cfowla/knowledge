One-page synthesis

Verdict: Read first. The paper is unusually useful for document-agent architecture because it makes workspace state explicit and tests the two mechanisms most relevant to stale-state failures: synchronized parsed/native access and reviewable diffs.

Core thesis. Knowledge-work agents fail when the representation used for search, the native file used for editing, and the state shown for review drift apart. StagedWorkspace defines a versioned workspace in which the native file tree is authoritative, parsed records carry source hashes and freshness state, and diffs are derived from accepted versus current workspace versions. This gives search, execution, and review a shared state contract.

Best evidence. The strongest claims come from paired read-axis ablations. On OfficeQA, dual parsed-plus-native access improved Pass@1 over artifact-only access by 12.1 points for GPT-5.4, 10.1 for Gemini 3 Flash, and 8.3 for Gemini 3.1 Pro. On APEX, dual access improved mean rubric score over parsed-only access by 4.7 points for Gemini 3 Flash, 5.5 for GPT-5.4 Mini, and 9.2 for GPT-5.4 Nano. Those paired comparisons support a mechanism claim inside this evaluation setup. The complete-system leaderboard rows are useful context, but they are not causal because attempt budgets, harnesses, parsers, and retrieval systems differ.

Main limit. The evidence remains tied to two benchmarks and one workspace stack. Review-diff evidence comes from only 57 APEX file-editing tasks. A large residual failure slice also remains: 188 of 452 APEX tasks were all-arm-zero for at least one completed model triplet. Better state handling does not solve numerical reasoning, ambiguous table scope, planning errors, or domain mistakes.

Section condensation

Abstract

The abstract frames stale workspace state as a systems problem, not only a model problem. StagedWorkspace combines versioned native files, parsed views tied to content hashes, and review diffs. The headline result is that dual parsed/native access has the highest point estimate for every tested model, with OfficeQA gains of 8.3 to 12.1 points over artifact-only access and APEX mean-rubric gains of 4.7 to 9.2 over parsed-only access.

The abstract also reports large same-model complete-system improvements, including Gemini 3.1 Pro at 63.9% on OfficeQA and GPT-5.4 Nano at 42.1 mean rubric on APEX. Those numbers are attention-grabbing, but the paper later marks the published comparison rows as non-paired. They should not be read as isolated estimates of the workspace mechanism.

1 Introduction

The introduction identifies a practical mismatch in agent systems. Search-friendly parsed text is easy to retrieve, but the native file carries formatting, formulas, embedded objects, and the artifact that must ultimately be submitted. If those two views drift, the agent can reason over stale text or modify a file that no longer matches what it reviewed.

The paper's answer is an explicit workspace-state contract. One native workspace version, one hash-linked parsed index, and one derived review state define what is current. This is the paper's most reusable design contribution because it makes freshness and provenance testable rather than implicit.

2 Related Work

The paper places itself among agent file systems, retrieval systems, document parsers, code-agent workspaces, and artifact-editing agents. Its distinction is not a new parser or file editor. It is the contract connecting native files, parsed content, staged mutations, and review.

The related-work argument is plausible, but novelty rests more on integration and explicit state semantics than on inventing version control or content hashing. Those mechanisms are familiar in software systems. The value is applying them consistently to mixed-format agent work.

3 Methods

At synchronization point t, W_t is the native workspace, C_t is the parsed record set keyed by source path and content hash, and Delta_t is the review diff between the accepted baseline and current workspace. W_t remains authoritative for execution and submission. A parsed record is current only when its source hash matches the native file. Mutating tool batches trigger hash scans and targeted refreshes, which avoids treating old parsed output as current.

The experiment separates two mechanisms. The read axis compares dual, artifact-only, and parsed-only views under fixed model, prompt, parser, retriever, grader, file tracker, and tool budget. The review axis compares visible versus hidden diff tools while keeping dual access fixed. Three independent attempts per task are used for the mechanism studies, with 10,000 bootstrap resamples for uncertainty and matched resampling for paired comparisons.

4 Results

OfficeQA gives the cleanest read-axis signal against artifact-only access. Dual access improves Pass@1 by 12.1 points for GPT-5.4 with p=.005, 10.1 for Gemini 3 Flash with p=.010, and 8.3 for Gemini 3.1 Pro with p=.041. The dual-versus-parsed contrast is strongest for Gemini 3.1 Pro at +9.0 points with p=.018. The other two OfficeQA dual-versus-parsed differences are positive but not reported as significant.

APEX shows the opposite restricted-view weakness. Dual access improves mean rubric over parsed-only by 4.7 points for Gemini 3 Flash with p=.028, 5.5 for GPT-5.4 Mini with p=.014, and 9.2 for GPT-5.4 Nano with p=.0002. Differences versus artifact-only are positive but non-significant. Visible diffs also have higher observed scores on the 57-task review subset, with gains of 2.5, 8.5, and 3.8 points across the three models. The paper does not present that small subset as broad proof of review causality.

5 Discussion, limitations, and future directions

The discussion correctly narrows the causal claim to the paired mechanism ablations. It also notes that final-answer graders cannot directly detect every workspace-state success, that hand-coded trajectories are illustrative, and that fixed parser and retriever choices prevent a clean decomposition of every component. The state contract therefore has evidence as a useful architecture, not evidence as the unique minimal architecture.

The residual APEX failures matter. The system still fails on reasoning, ambiguous scope, wrong computations, planning, domain knowledge, and rubric alignment. Future work proposed by the authors includes varying parser and retriever choices, testing larger edit-heavy suites, adding human review, and defining acceptance criteria over state transitions rather than grading only final outputs.

6 Conclusion and responsible release

The conclusion argues that native files, synchronized parsed views, and reviewable staged changes should be treated as parts of one workspace state. The benchmark results support this claim inside the tested setup, especially when either artifact-only or parsed-only access removes information needed by the task.

Reducto provided in-kind parser API credits. The authors plan a sanitized research implementation on GitHub and state that this was not the production code path used for the reported runs. The paper reports no new dataset or model release and warns that high-stakes uses require qualified human review.

Figure 1. Workspace-state contract

Purpose: Define one authoritative native workspace and two derived views.
Core state:
  W_t = current native workspace files
  C_t = parsed records keyed by source path and content hash
  Delta_t = review diff between accepted baseline W_0 and current W_t
Freshness rule:
  parsed record is current iff recorded source hash == hash of native file
Authority:
  native W_t is used for execution and submission
  parsed C_t is a searchable derived view
  Delta_t is a review view, not a second artifact copy
Failure prevented: agent reads stale parsed content after the native file changes.
This figure carries the architecture. The key choice is not "keep two copies." It is "keep one authoritative artifact and make every derived representation prove freshness against it."

Figure 2. Synchronization after mutation

Agent mutates native artifact
  -> hash scan detects changed paths
  -> workspace state advances
  -> affected parsed entries are invalidated or marked stale
  -> only changed files are reparsed
  -> parsed cache regains hash agreement with native workspace
  -> review diff updates from accepted state to current state

The selective refresh path is important for large document collections. It gives the agent a cheap freshness check without reparsing the full workspace after every edit.

Do not overclaim. The paper does not show that versioned workspace state makes agents generally reliable, that visible diffs always improve editing, or that the full-system leaderboard gains are caused only by the workspace. It also does not establish safety for clinical or other high-stakes use.

Implementation takeaways

1. Make one file tree authoritative

Parsed text, thumbnails, embeddings, and review views should never become competing sources of truth. Native artifacts own execution and submission state.

2. Put a content hash on every derived record

Every parsed page, chunk, embedding, or extracted table should carry the source path and source hash. A hash mismatch means stale, not "probably current."

3. Invalidate narrowly after writes

After mutation, scan hashes and refresh only affected files. This keeps freshness checks cheap enough to run on every edit cycle.

4. Journal mutations against a base version

Record actor, path, base hash, operation, and payload. Reject or rebase an operation if the base hash no longer matches the target.

5. Route tools by representation

Use parsed content for search and text retrieval. Use native bytes for rendering, formulas, programmatic edits, and final deliverables. Do not force one representation to handle both jobs.

6. Review changes, not just files

Produce format-aware diffs tied to accepted and current versions. The reviewer should see what changed and which source version generated the view.

7. Evaluate state transitions directly

Add checks for stale reads, wrong-base writes, unsynchronized cache entries, unreviewed mutations, and submission from the wrong version. Final-answer accuracy alone cannot catch these failures.

Best transfer to the ATOM/SEA pipeline. Treat the primary source file as authoritative, key parsed text and visual extractions to a source hash, store extraction-run provenance, and require every generated atom or appraisal artifact to name the exact source version it came from. Re-extraction should be triggered by a hash change, not by filename reuse.
