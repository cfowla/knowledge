One-page synthesis

Verdict: Read first. The paper is directly useful for anyone designing, validating, or maintaining reusable agent skills. Its strongest contribution is not the exact Qwen-based scorer, but the decomposition of skill quality into inspectable dimensions and the attempt to separate reusable document quality from task-specific downstream compatibility.
Core thesis

Downstream pass rate is a partial and task-dependent measure of skill quality. SkillEval instead evaluates intrinsic properties of SKILL.md documents using fixed semantic directions learned from controlled positive–negative pairs.

Quality model

Seven metrics span applicability, content quality, execution guidance, and robustness: A1 Format Validity; A2 Trigger Clarity; B1 Content Consistency; B2 Technical Specificity; C1 Workflow Integrity; C2 I/O Explicitness; D1 Failure Awareness.

Primary signal

On 518 held-out documents, positive skills scored higher than negative skills across all six learned semantic metrics. The largest mean separation was A2 (0.98 vs −0.96); C1 had the smallest separation (0.08 vs −0.67).

Downstream link

Metric-derived predictions of SkillsBench pass-rate uplift correlated with observed uplift at Pearson r = 0.779–0.787 for B1, B2, C1, C2, and D1. The combined all-metric setting was lower at r = 0.716.

Revision utility

Mean downstream pass rate rose from 18.6% for original skills to 38.3% after LLM-only revision and 48.1% after SkillEval-guided revision: +29.5 percentage points vs original and +9.8 points vs unguided revision.

Most important caveat

The intrinsic labels and controlled negatives are defined by the framework designers. The paper provides strong internal evidence that those directions recover those intended distinctions, but less evidence that the dimensions exhaust real-world skill quality or transfer without recalibration to independently curated ecosystems.

Section condensation — problem, prior work, and methodology

Abstract & Introduction

The paper argues that task-based evaluation conflates reusable skill quality with compatibility between a specific skill, task, model, harness, tool environment, and budget. A single pass-rate number can therefore indicate whether a skill helped in one setting without explaining why it did or did not help. SkillEval reframes part of evaluation as a document-level measurement problem: assess general properties of the skill artifact itself, then use those scores as complementary evidence alongside execution outcomes.

The proposed framework separates quality into four dimensions and seven metrics. A1 is deterministic; the other six are semantic. The semantic approach learns one fixed direction per metric in a frozen language-model representation space, enabling a new skill to be scored by projection rather than by repeated generative LLM judging. The intended advantages are interpretability, reproducibility of the scoring procedure, and explicit auditing/removal of nuisance signals such as length or formatting.

Related Work

The source contrasts task-based approaches such as SkillsBench and SWE-Skills-Bench with intrinsic document evaluation. Task-based methods provide direct evidence of utility but require execution environments and can mix skill effects with executor capability. Intrinsic approaches inspect the skill artifact itself, while LLM-as-a-judge methods offer flexibility but may be sensitive to order, non-target information, model choice, and surface edits.

SkillEval adopts the “internal representations as evaluation signals” line of work: high-level concepts may correspond approximately to linear directions in hidden space, and controlled contrastive examples can be used to identify those directions. The paper positions its contribution as applying this paradigm to fine-grained agent-skill quality.

Metric selection

A1 Format Validity checks whether the skill is valid Markdown with YAML frontmatter and required name/description fields. A2 Trigger Clarity asks whether the description says what the skill does, when to use it, and under what applicability conditions. B1 Content Consistency checks whether the body actually supports the capabilities claimed in the description; B2 Technical Specificity measures executable detail; C1 Workflow Integrity checks complete input→processing→output structure; C2 I/O Explicitness checks explicit contracts, fields, schemas, units, and constraints; D1 Failure Awareness checks failures, boundaries, diagnostics, and recovery.

The design intentionally avoids a single holistic “good skill” score. Each semantic property receives its own training pairs, pooling rule, hidden-space direction, and standardized score so weaknesses can be localized rather than hidden in an aggregate.

Direction learning and scoring

For each semantic metric, the authors build controlled positive–negative skill pairs intended to differ mainly in the target property while keeping task goal, topic, tools, and non-target content stable. A frozen Qwen3.5-9B model supplies hidden states at index 16. Pooling is metric-specific: A2 uses the description; B1 combines description and body; B2/C1/C2 use body mean pooling; D1 uses the final token of the full input. The maximum input length is 20,000 tokens, and no dataset document was truncated.

Each pair yields a representation difference vector. A precomputed confounding direction is projected out, the remaining differences are averaged and normalized to form the metric direction, and a new skill is scored by dot product with that direction. Scores are standardized using mean and standard deviation from positive and negative training skills. Higher z-scores indicate stronger alignment with the positive side of the metric.

Dataset and evaluation setup

The dataset contains 1,647 skills from open-source datasets, public online sources, manual construction, and LLM generation. Metric-specific controlled pairs are split into training and validation sets with no overlap in original documents, tasks, sources, or generation templates. The held-out semantic validation set contains 518 documents: 259 positive and 259 negative.

For downstream evaluation, SkillsBench tasks are run with Codex using GPT-5.5 at xhigh reasoning effort; with-skill and no-skill conditions use the same environment and executor configuration, with three runs per condition. Pass-rate uplift is defined as pass rate with skill minus pass rate without skill. Appendix analyses additionally test scorer backbones, executor-model robustness, hidden-state layers, pooling strategies, and surface-feature bias.

Section condensation — results and interpretation

Held-out intrinsic discrimination

All six semantic directions preserve the intended positive-over-negative ordering on held-out documents. Mean positive/negative scores were A2 0.98/−0.96, B1 0.79/−0.57, B2 0.90/−0.38, C1 0.08/−0.67, C2 0.38/−0.48, and D1 0.47/−0.63. A2 is the cleanest separator; C1 and C2 are weaker, consistent with their need to integrate information across larger portions of a document.

This is strong evidence that the learned directions generalize beyond the training pairs under the authors' validation design. It is not yet equivalent to external validation against an independent human-labeled corpus of skill quality.

Association with downstream task utility

For B1, B2, C1, C2, and D1, the authors fit one linear model per metric to map intrinsic score to pass-rate uplift. Pearson correlations between predicted and observed uplift were 0.780, 0.782, 0.785, 0.787, and 0.779, respectively; the all-metric setting achieved 0.716. A2 was excluded because trigger clarity was considered less directly related to execution quality.

The association is practically interesting because it suggests document-level signals can provide an early estimate of utility before expensive execution. However, the paper does not make intrinsic scoring a substitute for task testing: its own task-dependence analysis shows identical skills can produce markedly different uplift across tasks.

Metric-guided revision

The revision experiment compares original skills (D), LLM-only revisions without SkillEval scores (G), and metric-guided revisions (M). Mean downstream pass rate increased from 18.6% to 38.3% with LLM-only revision and to 48.1% with metric guidance. Relative to original skills, guided revisions improved A2 from 0.914 to 1.019, B1 from 0.896 to 1.022, C1 from −0.834 to −0.546, C2 from −0.631 to −0.393, and D1 from 0.913 to 1.422 while keeping B2 comparable.

This is the most implementation-relevant result: decomposed scores can do more than rank artifacts; they can target edits. The experimental support is encouraging but still limited by the specific LLM revision procedure, task sample, and lack of reported uncertainty around the 29.5-point improvement.

Bias and robustness analyses

Most tested surface variables correlate weakly with metric scores. The largest reported surface relationship is B2 versus model token length at r = −0.355; C2 schema-line count reaches r = 0.211. The authors therefore use orthogonalization against precomputed bias directions. Cross-backbone scorer agreement is high but not perfect: Qwen3.5-9B vs Qwen3.5-27B r = 0.948, Llama3.1-8B vs Llama3.2-3B r = 0.913, and cross-family pairs range 0.811–0.845.

Downstream skill utility is also reasonably but incompletely stable across 18 executor models: mean tolerance-aware concordance 0.724, median 0.739, 103/153 model pairs above 0.7, and a minimum pairwise concordance of 0.385. Hidden-state layer and pooling ablations show no globally optimal configuration, reinforcing that the scorer is metric-dependent rather than a single universal probe.

Task dependence and conclusion

Identical human-written skills reused across multiple tasks show task-specific utility. The xlsx skill spans a 66.7-percentage-point uplift gap from its lowest- to highest-uplift tasks, while pddl-skills spans 7.4 points. This directly supports the paper's motivating claim: downstream performance is a property of skill–task interaction, not skill quality alone.

The authors conclude that practical evaluation should combine two complementary views: compatibility with a particular task and general document properties that support reuse. SkillEval is presented as an interpretable bridge between those views and as a basis for diagnosing and refining skills.

Algorithm 1 — Direction learning and scoring

For each metric i:
  1. build paired training set (positive, negative)
  2. compute representation difference Δ
  3. remove component aligned with confounding direction
  4. average corrected differences and normalize → metric direction bᵢ
  5. project training skills onto bᵢ to get normalization μ, σ
  6. score unseen skill sᵢ(d) = hᵢ(d)ᵀ bᵢ
  7. standardize zᵢ(d) = (sᵢ(d) − μᵢ) / σᵢ

Governance note: The method is inspectable at the direction/scoring level, but reproducibility depends on the exact model checkpoint, hidden-state index, prompts, pooling, pair construction, bias-direction construction, and training data.

Evaluation and appraisal

Relevance
9.5 / 10

Rationale: Directly addresses agent-skill quality, validation, diagnostic feedback, and reusable procedural artifacts.

Evidence basis: Seven interpretable metrics, downstream association, revision study, and robustness analyses.

Limiting factor: Relevance is highest for SKILL.md-style systems; transfer to other memory/skill representations is inferred rather than demonstrated.

Would raise: Validation on multiple independent skill ecosystems and non-Markdown procedural memories.

Novelty
8.0 / 10

Rationale: The combination of intrinsic skill decomposition with fixed representation directions is a distinct and practical contribution.

Evidence basis: Controlled metric directions, bias orthogonalization, and diagnostic revision.

Limiting factor: Linear concept directions and contrastive activation methods are established techniques; novelty is primarily in application and decomposition.

Would raise: Strong evidence that the decomposition captures dimensions missed by existing intrinsic and task-based evaluators.

Method strength
7.5 / 10

Rationale: Careful train/validation separation, controlled pairs, fixed scoring, ablations, and cross-model checks make the design substantially stronger than a single-judge evaluation.

Evidence basis: 1,647-skill corpus, 518 held-out documents, disjoint tasks/sources/templates, layer/pooling/backbone/bias analyses.

Limiting factor: Metric labels and negative construction are partly generated/screened under designer-defined criteria; no independent human reliability study is reported.

Would raise: Preregistered external labels, multiple independent annotators, released pair-generation data, and fully reproducible code/checkpoints.

Evidence strength
6.5 / 10

Rationale: Evidence is consistent across intrinsic validation, downstream association, revisions, and robustness checks, but mostly benchmark/internal rather than deployment evidence.

Evidence basis: Large positive–negative separation, r≈0.78 with uplift, +29.5-point guided revision gain, cross-backbone and cross-executor analyses.

Limiting factor: Limited uncertainty reporting, no independent external corpus, and no prospective deployment evaluation.

Would raise: Confidence intervals, held-out external registries, prospective task evaluation, and replication by another group.

External validity
6.0 / 10

Rationale: Multiple skill sources and scorer/executor backbones help, but the evaluation remains centered on SKILL.md conventions and SkillsBench-style tasks.

Evidence basis: Public, generated, and manually constructed skills; 18 downstream executor models; cross-family scorer robustness.

Limiting factor: No independent ecosystem, organization, or long-running production skill library is evaluated.

Would raise: Cross-registry evaluation, longitudinal drift tests, multilingual skills, tool-permission variation, and real production failure data.

Implementation value
8.5 / 10

Rationale: The metric taxonomy can be adopted immediately as a static QA checklist even without reproducing the hidden-state scorer.

Evidence basis: Explicit dimensions, algorithm, diagnostic revision gains, and detailed bias/layer/pooling analyses.

Limiting factor: Exact scorer replication requires model internals, training pairs, bias directions, prompts, and normalization data not fully operationalized in the paper text.

Would raise: Public reference implementation, released pair datasets, calibrated thresholds, CI checks, and examples of integration into skill authoring/registry pipelines.

Strengths

  • Separates task compatibility from reusable document quality instead of treating downstream pass rate as the sole truth signal.
  • Decomposes quality into actionable dimensions that map naturally to authoring and validation workflows.
  • Uses fixed scoring directions rather than repeated generative judging, improving auditability of the scoring mechanism.
  • Includes nuisance-feature diagnostics, scorer-backbone robustness, executor-model robustness, layer ablations, and pooling ablations.
  • Tests a practical intervention: metric-guided editing, not just retrospective prediction.

Critical limitations

  • Construct validity: Positive/negative definitions are partly encoded by the authors' own metric criteria. High held-out discrimination therefore demonstrates recovery of those designed distinctions more directly than it proves a complete theory of skill quality.
  • External validation: The semantic scorer is not independently validated on a separately curated human-labeled skill registry or production corpus.
  • Uncertainty: Key correlations and revision gains are presented primarily as point estimates; confidence intervals, calibration error, and statistical uncertainty are limited or absent in the reported figures.
  • Metric incompleteness: The taxonomy does not separately score security, provenance, tool permissions, maintainability, retrieval uniqueness, cost, or context-budget efficiency, although some may be indirectly reflected.
  • Configuration dependence: Appendix results show layer and pooling choices are metric-dependent, and some scorer/executor pairs disagree materially. A deployed implementation should treat configuration as versioned model state, not a universal fixed constant.
  • Downstream association is not causation: Correlation with pass-rate uplift supports usefulness but does not prove that raising a metric score will always raise task success. The revision experiment is supportive, not definitive causal validation.
Best use: Use the paper as a design blueprint for a two-level skill QA system: deterministic structural checks + decomposed semantic checks, followed by targeted downstream execution tests. The seven metrics are especially valuable as an authoring checklist even if the representation-probe implementation is not adopted.
Do not use for: Treating a single SkillEval score as a certification of production safety, replacing task-specific execution tests, or assuming the reported z-scores/thresholds transport unchanged across models, skill libraries, or domains.

Implementation / research takeaways

1. Separate structural and semantic validation

A1 is deterministic while A2–D1 are semantic. This mirrors robust software/CDS validation design: cheap hard checks first, then sufficiency/quality checks. Do not force all validation into one LLM judge.

2. Keep metric outputs decomposed

The all-metric correlation (r = 0.716) was lower than each individual B1–D1 signal (0.779–0.787). A single weighted total may discard diagnostic information. Preserve the profile and only aggregate for narrow downstream decisions.

3. Treat nuisance features as testable confounders

Length, code blocks, schema lines, and other surface cues can be measured explicitly. A skill evaluator should ship with bias diagnostics and fail QA if a metric begins tracking format rather than semantics.

4. Version the scorer configuration

Model, layer, pooling, prompt, pair dataset, normalization statistics, and bias directions are all part of the evaluation artifact. Appendix results show they can materially change performance.

5. Use scores to propose targeted edits

The strongest practical pattern is diagnostic revision: identify weak dimensions, revise only those areas, and re-evaluate. This is safer than asking an LLM to “improve the whole skill,” which risks erasing strengths.

6. Keep downstream execution as a second axis

Skill quality and skill–task compatibility are different. Intrinsic screening can reduce expensive runs, but final acceptance should still include representative downstream tests with deterministic verifiers where possible.

Suggested build pattern derived from the paper

SKILL.md
  → deterministic format/schema checks (A1)
  → intrinsic semantic profile (A2, B1, B2, C1, C2, D1)
  → bias/confound audit
  → targeted revision if weak
  → re-score
  → representative downstream tasks
  → skill × task utility record
  → registry acceptance / versioned provenance

Model inference: the paper does not prescribe this exact production pipeline; it is a conservative implementation synthesis from its framework and findings.
