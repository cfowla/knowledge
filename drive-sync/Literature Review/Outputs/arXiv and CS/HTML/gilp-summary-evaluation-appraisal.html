Scope warning. This is a preprint about LLM-agent planning architecture. It is useful for agent harness design, state-delta evaluation, and hallucination-propagation thinking. One-page synthesis

Core thesis. LLM agents fail over long horizons partly because they write false state transitions into their own context. A small trained world-model backbone can reduce that failure mode by giving the LLM a compact transition skeleton and triggering targeted correction when the LLM's imagined delta disagrees with the backbone.

What the paper contributes

It separates agent-based world-model error from parameterized transition error, defines operational metrics for hallucination propagation, and implements GILP: skeleton scoring, LLM drafting, Jaccard consistency gating, targeted correction, and risk gating.

Best quantitative claim

The strongest direct empirical support is short-horizon real GPT-4o-mini validation: pooled HSR falls from 0.176 to 0.035 across four graph benchmarks, with about 20% token overhead and all SR values at 1.000.

Main limitation

The headline success gains, including SR 0.668 to 0.838 and H>10 SR 0.471 to 0.758, are derived from a calibrated simulator. The live API validation primarily supports hallucination reduction, not long-horizon task success.

Most reusable idea

Use a small auditable state-transition predictor as a guardrail inside the agent loop rather than as a replacement planner. Log HSR, propagation depth, correction rate, invalid-action rate, and post-correction deltas.

Section condensation

Abstract / central claim

The paper frames long-horizon LLM agents as implicit world models: the agent selects an action and also writes an imagined next-state delta that becomes part of later context. Its central claim is that agent-based world models reason flexibly but propagate hallucinated state atoms, while small parameterized world models have measurable transition errors and can be used as grounding signals.

The proposed method, Grounded Iterative Language Planning (GILP), keeps the API LLM as the planner but adds a trained backbone that predicts valid actions, state deltas, risk, and value. The headline results are large: simulator success rises from Agent-Replan 0.668 to GILP 0.838, long-horizon success from 0.471 to 0.758, and real GPT-4o-mini hallucinated-state rate (HSR) from 0.176 to 0.035. These results must be interpreted through the paper's own limitation: the main benchmark table is simulator-derived, while real API validation is shorter-horizon and smaller.

1. Introduction

The introduction distinguishes two world-model forms for LLM agents. An agent-based world model is the LLM's generated action plus imagined next-state text/JSON; its damaging errors are semantic hallucinations such as false completions, ignored dependencies, or wrong entity states. A parameterized world model is a trained transition predictor with explicit metrics such as NodeMSE, delta accuracy, and validity accuracy.

The paper motivates GILP with a cascade example: a false claim that task 3 completed causes later invalid actions and further state corruption. The authors define the core contribution as an operational metric set for hallucination propagation plus a hybrid planning loop where a trained backbone checks and corrects LLM state deltas before they enter the next prompt.

2. Related work

The related-work section places the paper at the intersection of ReAct-style agents, tree/search language agents, parametric world models from model-based RL, hallucination correction, symbolic verification, and structured output. The authors emphasize that many existing language-agent methods rely on the LLM's own imagined state, but most hallucination work studies single-turn factuality rather than multi-step state propagation.

The paper also positions GILP against symbolic or code-based world-model methods. Its claimed distinction is a lightweight, API-agnostic gate: a small trained model predicts a compact skeleton and a Jaccard consistency gate triggers re-prompting only when the LLM's imagined delta diverges from the backbone prediction.

3. Problem formulation

A task is represented as a graph state Gt with entities, dependency edges, per-node status values, and a goal mask. At each step, the LLM receives a serialized graph state, a goal, and candidate actions, then emits JSON with selected_action, imagined_next_state as node-status deltas, reasoning, and confidence. The true environment transition is then applied independently.

The paper defines hallucinated-state rate (HSR), propagation depth (PD), and error-explosion slope (EES) for the agent world model. The parameterized model has conventional supervised metrics such as NodeMSE, validity accuracy, delta accuracy, reward MSE, and done accuracy. The cost model counts API input/output tokens and compares cost per 1,000 tasks or per successful episode.

4. Method: GILP

GILP has four phases. First, a parameterized backbone scores each candidate action for validity, predicted delta, reward/value, done/completion, risk, and affected entities; the result is compressed into a top-k skeleton. Second, the LLM drafts an action and imagined delta using the current state, goal, candidate actions, and skeleton. Third, a consistency gate compares the LLM's changed-node set with the backbone's predicted changed-node set using Jaccard similarity. Fourth, a risk gate can re-present lower-risk alternatives.

The practical thresholding is central: consistency >= 0.70 is accepted, 0.30 to 0.70 is accepted with risk penalty, and <0.30 triggers a targeted correction prompt. The authors cap corrections at one per step and report about 22% correction-gate firing plus 8% risk-gate firing, implying approximately 1.30 LLM calls per step. The proof sketch shows one-step hallucination contraction proportional to gate recall times repair success, but the guarantee depends on a non-adversarial correction assumption and does not prove final-task optimality.

5. Experiments

The main experiments use four graph-structured benchmarks: TaskGraph, ToolChain, ResourceAlloc, and RepairFlow, each with 500 train, 100 validation, and 100 test tasks, split into 60 in-distribution and 40 OOD test tasks. The main comparison evaluates agent-only, parameterized-only, and hybrid planners over a calibrated behavioral simulator, with real GPT-4o-mini validation used to calibrate or corroborate selected quantities.

Across simulator results, GILP is the best overall planner: SR 0.838, HSR 0.079, PD 1.510, invalid-action rate 0.065, and risk-weighted failure 0.068. The strongest evidence for the intended mechanism is the real GPT-4o-mini validation: pooled HSR falls from 0.176 to 0.035 across n=80 agent and n=76 hybrid episodes, with all tasks short horizon (H=3-8) and all SR=1.000. The weaker evidence is the AgentBench-style KG traversal: GILP reduces HSR by 0.087 but lowers SR from 10/12 to 9/12, and neither difference is significant.

6. Discussion

The authors' main interpretation is that GILP works by division of labor: the LLM remains responsible for semantic reasoning, while the small trained model supplies auditable transition signals. The backbone need not be a strong standalone planner; even a weak MLP can provide enough validity and delta signal to improve hybrid behavior.

The discussion correctly identifies long horizon as the critical setting. Agent hallucinations are history-dependent because a false state atom can enter the next prompt, while parameterized transition error is local and directly measured. The paper's practical claim is that targeted correction is cheaper than verify-all strategies because it only spends extra tokens on suspicious steps.

7. Limitations

The limitations section is unusually important for this paper. The main comparison table is entirely from a calibrated behavioral simulator, not live LLM rollouts. Real API validation covers 80/76 GPT-4o-mini short-horizon episodes, and the multi-API results for Claude, Gemini, and Llama are calibrated rather than directly measured. Cost estimates are relative only because simulated token costs overshoot real runs by 3-4x.

The benchmark scope is restricted to graph-structured planning tasks. The method assumes access to oracle transitions for backbone training and checkable state deltas. When the backbone is poorly calibrated, as in the KG traversal experiment, correction can perturb otherwise-correct action selection. The paper does not validate deployment in clinical, safety-critical, web, software-engineering, or messy real-world agent settings.

8. Conclusion

The conclusion restates the comparison: agent-based world models reason well but hallucinate state; parameterized world models are measurable but weaker planners; GILP combines them by using a small trained backbone to ground an API-based agent. The quantitative summary is SR 0.668 to 0.838, long-horizon SR 0.471 to 0.758, simulator HSR 0.205 to 0.079, and real GPT-4o-mini HSR 0.176 to 0.035.

The best defensible reading is that GILP is a promising architecture pattern for agent harnesses and deterministic evaluation, not a mature benchmark result proving general API-agent reliability. Its most reusable pieces are the hallucination-propagation metrics, skeleton prompt format, correction-gate pattern, and explicit distinction between semantic planner ability and measurable transition accuracy.

Appendices A-G

Appendix A provides prompts for agent-only mode, GILP skeleton mode, correction, risk gating, and API call examples. Appendix B reports the state-serialization ablation, where JSON-table formatting yields the lowest hallucinated-state rate and formats vary by a factor of about 1.6x. Appendices C and D define the environments and backbone training setup: 50 epochs, Adam lr=1e-3, multi-task loss over validity, delta, reward, done, and risk, and small models under 100k parameters.

Appendix E is an important caveat: the independence-baseline formula underestimates any-error probability when errors are positively serially correlated, so the reported IndepBound should be read as a reference proxy rather than a true upper bound. Appendix F proves the one-step contraction formula, and Appendix G explains the simulator protocol and its conservative calibration behavior.

Algorithm and operational workflow

ALGORITHM 1 - Grounded Iterative Language Planning (GILP)
Inputs: environment, goal, backbone Ftheta, agent LLM, thresholds tau_high/tau_low/rho_th, horizon H.
Step loop:
1. Serialize current graph state and obtain candidate actions.
2. Score candidates with the parameterized backbone.
3. Compress predictions into skeleton Bt.
4. Ask LLM for selected action, imagined delta, and confidence.
5. Compute Jaccard consistency between LLM changed-node set and backbone changed-node set.
6. If consistency < tau_low, send discrepancy-specific correction prompt and parse revision.
7. If predicted risk exceeds threshold, re-prompt over a low-risk subset.
8. Execute action, log state, skeleton, action, imagined delta, next state, consistency, and token usage.
9. Stop when done or horizon expires.
Failure modes: bad backbone calibration; over-triggering corrections; correction prompt perturbing a correct action; unsupported state types; missing oracle transitions; serial correlation of errors.
Governance/useful logging: correction trigger rate, pre/post HSR, invalid-action rate, post-correction action changes, risk-gate rate, token overhead, and task-level outcomes.

Prompt and appendix workflows

APPENDIX A - Prompt suite
System prompt: instructs the planning agent to emit a single valid JSON object and only assert state changes supported by current state, candidate action, or skeleton.
Agent-only prompt: serializes world state, goal, candidate actions, and expected JSON schema.
GILP prompt: inserts a parametric world-model skeleton containing p_valid, value, risk, predicted delta, and affected entities.
Correction prompt: names each discrepancy between LLM-imagined deltas and backbone predictions, then asks for revised action and/or imagined state.
Risk prompt: warns about high predicted risk and re-presents lower-risk alternatives.
API examples: OpenAI JSON-object call and Anthropic message call with regex JSON extraction.

APPENDIX B-G - Reproducibility and caveats
B: Serialization alone changes HSR by about 1.6x; JSON-table is default.
C: Four benchmarks are TaskGraph, ToolChain, ResourceAlloc, RepairFlow.
D: Backbones train for 50 epochs with Adam lr=1e-3 and multi-task loss; all models <100k parameters.
E: IndepBound is an independence-baseline proxy, not a true upper bound under positive serial correlation.
F: One-step hallucination contraction proof relies on gate recall, repair success, and non-adversarial correction.
G: Simulator samples agent-side events over the same true graph transition function and is described as conservative but not exact.

AI/ML appraisal lens

Task

Long-horizon graph-structured planning where an LLM must select actions and emit imagined next-state deltas.

Data

Four synthetic/controlled graph benchmarks with train/validation/test tasks, plus small FB15k-237 KG traversal validation.

Method

Hybrid agent system using a small parameterized backbone, skeleton prompt, Jaccard consistency gate, targeted re-prompt, and risk gate.

Metrics

SR, long-horizon SR, invalid-action rate, HSR, propagation depth, risk-weighted failure, token cost, per-step error proxies, JSON-fail rate.

Baselines

Agent-only variants, verifier agent, parameterized-only MPC/MCTS, validity/delta/risk/value hybrid ablations, GILP variants.

Failure analysis

Explicit focus on false completion, false dependency, wrong entity, propagation depth, correction failures, and backbone calibration boundary conditions.

Critical appraisal point. The paper's strongest mechanistic evidence is HSR reduction in real GPT-4o-mini short-horizon episodes. The strongest claimed outcome gain - long-horizon success - is still mainly simulation evidence.

Evaluation and appraisal

Verdict: Read soon. This is worth preserving for agent-harness design and hallucination-propagation evaluation. Do not treat it as mature evidence that GILP-style grounding will generalize to production agents without independent live-rollout validation.

Implementation and practice takeaways

Build

Prototype a skeleton provider that returns candidate action, p_valid, predicted delta, affected nodes, risk, and short-horizon value. Treat it as advisory, not authoritative.

Measure

Log HSR, propagation depth, invalid-action rate, correction rate, repair success, token overhead, and pre/post-correction deltas.

Gate

Use a low-consistency threshold to trigger targeted correction. Avoid verify-all unless the domain warrants the cost.

Validate

Run live API rollouts at the actual horizon and state format of the target use case. Do not rely on short-horizon success to infer long-horizon stability.

Monitor

Track correction over-triggering, backbone miscalibration, and cases where correction changes a correct action into a wrong one.

Avoid overclaiming

Do not claim that structured JSON output prevents hallucinated state; the paper specifically argues that syntactic validity and semantic state validity are separate.
