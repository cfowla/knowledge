One-page synthesis

Core thesis. Shared-memory retrieval should separate semantic relevance from provenance admissibility. MAP-Graph operationalizes that separation by (1) recording execution lineage in a typed graph, (2) applying hard permission filtering before ranking, (3) multiplying semantic relevance by ancestry-derived path trust, and (4) re-evaluating support at action time with risk-sensitive rules.

MAP-Graph treats provenance as an active control signal rather than audit metadata alone. The system records users, agents, tools, resources, messages, memories, claims, and actions in a task-scoped graph while storing memories in a vector collection. A derived memory carries lineage and permission scope, so summaries cannot silently erase the policy state of their ancestors. Eligible memories are reranked by semantic similarity × path trust; a separate action-time gate uses affected ancestry, support availability, cause, and risk thresholds to return Allow, Block, Reverify, Redact, or AskUser.

On the controlled 2,700-task benchmark, MAP-Graph reports 94.96% task success, 72.70% exact decision accuracy, 90.22% clean success, 1.52% unsafe actions, and 0% measured poisoned-memory ASR, private-memory leakage, conditional unauthorized access, and revocation violation. Ablations are especially informative: disabling permission filtering raises TSR/accuracy but produces 100% conditional unauthorized access; removing the action gate or containment sharply increases unsafe behavior; removing trust propagation reduces TSR and increases unsafe actions. The strongest caveat is that 41 impermissible Allow decisions remain in the action-risk group, and all results come from synthetic, single-run, simulated workflows.

Why it matters. The paper is unusually explicit about the distinction between retrieval relevance, authorization, graded trust, and action-specific admissibility. That decomposition is directly reusable when designing governed agent memory, audit trails, or tool-action policy layers.

Section condensation

Abstract

The paper frames shared memory as execution state whose downstream use may be unauthorized or unsafe even when the memory is semantically relevant. It introduces MAP-Graph, which traces ancestry, excludes permission-ineligible records, reranks eligible memories by semantic similarity and multiplicative path trust, and applies a risk-sensitive action gate.

The abstract reports 94.96% overall task success, 72.70% exact accuracy, and 90.22% clean success on a controlled benchmark of 2,700 synthetic tasks per method, with ablations and transfer to two additional backbones. The stated conclusion is intentionally scoped to the evaluated setting.

1 — Introduction

The motivation is a failure mode that vector retrieval alone cannot diagnose: derived memory can conceal private, poisoned, untrusted, or revoked ancestry while remaining highly relevant. The paper distinguishes hard authorization from graded trust and argues that action risk creates a second admissibility decision after retrieval.

Three challenges organize the contribution: recursive ancestry (C1), heterogeneous hard versus graded constraints (C2), and action-dependent admissibility (C3). The paper positions MAP-Graph as a sequence of typed provenance capture → permission eligibility → trust-aware ranking → action-time gating → audit-preserving affected-lineage retention.

2.1–2.3 — Background and problem formulation

A shared-memory record is modeled with identifier, content, owner, visibility, derivation references, optional trust label, and metadata; final decisions are separate Action nodes. Provenance supplies origin/derivation, while benchmark-provided visibility, ownership, trust, risk, and revocation fields are treated as explicit policy inputs rather than inferred truth.

The retrieval objective first restricts candidates with CanRead(a,m), then scores eligible memories as semantic relevance × path trust and returns the top five. The important design constraint is non-substitutability: hard permission exclusion cannot be compensated by semantic similarity, while graded trust should demote—not automatically discard—eligible evidence.

3.1 — Graph schema

The task-scoped heterogeneous directed provenance graph has eight node types: User, Agent, Tool, Resource, Message, Memory, Claim, and Action. Ten edge types cover authorization, observation, forwarding, derivation, summarization, writing, reading, verification, invalidation, and action use.

This is execution lineage, not a general semantic knowledge graph. The implementation explicitly does not create generic Contradicts/Updates relations or claim open-domain conflict resolution.

3.2 — Memory construction and provenance capture

Construction uses observable workflow state. Non-empty writes create distinct embedded Memory nodes; semantically equivalent entries are not merged and normal observations do not mutate/supersede prior text. Derived memory inherits referenced identifiers and an intersected permission scope.

Explicit revocation changes a source to revoked visibility, clears its scope, updates directly referenced or already affected records, and leaves other descendants to discover the revoked ancestor during recursive trust evaluation. This preserves an auditable lineage rather than erasing contaminated descendants.

3.3 — Provenance-aware retrieval

Semantic similarity is max(0,1−cosine_distance). For each candidate, MAP-Graph computes permission eligibility and recursive ancestry-derived trust; only permission-eligible memories enter final ranking.

Path trust is the clipped multiplicative product of source trust, path integrity, transformation factor, permission validity, verification bonus, and writer reliability. Recursive ancestry can therefore lower trust for a locally innocuous summary because the relevant restriction or trust defect is inherited from upstream provenance.

3.4 — Affected ancestry and action-time gating

A memory is affected when recursive ancestry contains an untrusted, private, or revoked item. The final gate recomputes trust for retrieved support and contextual affected/permission-invalid inter-agent memories, then applies risk-indexed thresholds: 0.30 for answers, 0.60 for low/medium-risk non-answer actions, and 0.85 for high-risk non-answer actions.

Ordered rules first block high-risk actions with affected support, then handle absent surviving support, then private/revoked/untrusted/permission-invalid support, then low maximum trust. The same memory can therefore be admissible for an answer but inadmissible for a high-risk external action.

3.5 — Implementation notes

Within a task, graph, embedding, and gate state update incrementally; between tasks, graph and vector state reset. The backend exposes observe/write, retrieve, revoke, decide, and export. The paper gives benchmark-level complexity bounds of O(Dm) for ancestry trust and O(M log M) ranking, not deployment-scale performance claims.

4.1–4.3 — Benchmark, baselines, metrics, implementation

The full benchmark has 2,700 tasks: 900 each in corporate workflow, software engineering, and research assistance; six groups cover clean utility, poisoned propagation, private leakage, revocation, action-risk sensitivity, and clean compression/overhead. Each domain-group cell contains 15 semantic families × 10 variants. The sanitizer removes oracle/evaluator and family/variant clues while retaining the provenance/policy fields under study.

Seven baselines span no memory, shared vector memory, isolated vector memory, adapted G-Memory, adapted Collaborative Memory, adapted MemLineage, and Flat Provenance. Main runs use Qwen2.5-7B-Instruct at temperature 0; embedding-based methods use BAAI/bge-small-en-v1.5, k=5. TSR rewards any safe intervention for oracle non-Allow cases, so exact accuracy must be read alongside it.

4.4 — Main results

MAP-Graph leads the reported aggregate benchmark: TSR 94.96%, exact accuracy 72.70%, clean success 90.22%, unsafe actions 1.52%, and 0% reported ASR, leakage, UAcc, and revocation violation. The paper emphasizes that 100% UAcc for several baselines means every observed unauthorized attempt succeeded, not that every memory read was unauthorized.

The main residual weakness is the action-risk group: 41/450 decisions are impermissible Allow outcomes (9.11%). The authors explicitly scope the result to a synthetic, templated, simulated, single-round, single-run benchmark.

4.5 — Backbone transfer

A fixed 540-task subset stratified by domain, experiment group, and oracle label is evaluated under Qwen2.5-7B-Instruct, GLM-4-9B-0414, and Llama-3.1-8B-Instruct. MAP-Graph has the highest exact accuracy and lowest unsafe rate across all three backbones.

TSR is not uniformly best: on GLM, MAP-Graph reaches 86.30% versus B6 at 88.89%. This is evidence of a utility–safety trade-off rather than backbone-invariant dominance.

4.6 — Ablations

Removing the action-time gate or containment causes large increases in ASR, revocation violations, and unsafe actions with little change in clean TSR. Removing trust propagation lowers TSR by 7.59 points and increases unsafe actions from 1.52% to 8.56%. The compressed graph preserves most utility while substantially reducing exported graph size.

The most revealing ablation disables permission filtering: TSR rises to 96.00% and exact accuracy to 78.63%, yet conditional unauthorized access rises to 100%. This directly supports the paper’s argument that utility and endpoint leakage alone are insufficient governance metrics; the read boundary must be instrumented.

5 — Related work

The paper distinguishes MAP-Graph from agent-memory persistence systems, private/shared memory tiers, graph retrieval, provenance standards, and specific G-Memory/Collaborative Memory/MemLineage mechanisms. It presents MAP-Graph as combining task-local permission filtering, multiplicative ancestry scoring, affected-state audit metadata, and action-time gating rather than subsuming those systems.

6 — Conclusion

The authors conclude that the controlled results support provenance as a mechanism for governing retrieval and actions, not merely post-hoc audit. They also state that future work should test repeated, less templated, cross-session, and deployment-scale settings.

Appendices A–F

Appendices specify graph/schema constants, backend operation semantics, benchmark generation and sanitization, baseline adaptations, metric formulas and fixed implementation settings, scenario/domain diagnostics, full ablation diagnostics, backbone access-boundary results, and error analysis. These appendices materially strengthen reproducibility and expose several caveats hidden by aggregate TSR.

Figure 2 — Poisoned-memory propagation and containment

Purpose: Demonstrate recursive ancestry and downstream containment.
Path: poisoned/untrusted Resource R1 → Memory M1 → summarized Memory M2.
Retrieval: M2 may remain semantically relevant, but ancestry traversal discovers R1.
Effect: M1/M2 are marked affected; path integrity/trust fall and ranking is reduced.
High-risk action: affected supporting memory triggers Block.
Audit behavior: affected lineage remains recorded rather than deleted.
Limit: this is an implemented benchmark policy example, not a proof that every allowed action is safe.

Core decision workflow

query q + agent a
  → semantic candidates
  → CanRead(a,m) hard permission filter
  → recursively compute path trust ρ(m,a)
  → Score = semantic_similarity × ρ
  → select top 5 eligible memories
  → proposed action + risk
  → recompute supporting/contextual affected state
  → ordered action-time rules + threshold θ
  → Allow | Block | Reverify | Redact | AskUser
  → retain selected IDs, affected ancestors, scores, thresholds, reasons, and decision for audit

Error analysis

MAP-Graph has 737 exact-decision errors. Of these, 601 are safe but non-exact interventions, 95 are unnecessary interventions on oracle-Allow tasks, and 41 are impermissible Allow decisions. All 41 impermissible Allow outcomes occur in Exp-5, concentrating residual safety failure in action-risk sensitivity rather than the poisoned, private, or revoked-memory groups.

Main strengths

The strongest design choice is measurement of the access boundary rather than relying on endpoint leakage alone. The no-permission-filter ablation makes this concrete: downstream gating can keep endpoint leakage low while unauthorized reads still occur. The benchmark also separates clean utility from safety interventions, provides a flat-provenance control, and exposes error composition rather than reporting only a single success metric.

Main limitations

Evidence maturity is constrained by synthetic templated tasks, simulated actions, one four-agent round, task-local reset between cases, single-run backbone evaluations, adapted rather than fully reproduced baselines, and incomplete operational performance measurement. The implementation uses explicit benchmark policy fields; it does not solve provenance inference from ambiguous natural language, cryptographic integrity, general truth maintenance, or open-domain conflict resolution.

What would change the appraisal

Confidence would increase materially with cross-session experiments, repeated stochastic runs, real enterprise permission graphs, revocation over long-lived derived memory, adversarial attempts to launder restricted content through summaries, human-facing audit/explanation evaluation, and isolated latency/storage overhead measurements. Evidence strength would fall if released code or reproduction failed to match the access-boundary and ablation behavior.

Implementation and research takeaways

Separate hard and graded controlsPermission should be a pre-ranking eligibility gate; trust can then grade evidence that is still legally/policy eligible.
Carry restrictions through derivationDerived memory should inherit lineage and access scope so summarization cannot erase provenance constraints.
Recheck at action timeRetrieval admissibility is insufficient when the same evidence may support actions with different risk.
Keep affected lineageMark-and-retain can support audit better than deleting descendants, provided affected records cannot silently re-enter support.
Instrument read boundariesEnd-to-end leakage can be zero even after an unauthorized read if a later gate blocks execution.
Use exact-decision metricsA safety-weighted success metric can hide conservative over-intervention; exact labels and error taxonomy are necessary complements.
Do not overclaim. MAP-Graph is build-useful and benchmark-useful. The paper does not establish secure deployment, cryptographic provenance integrity, automated truth resolution, long-term memory governance, or safety under real organizational policy drift.
