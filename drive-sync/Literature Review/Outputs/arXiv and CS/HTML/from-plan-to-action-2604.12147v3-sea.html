One-page synthesis

Verdict: Read first. The paper provides a concrete process-level framework for asking whether an agent followed the strategy it was given, rather than judging only whether the final task succeeded. Its strongest practical result is that plan quality and model-plan alignment matter, and periodic plan reminders can improve success without requiring strict compliance.
Core thesisPlans materially shape agent behavior and success, but agents do not simply execute them. They combine the explicit plan with model-internalized workflows and local context.
New measurement layerThe authors define Plan Phase Compliance (PPC), Plan Order Compliance (POC), Plan Phase Fidelity (PPF), and their geometric-mean Plan Compliance (PC).
Standard planThe baseline workflow is Navigation → Reproduction → Patch → Validation. Standard-plan success was 56.3% for GPT-5 mini, 38.4% for DeepSeek-V3, 39.4% for DeepSeek-R1, and 64.8% for Devstral-small.
No planAgents still exhibit recognizable internal workflows, but success falls overall. Some issues are solved only without the standard plan because faulty reproduction-test generation can derail repair.
Bad plans can be worseRemoving one key phase can damage performance more than removing the plan entirely. Added phases can also hurt when they conflict with a model’s internal strategy.
Adaptive overrideAgents often ignore suboptimal ordering. Devstral-small, for example, continues to reproduce before patching despite being instructed to patch first.
Reminder effectRe-inserting the standard plan every five steps improves DeepSeek-V3 compliance and produces consistent success improvements across the studied models.
Generalization signalPlan compliance falls by 13% on the selected SWE-bench Pro comparison, where trajectories become more navigation/patch-heavy and often fail to reach validation.
Interpretive boundary. The empirical evidence is strongest for the behavioral effects of plan variants and reminders. Explanations involving fine-tuning, benchmark contamination, model-internal strategies, context pressure, or short-term reward are partly supported by indirect tests and trajectory inspection but are not cleanly isolated causal mechanisms.

Methods & metrics

Experimental frame

SourceSWE-agent is held as the common scaffold while the backbone LLM varies across GPT-5 mini, DeepSeek-V3, DeepSeek-R1, and Devstral-small. The primary benchmark is SWE-bench Verified: 497 Easy/Medium/Hard instances after excluding three Very Hard instances unresolved by every studied model under every plan setting. Generalization experiments use 266 Python SWE-bench Pro instances; because success was near zero on many, the compliance comparison in §6.1 is narrowed to 31 instances resolvable by at least one model under the Standard plan.

SourceEight plan settings are tested: Standard, No Plan, No Reproduction, No Validation, added regression testing, added change summary, reordered phases, and periodic reminders. Existing repository tests are deliberately distinguished from agent-generated tests: regression testing is outside the default N-R-P-V alphabet unless explicitly added.

Action abstraction

Raw SWE-agent trajectory
  → Graphectory: action graph with chronological edges
  → action-to-phase mapping
       Navigation: inspect files/directories
       Reproduction: create/run new tests before application-code edits
       Patch: edit application code
       Validation: create/run new tests after patching
       General: actions outside the current plan vocabulary
  → Langutory: compact phase-letter trajectory
  → PPC / POC / PPF / PC

The automated phase mapping was manually checked on 320 actions: two authors independently labeled the first occurrence of each default-plan phase across 20 sampled trajectories per model. Agreement among the two human annotations and automated labels reached Fleiss’ κ = 0.99.

Compliance metrics

PPC = number of instructed phases appearing at least once ÷ number of instructed phases
POC = LIS(first-occurrence indices of instructed phases) ÷ number of instructed phases
PPF = |plan alphabet| ÷ |plan alphabet ∪ observed phase labels|
PC = (PPC × POC × PPF)1/3

AppraisalThe decomposition is useful because “followed all phases,” “followed them in order,” and “introduced extra phases” are behaviorally distinct. The geometric mean prevents one strong component from fully compensating for a weak one, but equal multiplicative weighting is a design choice rather than an empirically validated utility function.

Other analyses

Task success is the benchmark issue-resolution rate. Graphectory node, temporal-edge, and loop counts measure trajectory complexity. Phase Flow Analysis visualizes transitions as Sankey-style flows. Standard-plan experiments are repeated three times for RQ7, with pairwise McNemar tests and reproducible subsets used to test whether conclusions survive agent nondeterminism.

Section condensation

Abstract & Introduction

The paper argues that agent plans are usually advisory system-prompt instructions rather than enforced workflows. Because an agent chooses each action from its local context, it may skip, reorder, or add phases as trajectories grow. Evaluating task success alone therefore cannot distinguish plan-following from alternative routes such as memorized workflows, benchmark overfitting, or contamination.

The study positions plan compliance as a process-level object of measurement. Across 21,120 trajectories, the authors ask how compliance varies by model, whether plans improve task success, what happens when plans are removed or mutated, whether reminders help, how results generalize to SWE-bench Pro, and whether conclusions survive stochastic variation.

2. Experimental Design

The default plan is Navigation (N) → Reproduction (R) → Patch (P) → Validation (V). The mapping rules intentionally distinguish newly generated tests from existing repository regression tests. Langutory compresses raw trajectories into phase letters, enabling phase coverage, ordering, and fidelity to be quantified.

Figure 1 illustrates why the components differ: a trajectory can cover every phase but start Reproduction before Navigation, or can omit Reproduction and Validation entirely. PPC, POC, and PPF are combined into PC using a geometric mean.

3. Empirical Setup

Four LLMs are evaluated under eight plan settings on SWE-bench Verified and, for generalization, SWE-bench Pro. The analysis combines PC metrics, task success, trajectory-complexity metrics, and phase-flow diagrams. Table 1 defines the exact mutated plan sequences.

The action-to-phase classifier receives a strong validation result (κ = 0.99 on 320 annotated actions), supporting the reliability of the abstraction for the sampled default-plan actions. The manual check is nevertheless narrower than the full space of plan variants and General/out-of-plan actions.

4. Standard Plan Compliance & No Plan

Under the Standard plan, compliance differs sharply by model. Devstral-small nearly always covers phases in order but performs more out-of-plan actions; DeepSeek-V3 has near-perfect phase fidelity while omitting or misordering phases; DeepSeek-R1 has the weakest compliance; GPT-5 mini changes strategy with problem difficulty and often skips Reproduction on easier issues. Resolved trajectories have significantly higher PC for Devstral-small (p = 1×10−5) and DeepSeek-R1 (p = 0.032), but not for DeepSeek-V3 (p = 0.60) or GPT-5 mini (p = 0.285).

When the plan is removed, model-internalized workflows remain visible but success drops overall. Devstral-small continues to resemble N-R-P-V, GPT-5 mini often resembles N-P-V, and DeepSeek models more often reduce to N-P. Yet every model also solves some instances only under No Plan; manual inspection links many such cases to incorrect reproduction tests under the Standard plan, after which the no-plan trajectory succeeds by skipping that step.

5.1 Reduced Plans

Removing Reproduction or Validation does not simply make agents shorter or freer. It can destabilize behavior, especially when the omitted phase is important to a model’s learned workflow. DeepSeek-R1 emits malformed tool calls in 349 No-Reproduction instances, while GPT-5 mini is particularly harmed by removing Validation. DeepSeek-V3 is less dependent on Validation, consistent with its tendency to skip that phase.

The authors’ synthesis is that a bad incomplete plan can be worse than no plan. Reduced-plan-only successes still occur, especially when the Standard plan’s reproduction requirement leads to a bad test. After accounting for nondeterminism, No Validation yields relatively few exclusive successes: 7 GPT-5 mini, 19 Devstral-small, 5 DeepSeek-V3, and 1 DeepSeek-R1.

5.2 Augmented Plans

Adding relevant phases is not automatically beneficial. Regression-test execution is already natural for Devstral-small and GPT-5 mini and changes success only modestly, but DeepSeek-V3 struggles to incorporate the added phases. Early long regression feedback may redirect the trajectory toward environment/test issues rather than repair. DeepSeek-R1 again performs poorly.

A final change-summary phase is largely neutral for GPT-5 mini, DeepSeek-V3, and Devstral-small because it occurs after core repair reasoning. DeepSeek-R1, however, shows pervasive tool-call failure in 413 instances. The authors conclude that augmentation works best when it aligns with the model’s internal strategy and can be harmful when it does not.

5.3 Reordered & Reminded Plans

The N-P-R-V reorder tests whether models will obey a still-plausible but strategically different sequence. DeepSeek-V3 often follows Navigation directly with Patch, while Devstral-small continues to reproduce before patching. The initial DeepSeek-V3 result rises from 191 to 196 resolved issues, but on the reproducible subset the rate changes only from 38.3% to 38.0%, showing that the apparent gain is not robust.

Periodic reminders are the clearest positive intervention. Re-injecting N-R-P-V every five steps improves DeepSeek-V3 compliance and keeps other models near their prior PC while improving success consistently. The authors interpret this as a way to counter plan salience loss and drift toward irrelevant subgoals.

6. Generalization & Nondeterminism

On the selected SWE-bench Pro comparison, PC drops by 13% on average across models and settings. Phase flows shift toward repetitive Navigation and Patching, with fewer trajectories reaching Validation and most agents still skipping Reproduction. This indicates that the high-level Standard plan is less effective on the harder benchmark.

Repeated Standard-plan runs produce statistically significant outcome differences by pairwise McNemar tests, confirming nondeterminism. The reproducible subsets contain 401 GPT-5 mini, 308 Devstral-small, 323 DeepSeek-V3, and 287 DeepSeek-R1 instances. Re-analysis on these subsets preserves the main qualitative findings, including the benefit of reminders.

7. Related Work

The paper situates itself against work on plan construction/refinement, separated planner/executor systems, process-centric trajectory metrics, and agent goal-plan-action alignment. Its claimed distinction is a mathematically specified, scalable compliance measure paired with controlled prompt-level plan mutations rather than task-level success alone or LLM-judge scoring.

8. Threats to Validity

The authors note external-validity limits from four models, two benchmarks, and a single software-repair domain. Internal validity is addressed by consistent configurations and repeated experiments. Construct validity is limited by a phase-level abstraction that discards some project-specific detail, though core repair phases are intentionally preserved.

Additional appraisal concern: some of the strongest causal explanations remain hypotheses. DeepSeek-R1’s frequent scaffold/tool-call failures can confound plan-quality effects with interface compatibility, and the 31-instance SWE-bench Pro filtered subset improves analyzability but narrows generalizability.

9. Discussion

The authors argue that the method can generalize to other domains by replacing the phase vocabulary while leaving the compliance mathematics unchanged. They explicitly caution against treating maximum compliance as the goal: productive deviations can be adaptive, while harmful omissions, reordering, or loss of plan awareness deserve intervention.

They propose compliance as an online monitoring signal for targeted reminders or adaptive plan refinement and as a post-training supervision signal that teaches models to follow task-appropriate plans without merely memorizing fixed workflows.

10–11. Conclusion & Data Availability

The paper concludes that plans clearly affect issue-resolution success but are imperfectly followed. Better plans and better plan-following are both plausible routes to improved agents. The study artifacts are stated to be publicly available via the cited artifact DOI.

Directly addresses agent reliability, scaffold behavior, process monitoring, and evaluation beyond endpoint success.

Evidence basis: formal compliance metrics, plan mutations, reminder intervention. Limiter: software-engineering-only domain. Would raise: replication in web, scientific, or clinical tool agents.

Strong contribution in turning plan-following into a measurable process construct and experimentally manipulating plans at scale.

Implementation value

Highly actionable for agent harness design: instrument phase compliance, test plan mutations, use reminders, and avoid treating strict compliance as the goal.

Evidence basis: formal metrics, every-five-step reminder intervention, model-specific failure modes, public artifact. Limiter: reminder cadence and intervention thresholds are not optimized. Would raise: online adaptive controller experiments with cost/latency tradeoffs.

Strengths

  • Separates process correctness from task-level success instead of assuming one implies the other.
  • Uses controlled plan mutations rather than purely observational trajectory analysis.
  • Formal metrics are simple, reproducible, and interpretable; mapping validation is unusually strong for a process-abstraction paper.
  • Explicitly checks nondeterminism and re-runs analyses on reproducible subsets rather than ignoring stochastic instability.
  • Tests both a more familiar benchmark and a harder benchmark intended to reduce training overlap.
  • Finds a practical intervention—periodic reminders—that is plausible to deploy in existing agent scaffolds.

Principal limitations / concerns

  • Causal overreach risk: “fine-tuning paradigm,” “data contamination,” “context pressure,” and “short-term reward” are plausible explanations, but the experiments mainly manipulate plans, not those causes directly.
  • DeepSeek-R1 confounding: 349 malformed-tool-call cases in No Reproduction and 413 tool-call failures in Summary mean some performance loss is scaffold/interface failure rather than a clean test of planning.
  • Metric normativity: PPF penalizes out-of-plan phases even when those phases—such as regression testing—may be useful. PC is therefore best interpreted as descriptive alignment, not quality.
  • Compression by first occurrence: POC uses first occurrences and can miss whether later cycles are strategically appropriate or whether an early accidental phase creates a misleading ordering score.
  • Generalization bottleneck: the detailed SWE-bench Pro comparison is filtered to 31 resolvable instances, which is informative but small and selected.
  • Statistical reporting: some p-values are reported, but effect-size uncertainty and confidence intervals are not a consistent part of the plan-variant comparisons.

Bottom line

The paper is persuasive that plans influence agent trajectories even when agents do not follow them exactly, that plan quality/alignment can matter more than nominal compliance, and that reminders can help long-horizon execution. It is less persuasive as evidence for the exact causal origins of plan violations. The most reusable contribution is the evaluation framing: treat compliance as a process signal to monitor and intervene on, not as a single optimization target.

Implementation takeaways

1. Instrument plans explicitlyRepresent plan phases as typed states/events and compute phase coverage, first-occurrence order, and out-of-plan actions from traces. Keep raw traces for audit.
2. Separate adherence from qualityDo not reward high PC by itself. Pair compliance with task success, failure mode, cost, latency, and human-defined safety/quality checks.
3. Add targeted remindersA simple scaffold intervention is to re-surface the active plan periodically or after drift signals. The paper’s fixed schedule is every five steps; production systems should test adaptive thresholds.
4. Test plan mutations per modelPlan steps that help one model can distract another. Treat plan architecture as a model/scaffold compatibility surface requiring evaluation.
5. Distinguish useful deviationsRegression tests are a concrete example of an out-of-plan behavior that may be beneficial. Log why a phase is out-of-plan before classifying it as harmful.
6. Detect scaffold failures separatelyMalformed tool calls should be a distinct failure class from plan noncompliance; otherwise compliance analyses can mistake interface fragility for strategic behavior.
7. Stress-test on harder distributionsCompliance measured on a familiar benchmark can overstate robustness. Re-run both plan and process metrics on distribution shifts and low-overlap datasets.
8. Use process supervision cautiouslyPost-training can teach plan following, but retain the ability to override a bad order or unnecessary phase. Optimize for task-appropriate behavior, not obedience.

Build-useful evaluation harness

for each (model, task, plan_variant):
    run agent → trace
    map actions → phase labels
    compute PPC / POC / PPF / PC
    record success + cost + tool failures
    classify deviations:
        missing phase
        harmful reorder
        useful out-of-plan action
        context drift
        scaffold/tool-format failure
    if harmful drift persists:
        re-surface plan or revise plan
compare across repeated runs and shifted benchmarks
Do not overclaim from this paper: it does not show that every agent should follow a fixed plan, that five-step reminders are universally optimal, that plan compliance is a safety guarantee, or that benchmark contamination is the proven explanation for any specific model’s behavior.
