One-page synthesis

Verdict: Read first. This is highly relevant to practical agent harness design because it reframes memory as a decision-time presentation problem rather than merely a storage or retrieval problem. The architecture is conceptually clear, modular, and directly adaptable to structured agent state.

Core thesis

Agents can retain and retrieve the right information yet still fail because the information is poorly formed, mixed with functionally different content, weakly prioritized, or presented with insufficient salience. The authors call this post-access failure the Memory-Action Gap. MemArbiter addresses the memory-management component by converting history into atomic items, organizing those items into functional banks, and controlling their prompt-level presentation over time.

What the system does

MemArbiter uses five banks—Goal, Task State, Constraint, Episodic, and Reference—plus dual representations for each item: a detailed focal form and a compressed ambient form. Bank-level demand and item-level relevance inform a stateful temporal gate that promotes, retains, demotes, or hides items before assembling the next action prompt.

Headline results

Across 134 ALFWorld out-of-distribution tasks, MemArbiter achieved 82.84% success with a 500-token memory budget and 92.54% with 750 tokens. The strongest flat baseline reached 61.94% and 67.16%, respectively. With GPT-5.4 used only for action generation at 500 tokens, MemArbiter reached 83.58% versus 70.89% for Flat Retrieval and 73.13% for Flat Recency.

Why it matters

The strongest practical insight is not the five-bank taxonomy itself. It is the separation of memory content from memory presentation state. A memory item remains stable while its visible form and salience change as the task evolves. This is a useful design pattern for chat-interface workflows, clinical decision support prototypes, multi-step code generation, and other constrained-context systems.

Main limits

The evaluation is narrow: one environment, one task family, one run per task for the principal open-weight experiments, no reported confidence intervals or significance testing, no cost/latency accounting for the additional parsing and writing calls, and no direct causal intervention proving that specific promotion or demotion decisions caused improved actions. Implementation details are conceptual rather than sufficient for exact reproduction.

Section condensation

1. Introduction

The paper distinguishes memory accessibility from memory influence. Existing work largely improves retention, retrieval, compression, or episodic storage, but retrieved information may still fail to shape action selection. The proposed Memory-Action Gap occurs after information is available to the memory-management pipeline and may arise from either poor memory management or model reasoning limits; this work targets the former.

The authors argue that heterogeneous information serves different decision functions and temporal roles. Raw observations may combine state, outcome, constraints, and reference facts, making block-level storage difficult to update and prioritize. MemArbiter therefore treats memory management as end-to-end arbitration across formation, organization, relevance estimation, temporal presentation, and prompt assembly.

2. Preliminaries and problem formulation

The agent follows a ReAct-style loop. At each step, the memory module converts accumulated cross-step information into a prompt-visible context used alongside the current observation. A memory item is defined as an atomic, future-useful unit extracted from goals, observations, or interaction outcomes.

Items are assigned one primary functional role: Goal directs behavior; Task State represents the current decision condition; Constraint prevents invalid behavior; Episodic records prior attempts and outcomes; Reference preserves reusable environmental facts. The taxonomy is justified by different update patterns, persistence, and activation conditions.

3. MemArbiter

A state parser derives subgoal, progress, relevant entities, and unresolved information needs. A Candidate Writer proposes bank-specific additions or revisions, followed by validity checking, deduplication, and conflict handling. Update behavior differs by bank: Task State replaces snapshots, Constraint merges or revises rules, Episodic appends events, and Reference consolidates facts.

Each item has focal and ambient renderings. Bank-level demand estimates the need for a memory role; item-level relevance estimates the value of a specific item. A stateful temporal gate uses present signals, prior presentation state, and relevance history to assign focal, ambient, or hidden status. Prompt assembly groups items by bank, presents focal before ambient, orders within bands by relevance, and excludes hidden content.

4. Experiments

The evaluation uses all 134 unseen tasks in ALFWorld's eval_out_of_distribution split, with a 50-step cap. Comparators are Flat Recency and BM25-based Flat Retrieval under identical 500- and 750-token memory-presentation budgets. Qwen3.6-27B-FP8 performs action generation, candidate writing, and state parsing; a cross-model experiment swaps GPT-5.4 into action generation only.

Primary performance is SR@50, with cumulative SR@k curves, ablations, and diagnostics for recovery and recurrence. MemArbiter substantially exceeds both baselines under both budgets. Removing functional banks or dynamic signals causes the largest final degradations; removing the temporal gate improves early SR@15 but reduces final SR@50, supporting the claim that stateful presentation matters more as trajectories lengthen.

5. Related work

The paper positions itself between long-term agent memory, in-trial context compression, subgoal-organized working memory, revisable execution context, and learned memory editing. Its claimed distinction is explicit arbitration of heterogeneous within-trajectory memory by decision function and presentation salience.

The framing also draws on evidence that relevant information can be underused due to prompt position and that retrieved experience can propagate error. The contribution is therefore not retrieval itself but deciding which accessible memories should become prominent, compressed, or temporarily absent at each step.

6. Limitations and future work

The authors acknowledge a single-environment evaluation, explicit hand-designed roles, and associative rather than causal mechanism evidence. They propose testing web, multimodal, and open-ended environments, adapting roles to domains, and using controlled interventions on presentation states.

Additional unaddressed limitations include absent uncertainty estimates, limited reproducibility detail, unclear inference overhead, no comparison with stronger modern memory managers, and no test of robustness to memory-write errors or adversarially incorrect items.

7. Conclusion

The authors conclude that memory effectiveness depends on arbitration after storage and retrieval. Function-aware organization, dynamic relevance, and temporal presentation improved success, recovery, and recurrence metrics under fixed prompt budgets.

The conclusion is supported within ALFWorld, but claims should remain benchmark-scoped until replicated across environments, models, and independently implemented systems.

Evaluation and appraisal

Relevance
9.5 / 10

Directly applicable to agent harnesses, structured context engineering, and long-running chat workflows.

Evidence basis: Explicit bank taxonomy, temporal gate, prompt-budget controls, and failure-response analysis.
Limiting factor: Not evaluated in the user's clinical, coding, or web-agent settings.
Raise/lower: Cross-domain validation would raise it; failure to transfer would lower it.

Novelty
8.0 / 10

The post-access Memory-Action Gap and decision-time presentation framing are useful conceptual contributions.

Evidence basis: Separation of functional role from focal/ambient presentation state.
Limiting factor: Many ingredients resemble established working-memory, hierarchical context, and salience-management ideas.
Raise/lower: Stronger differentiation from close contemporaneous systems would raise it.

Method strength
6.5 / 10

Controlled budgets, ablations, and behavioral diagnostics are good, but the study remains a narrow benchmark experiment.

Evidence basis: Same task set and memory budgets across methods; 134 OOD tasks; component ablations.
Limiting factor: One environment, simple baselines, one principal run per task, no statistical uncertainty.
Raise/lower: Replication, stronger baselines, repeated seeds, and significance analysis would raise it.

Evidence strength
6.5 / 10

The reported effects are large and internally coherent, but precision and causal mechanism evidence are limited.

Evidence basis: 20.9- and 25.38-point gains; ablation degradation; recovery and recurrence improvements.
Limiting factor: No confidence intervals, significance tests, or independent replication.
Raise/lower: Pre-registered replication and controlled memory-state interventions would raise it.

External validity
4.5 / 10

Transfer is plausible but not demonstrated beyond ALFWorld.

Evidence basis: Cross-action-model persistence with GPT-5.4.
Limiting factor: Same environment and same Qwen-based memory manager; no web, coding, multimodal, or open-ended tasks.
Raise/lower: Multi-environment and independent implementation results would raise it.

Implementation value
8.0 / 10

The architecture yields a strong blueprint for structured memory systems even without exact code.

Evidence basis: Clear stages, bank semantics, update behavior, dual-band representations, and gate concept.
Limiting factor: Missing prompts, thresholds, schemas, cost, latency, and operational details.
Raise/lower: Released code and end-to-end configuration would raise it substantially.

Main strengths. Large absolute benchmark gains under fixed prompt budgets; interpretable architecture; useful separation of memory role and presentation form; appropriate ablations; diagnostics aligned with claimed mechanism.
Main limitations. Single benchmark, weak comparator set, absent uncertainty, unknown extra inference cost, incomplete reproducibility, hand-designed roles, and no robustness test against incorrect or conflicting memory writes.
Bottom line. Treat this as a high-value architecture paper and implementation template, not as proof that the exact five-bank design is universally optimal. The most transferable contribution is stateful, function-aware salience control under a fixed context budget.

Implementation and workflow takeaways

1. Store atoms, not transcript blocksSplit observations into independently updatable facts, constraints, state changes, action outcomes, and references.
2. Separate semantics from salienceKeep the canonical memory item stable; change only its rendered form and visibility.
3. Protect invariant contentGoals and active constraints should resist ordinary recency decay until completed, superseded, or invalidated.
4. Treat failures as presentation triggersA failed action should automatically raise relevant episodic evidence and applicable constraints.
5. Make state replacement explicitCurrent state should overwrite stale snapshots rather than coexist ambiguously.
6. Budget by function, then by itemFirst decide which memory roles matter now; then rank items inside those roles.

Practical adaptation for chat/web workflows

Suggested lightweight structure for a living Markdown artifact:

GOAL
- Persistent completion criteria.

CURRENT STATE
- Latest validated status only.

CONSTRAINTS
- Hard rules, exclusions, safety conditions, and non-negotiable requirements.

EPISODIC LEDGER
- Recent actions, observed results, failures, and corrections.

REFERENCE
- Stable facts, source identifiers, formulas, filenames, and reusable parameters.

DECISION-TIME VIEW
- FOCAL: full text for items directly needed in the next step.
- AMBIENT: compressed reminders for still-relevant background.
- HIDDEN: retained in the artifact but omitted from the next prompt.

Where this maps to your existing method

Your staged Markdown-to-pseudocode-to-HTML workflow already resembles a manual MemArbiter. The stage goal acts as Goal memory, the living draft acts as Task State, canned instructions function as Constraints, prior step outputs form Episodic memory, and attached source files or formulas serve as Reference memory. The main upgrade would be to explicitly mark which items are focal versus ambient at each step and to replace stale state rather than continuously append.

Do not overclaim

  • Do not assume the exact five banks are optimal for every domain.
  • Do not infer that improved prompt organization eliminates reasoning failures.
  • Do not use ALFWorld success as evidence of clinical, software-engineering, or production safety.
  • Do not ignore the cost and error surface introduced by memory-writing and state-parsing model calls.
