One-page synthesis

Core thesis. SKILLER optimizes the text of an agent skill as a policy while keeping the compact executor frozen. A strong-model critic diagnoses verifier-grounded failures and a strong-model actor makes bounded edits, optionally creating task-local helper scripts; replay memory preserves prior failures and effective edits.

The method addresses a model-mismatch hypothesis: skills written for frontier models may be too verbose, weakly grounded, or insufficiently mechanical for compact models. SKILLER therefore treats the small-model agent loop as the environment, uses the benchmark verifier for reward/diagnostics, conditions updates on a successful reference trajectory, and transfers all optimization signals through natural language rather than gradient updates. The system explicitly supports preservation, regression rollback, and deterministic helper-script synthesis.

Across Table 1, the strongest evidence is on structured skill and software-engineering tasks. Qwen3.5-9B + SKILLER reaches 73.91 on SkillsBench and 82.80 on SWE-Skills-Bench, compared with the strongest listed non-SKILLER baselines of 60.87 and 62.40. Results are less uniformly dominant elsewhere: Qwen3.5-9B ties SkillX on GAIA (49.40); Qwen3.5-4B trails SkillX on SkillsBench (42.03 vs 43.48) and GAIA (43.78 vs 44.18); and it ties Manus on EarthBench (71.51). The held-out GAIA/EarthBench tests support same-benchmark transfer, but are not external-dataset validation.

Interpretation constraint. The paper's repeated language that SKILLER “consistently outperforms” baselines is broader than the individual Table 1/2 cells support. Several cells are ties or losses. The central result remains strong on SkillsBench and SWE-Skills-Bench, but the global superiority claim should be qualified.

Section condensation

Abstract and Introduction

The paper frames agent skills as standardized procedural artifacts that constrain agent behavior, arguing that frontier-model-authored skills can mismatch compact executors. SKILLER is proposed as an offline skill-construction framework that uses strong models to optimize text artifacts for smaller Qwen executors. The abstract reports gains of 4.3-20.4 percentage points for the 9B model and 1.8-13.3 points for the 4B model over selected skill-generation/evolution methods, plus much lower executor token pricing than frontier models on the illustrated SkillsBench comparison.

The introduction motivates natural-language policy iteration rather than weight updates. Its three stated contributions are a skill-generation framework for compact executors, language-level propagation of RL signals, and evaluation across SkillsBench, SkillLearnBench, SWE-Skills-Bench, GAIA, and EarthBench.

Related Work

The source positions SKILLER among agent-skill acquisition/evolution, memory, RL, and executable-skill systems. The distinctive claim is not that skills or verbal feedback are new, but that the target compact model is explicitly treated as the environment and the textual skill is iteratively repaired using verifier-grounded evidence.

Method

For task instance x and skill K, the frozen compact model generates a trajectory. The environment returns trajectory, reward, and verifier diagnostics. The structured state combines the task, current trajectory, successful reference trajectory, and diagnostics. The critic produces localized modification suggestions; replay memory stores failure signatures, critic summaries, and accepted edits/outcomes; the actor performs bounded Insert/Replace/Create/Delete operations and may create task-local helpers.

The successful reference trajectory is privileged optimization-side evidence, explicitly barred from direct runtime use. This makes SKILLER closer to verifier-guided, reference-supervised textual policy search than conventional gradient RL. The method also describes batch optimization and snapshot rollback after regressions.

Experimental setup

SkillsBench uses 26 single-skill tasks; SWE-Skills-Bench uses 10 selected skill-sensitive tasks covering 117 instances; SkillLearnBench uses 100 verified task instances; GAIA uses 165 validation instances; EarthBench uses 248 samples. GAIA and EarthBench split half of stratified instances for skill generation and the remainder for held-out same-benchmark testing. Target executors are Qwen3.5-9B/4B in OpenCode; GPT-5.4 is the reported strong-model actor/critic during offline generation.

Results are averaged over three executions of the same skill. Main text says SKILLER uses a five-step reinforcement-learning schedule across tasks. Appendix E describes the released SkillsBench configuration as three optimization rounds, creating a configuration/schedule ambiguity that should be resolved from code before exact reproduction.

Main results

SKILLER is especially strong on SkillsBench and SWE-Skills-Bench. For Qwen3.5-9B it scores 73.91 and 82.80, respectively; for Qwen3.5-4B it scores 42.03 and 66.70. The 4B SWE result exceeds all listed 9B baselines other than SKILLER itself, supporting the paper's claim that executor-specific behavioral constraints can compensate for some parameter-scale disadvantage on highly structured tasks.

Performance is mixed on broader information-seeking/domain tasks. Qwen3.5-9B ties the best baseline on GAIA and leads on EarthBench. Qwen3.5-4B does not lead SkillsBench or GAIA, ties EarthBench in Table 1, and trails Manus on the EarthBench held-out split. These exceptions matter when interpreting the paper's global superiority language.

Ablations, cost, and appendices

State ablation shows task instance and current trajectory are the most consequential state components on SkillsBench/SWE. Critic ablation identifies conversion of diagnosis into a concrete skill modification (“Generation”) as the most important critic operation. Actor ablation indicates helper-script synthesis is especially important on SkillsBench/SWE. These experiments support the mechanism claim that grounded, executable repair—not merely generic reflection—drives gains.

Cost analysis reports only strong-model skill-generation consumption, excluding compact-model downstream evaluation tokens. SKILLER costs $8.95 in the five-benchmark Qwen3.5-9B aggregate versus $14.55 for SkillX, while AutoSkill/EvoSkill are cheaper but substantially lower scoring. Appendix F/G show nonmonotonic updates and motivate snapshot rollback: later local repairs can preserve most gains without improving the best checkpoint.

Conclusion

The authors conclude that natural-language policy iteration can offload procedural reasoning into explicit constraints and deterministic helper tools, making compact model agents more reliable and economical without weight updates. The benchmark evidence supports the concept, particularly for structured tool-use/software tasks, but deployment-scale generalization remains untested.

Evaluation and appraisal

Verdict: Read first. Best use: design pattern for verifier-guided skill adaptation of compact agents and for externalizing deterministic procedures into auditable artifacts. Do not treat it as proof of broad cross-model deployment reliability or as evidence that SKILLER wins every benchmark setting.
9/10

Relevance

Highly relevant to reusable agent skills, small-model execution, verifier feedback, and agent reliability.

Evidence basis: Directly studies compact executors, skill artifacts, tool use, memory, rollback, and executable helpers.

Principal limiting factor: No production or domain-specific deployment evaluation.

Would raise/lower: Higher with real deployment studies; lower if the target use case does not involve structured tool execution.

8/10

Novelty

The textual-policy framing and bounded actor/critic repair loop are a meaningful synthesis of skill evolution, verifier feedback, and compact-model adaptation.

Evidence basis: Explicitly optimizes the skill artifact rather than model weights and integrates state, reference trajectories, replay evidence, bounded edits, and helpers.

Principal limiting factor: Relies on familiar ingredients: verbal feedback, trajectory comparison, memory, and strong-model distillation.

Would raise/lower: Higher if shown to generalize across agent harnesses/model families; lower if prior systems implement an equivalent loop.

7/10

Method strength

Broad benchmark coverage and targeted ablations support the mechanism, but evaluation design has important selection and reproducibility limits.

Evidence basis: Five benchmarks, two executor sizes, three-run averages, held-out tests, state/critic/actor ablations, cost and qualitative analyses.

Principal limiting factor: SWE subset is preselected for skill sensitivity; no uncertainty/significance; main-text five-step schedule conflicts with Appendix E three-round SkillsBench description.

Would raise/lower: Higher with preregistered/full benchmark coverage, variance/CI reporting, and fully consistent released configurations.

7/10

Evidence strength

Data strongly support benefits on structured skill/software tasks, but evidence for universal superiority is weaker.

Evidence basis: Large gains on SkillsBench/SWE and mechanism-consistent ablations; same-benchmark held-out transfer on GAIA/EarthBench.

Principal limiting factor: Several Table 1/2 cells are ties or losses despite broad superiority wording; no statistical uncertainty is reported.

Would raise/lower: Higher with repeated-seed distributions, significance/CI, and independent replication; lower if code reproduction fails.

5/10

External validity

Generalization is demonstrated within benchmarks, not across model families, harnesses, or deployment environments.

Evidence basis: Two Qwen compact scales and five task families provide some breadth.

Principal limiting factor: Single compact-model family, OpenCode loop, selective subsets, and same-benchmark held-out splits.

Would raise/lower: Higher with Gemma/Llama/other Qwen variants, multiple harnesses, cross-benchmark transfer, and production workloads.

8/10

Implementation value

The paper provides unusually actionable architecture, prompts, bounded edit semantics, replay/rollback logic, and released project code.

Evidence basis: Figures 2/4/5, Appendix E, helper-script design, snapshot rollback, and a public project link.

Principal limiting factor: Strong-model dependency and successful reference trajectory requirements may be costly or unavailable; exact schedule details need reconciliation.

Would raise/lower: Higher with complete reproducibility scripts, cost accounting including executor evaluation, and reference-free variants.

Strengths

  • Mechanism is explicit and auditable: state, reward, critic diagnosis, bounded actor edit, replay memory, and rollback are separable components.
  • Ablations are aligned with architectural claims rather than only reporting final benchmark scores.
  • Structured-task gains are large enough to be practically meaningful, especially SWE-Skills-Bench.
  • Helper-script synthesis is treated as an execution artifact, reducing reliance on compact-model internal arithmetic/procedural consistency.
  • Cost analysis separates offline strong-model skill construction from compact executor evaluation, making the optimization budget visible even though it is incomplete end-to-end accounting.

Principal limitations and claim checks

  • Claim inflation: SKILLER does not strictly beat every listed baseline in every Table 1/2 cell.
  • Selection bias: the SWE subset intentionally selects tasks where skills measurably affect performance.
  • Limited uncertainty: scores are three-run averages without reported variance, confidence intervals, or statistical tests.
  • Same-benchmark transfer: GAIA/EarthBench “zero-shot” tests are held-out instances from the same benchmark distributions.
  • Executor generalization: only Qwen3.5-9B/4B are evaluated; cross-family portability of generated skills is not shown.
  • Privileged supervision: a successful reference trajectory is used during optimization. This is disclosed and blocked at runtime, but it may limit availability/scalability and means the method is not reward-only search.
  • Cost boundary: Table 4 excludes compact-model downstream evaluation tokens and therefore is not total lifecycle cost.
  • Configuration ambiguity: main text describes five optimization steps across tasks, while Appendix E says the released SkillsBench configuration runs three rounds.
What would falsify the strongest interpretation: failure to reproduce the large SWE/SkillsBench gains under the released configuration; loss of benefit on other compact-model families; or evidence that improvements depend mainly on privileged reference trajectories rather than verifier-grounded localized repair.

Implementation / research takeaways

Build pattern

Represent a skill as a versioned artifact with explicit tool contracts, deterministic helpers, and bounded edit primitives rather than an unrestricted prompt blob.

Feedback pattern

Capture task, current trajectory, reference/success evidence, verifier diagnostics, and reward separately. Preserve causal localization before editing.

Safety / stability

Store accepted edits and outcomes; snapshot every round; roll back to a passing skill after regression; audit direct oracle/reference leakage.

Optimization strategy

Prefer small localized edits and helper extraction when failures are procedural. Do not assume more generated text or more update steps improve the policy.

Evaluation design

Report full baseline cells, uncertainty across seeds/runs, checkpoint selection policy, and end-to-end cost including executor evaluation. Separate same-benchmark holdout from external transfer.

Next experiment

Test reference-free critic variants and cross-family portability: generate a skill for one compact executor, then measure reuse/adaptation cost on other models and harnesses.
