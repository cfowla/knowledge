One-page synthesis

Core thesis. Agent skills should not be retrieved and compressed as indivisible documents. SkillZip instead treats source-grounded procedural sections—with explicit interfaces, dependencies, resources, guards, verifiers, and provenance—as the shared unit for retrieval, compression, execution, and maintenance.
What changes conceptuallyThe paper reframes skill retrieval as executable-context compilation. Sec2Graph creates occurrence-specific section nodes; MotifZip compresses recurring contract-compatible subgraphs into reversible ported macros; PathHydrate retrieves a dependency-closed verifier-reachable subgraph under a context budget; ReZip promotes or revises macros as new skills and execution traces arrive.
Main empirical claimAcross the directly comparable main settings, SkillZip reports the highest task performance and retrieval quality, with a 3.46× compression ratio, 99.2% dependency preservation, 98.7% verifier reachability, and substantially lower delivered context than whole-skill loading.
Most important result. Compression quality depends on preserving executable structure, not merely reducing tokens. At the same rounded 3.46× compression ratio and 1,941-token rendered context, text compression drops dependency preservation to 65.0%, verifier reachability to 60.0%, and reward to 25.5, whereas SkillZip retains 99.2% / 98.7% and reward 33.3.
Principal limitation. Evidence remains benchmark-centered and author-controlled. The paper tests two benchmark families, many perturbations, and six LLM backbones, but the source does not report independent replication or real production skill-library deployment. Contract extraction is a central dependency and is imperfect (macro-F1 91.6; exact match 84.6).
Best useArchitecture and implementation reference for procedural-memory systems, skill retrieval, graph-based context compilation, and reversible compression.
Do not use forAssuming that graph compression is safe simply because benchmark structural metrics are high, or treating the framework as production-validated.
Bottom lineBuild-useful and benchmark-useful. The contract-preserving abstraction is the paper’s durable idea; exact performance numbers need independent reproduction.

Section condensation

Abstract

The abstract identifies a unit mismatch in existing skill systems: whole packages are retrieved, text is compressed, and execution graphs are constructed only after retrieval. SkillZip proposes a persistent section-level graph whose recurring motifs can be rewritten as reversible macros while retaining boundary signatures, dependency closure, verifier reachability, and source expansion.

Reported headline results are up to 12.2 points over the strongest baseline, a 3.46× compression ratio, 99.2% dependency preservation, 98.7% verifier reachability, and robust retrieval as the skill library scales from 200 to 100K skills.

1. Introduction

The introduction argues that procedural knowledge is internally modular even when stored as a single “skill” artifact. Overlap across skills—such as CSV ingestion, normalization, or validation—creates retrieval redundancy and ambiguity when whole packages remain the retrieval unit.

Four challenges motivate the system: reuse-granularity mismatch; contract preservation under compression; persistent executable compression rather than task-time graph compilation; and execution-aware maintenance. The proposed unifying object is a contract-bearing section subgraph that survives retrieval, compression, execution, and source expansion.

2. Related Work

The paper positions SkillZip between agent-skill/procedural-memory systems, skill-level retrieval/orchestration, prompt/skill compression, and graph mining/summarization. Its distinction is not merely using graphs: it makes section-level source occurrences the reusable unit and requires executable contract preservation during compression.

The detailed related-work appendix broadens this comparison to skill acquisition, graph-structured skill schemas, progressive disclosure, multi-granularity retrieval, procedural compression, and graph grammars. The source frames prior systems as useful foundations that generally do not combine persistent cross-skill section compression, explicit verifier-aware contracts, reversible expansion, and task-conditioned hydration in one representation.

3. Preliminaries

The paper defines a section node as a typed procedural unit carrying execution role, content, input/output signatures, resources, guards/verifiers, and source provenance. Nine operational roles are used: Intent, Trigger, Input, Precondition, Operation, Resource, Failure, Verifier, and Output.

A procedural skill graph contains occurrence-specific nodes plus canonical prototypes linked by equivalence edges. A macro compresses a connected section subgraph through typed boundary ports and retains an expansion rule plus contract. Verifier reachability is explicit: every state-changing operation or macro must retain a directed path to at least one verifier.

4. Method

Sec2Graph grounds source sections and extracts typed contracts; MotifZip mines structurally compatible recurring subgraphs and accepts only those with clear boundaries, stable signatures, dependency closure, verifier reachability, and positive compression gain; PathHydrate maps a query to section anchors, connects and repairs a compact executable subgraph, and progressively expands macros; ReZip incrementally reuses, promotes, demotes, splits, or retires macros based on new skills and execution traces.

The central formal claim is structural rather than semantic: reversible macro rewriting can reconstruct the recorded source graph and preserve typed external dependencies and verifier reachability for non-conflicting occurrences. The authors explicitly state that this does not prove equivalence of unrecorded behavior or correctness of the verifier itself.

5. Experiments

Main experiments use SkillsBench and ALFWorld. In the default SkillsBench setting the library has 1,000 skills, MiniMax-M2.7 is the backbone, and the procedural-content selection budget is 3,000 tokens; ALFWorld uses a 1,200-token default. SkillsBench evaluates 87 tasks using deterministic executable verifiers; ALFWorld evaluates all 140 episodes of the valid_seen split.

Experiments cover task reward/success, Ret@1/Ret@5/MRR, compression ratio, rendered tokens, dependency preservation, verifier reachability, recovery, contract corruption, procedural overlap, library scaling, domain transfer, budget sensitivity, runtime/cost, streaming updates, repeated runs, cross-backbone behavior, and failure attribution.

6. Conclusion

The conclusion reiterates that scalable skill libraries benefit from aligning the representation unit across storage, retrieval, compression, and execution. The reported evidence supports the narrower claim that section-level, verifier-aware, reversible compression can deliver smaller and more effective task context than whole-skill or text-only alternatives in the tested environments.

Method architecture

Sec2GraphSegments packages using headings, lists, code, warnings, argument descriptions, tool references, and tests; infers roles; extracts signatures/resources/guards; connects dependencies, verifiers, repairs, weak order, membership, and endpoints; then links contract-compatible occurrences through canonical prototypes without erasing source identity.
MotifZipStarts from typed signature buckets, grows motifs over dependency/weak-order neighborhoods, counts non-conflicting source occurrences, validates macro contracts, scores positive description-length gain, then greedily rewrites non-overlapping motifs into ported reversible macros.
PathHydrateAnalyzes the task into goal, outputs, capabilities, inputs, domain/profile, and ordered subgoals; fuses section-level and skill-level evidence; connects seeds; repairs required roles and verifier paths; then renders each macro at name, contract, outline, or full-source level.
ReZipMatches new skill regions against existing macros, buffers residuals, promotes recurring valid residual motifs, and tracks macro expansion/failure/repair evidence. Risk first increases hydration detail; persistent risk can split or retire a macro while retaining source-grounded expansion.
Representation invariant
source skill package
  → occurrence-specific typed sections
  → dependency / verifier / resource / membership edges
  → contract-valid recurring motif
  → reversible macro with typed ports + expansion map
  → task-time dependency-closed hydrated subgraph
  → execution log feeds maintenance
Critical dependency. The safety value of MotifZip and PathHydrate is conditional on correctly extracted contracts. The paper’s corruption study confirms graceful degradation at modest corruption but substantial loss at high corruption.

Algorithm 1 — SkillZip Workflow

Input: skill library S, update stream U, query q, executor profile p, budget B
1. Sec2Graph each skill and merge into raw graph G
2. Link canonical prototypes
3. MotifZip(G) → compressed graph + macro dictionary
4. PathHydrate(q,p,B) → rendered context + hydration log
5. ReZip over new skills / execution traces
Output: context, log, updated compressed graph
Appraisal: Clear end-to-end contract; separates persistent library construction from task-time context hydration and ongoing maintenance.

Algorithm 4 — PathHydrate

AnalyzeTask → BuildSeedQueries → DenseSectionScore
→ skill-document + node-max RRF concentration → ConnectSeeds
→ AttachScaffold / verifiers → prune/fill → RepairClosure → EnforceBudget
→ ChooseMacroRenderLevels → RenderContract → RecordHydration
Appraisal: The algorithm treats budget as an allowance, not a quota, and stops when sufficiency conditions are met.

Algorithm 5 — ReZip

New skill: Sec2Graph → MatchMacros → AssimilateSkill → buffer residuals
→ promote residual when support ≥ m, gain > 0, contract valid
Execution trace: update macro stats → compute risk → ReviseMacro if threshold exceeded
Appraisal: Operationalizes skill-library evolution rather than treating compression as one-shot preprocessing.

Algorithm 6 — EvaluateSkillZip

For each query: hydrate compressed context + render uncompressed context
→ paired execution → dependency preservation / verifier reachability
→ expansion / fallback / downstream inflation / token reduction
→ aggregate task + structural metrics
Appraisal: Evaluation explicitly measures whether compact context remains executable rather than only smaller.

Appendix findings and reproducibility details

BenchmarksDefault SkillsBench: 1,000-skill library, 87 tasks, deterministic executable verifiers, MiniMax-M2.7, 3,000-token procedural-selection budget. ALFWorld: 37-skill library, all 140 valid_seen episodes, 1,200-token default, 30 environment steps, 60 model turns, at most two source expansions.
Retrieval and decodingBGE-M3 dense encoder; initial recall capped at 12; lower-ranked skill retained only when cosine similarity ≥0.45 and ≥0.90 of the top score. Task-analysis, retrieval-control, and action calls use temperature 0 and deterministic decoding when supported.
MotifZip / PathHydrate weightsMotifZip: α=0.5, λ=0.3, μ=0.2 after scaling objective terms; contract-invalid motifs are rejected before scoring. PathHydrate: η=0.4 and β=γ=δ=0.2 after normalizing token cost by selection budget.
Runtime environmentSkillsBench via BenchFlow 0.6.2 in isolated Docker containers. Local graph construction measured on Intel Xeon Gold 6248R CPU with 512 GB RAM; timed graph construction + MotifZip is single-process. Provider inference is remote and excluded from local graph-search latency.
Statistical protocol. Repeated statistical experiments use five matched runs. Methods are paired by task/episode and random seed; confidence intervals use 1,000 paired bootstrap samples over outcome-level differences, and p-values use paired permutation tests.
Leakage safeguard. SkillsBench verifier source, excerpts, assertions, and intermediate outcomes are withheld from task anchoring, retrieval, hydration, and agent execution; verifiers are invoked only after execution to score artifacts. The task anchoring prompt is derived from the agent-visible task brief and metadata.
Prompt appendix. Appendix F provides prompt templates for section role/contract extraction, cross-section signature canonicalization, SkillsBench task anchoring, ALFWorld task anchoring, SkillsBench execution context, and ALFWorld action/source-expansion behavior. The prompts use strict JSON schemas and shared contract/signature vocabularies. Full wording is not reproduced here because the load-bearing reproducibility constraints are captured above and in the method summary.
Reproducibility boundary. The 100K structural-scaling result begins from cached extracted section records. Fresh LLM-assisted role/contract extraction time is provider-dependent and is explicitly not extrapolated to 100K skills.

Evaluation & appraisal

Verdict: Read first. This is a high-value architecture paper for agent skill libraries and procedural memory. Its most durable contribution is the insistence that compression preserve explicit executable contracts and remain reversible to source sections. Treat the exact benchmark gains as promising but not deployment proof.
9/10
Relevance

Directly addresses scalable skill retrieval, context compression, executable procedural memory, verifier-aware execution, and incremental library maintenance.

Evidence basis: full architecture plus two benchmark families and implementation details. Limiting factor: relevance is highest for agent-skill systems, not general RAG. Would raise: validated use in real skill repositories.

8/10
Novelty

The combination of occurrence-specific section graphs, contract-preserving reversible macros, budgeted hydration, and execution-driven maintenance is meaningfully distinct.

Evidence basis: explicit differentiation from whole-skill retrieval, text compression, task-time graphs, and generic graph grammars. Limiting factor: individual ingredients draw on established graph mining, procedural memory, and progressive disclosure. Would raise: clearer proof that the combination enables capabilities unavailable to prior structured-skill systems.

8/10
Method strength

Strong comparative design with multiple baselines, ablations, corruption tests, overlap controls, scaling, streaming updates, cost accounting, repeated runs, and paired statistical testing.

Evidence basis: Tables 1–14 and Appendix D. Limiting factor: preprint, author-controlled implementation, and some controlled/synthetic stressors. Would raise: independent reproduction, open artifacts, and externally run benchmarks.

7/10
Evidence strength

Results consistently support the narrow claim that section-level contract-aware context can outperform coarse or lossy alternatives under the tested settings.

Evidence basis: two benchmarks, six backbones, five-run paired statistics, structural metrics, and cost studies. Limiting factor: no independent replication or production outcome evidence; contract extraction remains imperfect. Would raise: third-party replication and real-world failure data.

6/10
External validity

SkillsBench domains plus ALFWorld and six LLM backbones demonstrate cross-task and cross-executor transfer, but both are benchmark environments.

Evidence basis: domain partition, ALFWorld, 200→100K distractor scaling, cross-backbone tests. Limiting factor: no production skill library, organizational permissions, adversarial/malicious skills, or long-term live maintenance. Would raise: deployment across heterogeneous real repositories and tool ecosystems.

9/10
Implementation value

The paper is unusually actionable: formal objects, explicit invariants, six algorithms, parameter settings, prompt schemas, runtime measurements, maintenance logic, and failure taxonomy are provided.

Evidence basis: Sections 3–4 and Appendices A/D/F. Limiting factor: some engineering details of the full implementation and annotation process remain outside the paper. Would raise: released reference implementation with golden tests and end-to-end reproduction scripts.

Strengths

  • Separates structural correctness from mere compression and measures both.
  • Uses reversible source expansion instead of treating compression as irreversible summarization.
  • Explicitly models verifier reachability, a key execution-safety concept that many retrieval papers omit.
  • Ablations align well with the claimed causal components: section granularity, contract checks, closure, verifiers, and adaptive hydration.
  • Cost accounting distinguishes cached structural construction, online retrieval/rendering, and full multi-turn execution.
  • Repeated-run paired statistics and cross-backbone results reduce concern that the gains are single-run or single-model artifacts.

Limitations / red flags

  • The system depends on LLM-assisted contract extraction; its weakest field is implicit preconditions/guards, precisely where hidden execution obligations can matter most.
  • The core proposition is structural lifting, not semantic program equivalence. A preserved verifier path does not prove the verifier is sufficient or correct.
  • The 100K scaling experiment measures deterministic graph construction from cached section records, not end-to-end ingestion of 100K skills including LLM extraction.
  • Streaming contract drift and procedural-overlap studies are controlled constructions. They demonstrate mechanism behavior, not natural production distributions.
  • Real-world security concerns—malicious skills, permission boundaries, unsafe tool side effects, provenance trust, and governance across authors—are not directly validated by these experiments.
  • Case studies are explicitly illustrative constructions rather than additional quantitative samples.

Implementation takeaways

1. Choose the right atomic unitIf a skill document contains multiple independent operations/verifiers, retrieval should operate below the package level. Preserve occurrence identity even when canonicalizing reusable prototypes.
2. Make contracts first-classCompression candidates should expose typed inputs/outputs, resource requirements, guards, failure behavior, and verifier hooks. Surface similarity should only be a secondary signal after structural compatibility.
3. Separate hard validity from optimizationReject motifs that violate boundary clarity, signature stability, dependency closure, or verifier reachability before considering compression gain.
4. Preserve reversible provenanceEvery abstraction should retain occurrence-specific source/port maps so a compact macro can be expanded back to the exact source sections.
5. Treat context as a compiled artifactRetrieve anchors, connect them, repair dependencies/verifiers, then render the smallest sufficient view. Do not simply concatenate top-k snippets or greedily spend the entire budget.
6. Instrument recoveryLog late expansion, fallback, verifier failure, repair cost, and hydration level. A macro that repeatedly needs expansion is evidence that the abstraction is too coarse or unsafe for that task family.
7. Keep structural and sufficiency validation distinctGraph validity (ports/closure/reachability) is not the same as task sufficiency. The runtime compiler still needs to verify that the selected subgraph covers task anchors and required roles.
8. Benchmark the full lifecycleMeasure active representation size, source storage, construction time, retrieval latency, rendered context, downstream tool calls, verifier failures, and trajectory tokens separately.
Build-useful abstraction. The strongest reusable pattern is not “compress skills with graphs.” It is: make source-grounded procedural contracts explicit, abstract only contract-equivalent recurring subgraphs, and retain reversible expansion plus runtime sufficiency checks.
