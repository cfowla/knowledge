One-page synthesis

Verdict: Skim deeply. The full paper is stronger than the task-queue briefing. It has a real end-to-end A100 speed result and enough kernel detail to be useful. The result is still narrow. Treat it as a design and benchmarking reference for inference-serving work, not as evidence that mixed precision broadly improves long-context model quality.

TileMix changes where low precision is used inside dense attention. The kernel keeps every legal token interaction, partitions the score matrix into hardware-aligned tiles, and routes groups of key tiles through either FP16 or INT8 score computation. A compact 64-bit mask drives constant-time route lookup inside the streaming attention loop. Both arithmetic paths feed one online-softmax state, so precision can vary spatially without turning the method into sparse attention.

The strongest systems result is Table 2. At 4k-token prefill on LLaMA 3.2 3B-Instruct, batch size 8, SpTrans75 reaches 31.80 K tokens/s versus 14.33 K tokens/s for FlashAttention and 29.80 K tokens/s for the matched all-INT8 One path. That is a calculated 2.219-fold throughput relative to FlashAttention and about 6.7% above One for that setting. The timing includes quantization, scale restoration, routing, staging, and scheduling. This matters because it is not an isolated Tensor Core microbenchmark.

Quality is more complicated. Uniform INT8 often loses accuracy on LongEval and LV-Eval, and mixed routing often recovers part of the loss. The best layout depends on task, model, context length, and INT8 coverage. The large SpTrans gains on 16k factual recall are especially odd. LLaMA 3.2 3B reports 21.65 for SpTrans75 versus 6.72 for FP16. Appendix results show the same kind of jump on Qwen. The authors call this a recurring layout-task interaction. Without a mechanism or independent replication, the result should stay in the evidence record but should not be read as a general accuracy benefit.

Section condensation

Abstract

The paper frames long-context prefill as a dense-attention compute and memory problem. TileMix makes precision a spatial routing decision over score-tile groups inside a fused dense-attention kernel. It uses FP16 and INT8 score paths, keeps dense legal connectivity, requires no training, and supports grouped-query attention, variable-length batches, and an INT8 KV-cache interface.

The abstract claims quality recovery relative to uniform INT8 and higher prefill throughput than FP16 across LongEval, LV-Eval, and A100 benchmarks on LLaMA, Qwen, and Vicuna. The source also links a public implementation.

Introduction

The authors separate three existing efficiency directions: low-precision quantization, sparse attention, and IO-aware fused attention. Their stated gap is spatial precision routing inside a fused dense-attention loop. TileMix keeps the attention graph dense and changes the arithmetic used for selected score tiles.

The engineering difficulty is shared state. FP16 and INT8 score paths have different rounding, accumulation, and rescaling behavior, yet both must update the same running maximum, normalizer, and output accumulator. The paper treats this as a kernel design problem rather than a model-training method.

Related work

The paper positions TileMix next to quantized attention, sparse long-context attention, and FlashAttention-style fused kernels. Sparse layouts such as BigBird and Sparse Transformer appear again as precision-routing templates. Their spatial patterns select which groups stay in FP16 rather than which interactions are removed.

The related-work section supports the design motivation. It does not, by itself, establish that TileMix is the first possible implementation of mixed precision inside fused attention. The novelty score in this appraisal therefore remains source-grounded rather than an exhaustive patent or code-prior-art claim.

Preliminaries

The kernel uses tiled attention and online softmax so it never needs to materialize the full L by L score matrix. On A100, the low-precision path uses INT8 Tensor Core MMA with INT32 accumulation, followed by scale restoration.

Because every score tile contributes to one shared softmax state, path-specific numerical errors can propagate across later normalization and output accumulation. The paper later measures this directly rather than assuming FP16 and INT8 routes are numerically interchangeable.

TileMix method

Each query-tile row streams key and value tiles. A routing group can control one or several adjacent key tiles. For each KV head and query-tile row, the policy packs up to 64 binary route decisions into one word. A shift-and-mask selects INT8 or FP16 for the current group. Legality masks remain separate, so routing does not remove legal attention edges.

The main configuration uses blockwise symmetric INT8 quantization for Q and K with 128-token query blocks and 64-token key blocks. V and PV stay FP16 in the primary path. The quantize-once mode materializes Q8, K8, and scales once per attention call, while the appendix also describes an on-the-fly mode. Static data-free templates set the evaluated routing policy.

Experiments

Evaluation covers LongEval exact-match line retrieval, 11 English and Chinese LV-Eval tasks, prefill throughput and TOPS, and numerical deviation from a Torch FP16 reference. The main model is LLaMA 3.2 3B. Appendices add Qwen2 7B, Qwen2.5 7B, and Vicuna 7B. Baselines include FP16, the matched all-INT8 One path, FlashAttention, sparse long-context methods, and SageAttention.

All implementation measurements use A100 40GB GPUs. Throughput uses batch size 8, three warmups, and five timed iterations under the same wrapper. The reported timing includes quantization and route overhead. Quality results show that mixed routing often recovers accuracy lost under uniform INT8, but policy ranking changes across tasks. Numerical deviation generally rises as INT8 coverage increases.

Conclusion and limitations

The authors conclude that tile-group precision routing provides an accuracy-efficiency control inside dense attention. Their implementation supports FP16/INT8 score routing, grouped-query attention, variable-length batches, and an INT8 KV-cache interface.

The stated scope is forward inference during long-context prefill on A100. Other numerical formats need separate scale and scheduling support. The evaluated policies are static. The kernel interface can accept adaptive policies, but the paper does not test them.

Implementation takeaways

Precision can be routed without sparsity

Keep legality and arithmetic choice as separate masks. This preserves dense token connectivity while allowing heterogeneous score computation.

Pack route metadata aggressively

One 64-bit word per KV head and query-tile row gives constant-time inner-loop lookup. Group adjacent key tiles when long contexts would otherwise exceed 64 decisions.

Benchmark the full path

Quantization, rescaling, memory staging, route lookup, and scheduling can erase theoretical INT8 gains. TileMix includes these costs in its throughput numbers.

Track memory separately from bandwidth

Quantize-once increases resident HBM but reduces INT8 operand reads. The on-the-fly mode preserves the FlashAttention-like resident footprint while doing more conversion work per tile.

Treat routing layout as a quality variable

INT8 coverage is not enough to predict quality. FP16 placement changes LongEval and LV-Eval behavior, so policy evaluation belongs in the deployment test matrix.

Measure numerical error by coverage and depth

The appendix shows that routed-precision error depends on more than sequence length. Coverage, layout, and model depth deserve explicit numerical checks.
