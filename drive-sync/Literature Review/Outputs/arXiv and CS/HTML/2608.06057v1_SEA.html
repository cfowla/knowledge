One-page synthesis

Verdict: Read first. The paper isolates a practically important failure mode—non-authoritative but plausible history redirecting an otherwise available tool-use policy—and tests a concrete training approach that substantially improves robustness. The strongest use is as a design and evaluation reference for agent state management and reliability training, not as proof of production readiness.

Core thesis

Tool-using language models can be policy-hijacked by history: an old failed call, a competing entity, a stale parameter convention, or a success-looking but non-authoritative trace can cause the model to reuse the wrong state even when the current request, available tools, and correct next action are unchanged. ContextPollute-Bench makes that phenomenon directly measurable by synchronizing three views of the same decision point: Original history, Polluted history, and an Oracle State containing only decision-relevant reliable information.

The proposed remedy, Oracle-guided On-Policy Distillation (Oracle-OPD), trains a student on polluted history while a frozen teacher sees Oracle State and provides token-level reverse-KL supervision on prefixes generated by the student itself. At deployment, the Oracle State and teacher are removed. The 1.7B student reaches 0.8703 balanced tool-use accuracy (BTA), versus 0.6628 for Gold-SFT and 0.8499 for off-policy distillation; using an 8B teacher raises the same 1.7B student to 0.9193 BTA.

Why the result matters

The key conceptual move is to distinguish task policy failure from state-selection failure. A model may know how to call the correct tool under a clean or Oracle state yet still fail when stale history provides a plausible competing state. The paired design makes that distinction much clearer than aggregate function-calling benchmarks.

Main caution. BTA balances complete correct calls against not calling on gold-Answer examples. Its non-call component does not, by itself, establish that the generated clarification or answer is substantively correct or useful. This makes BTA a strong call-control metric but an incomplete measure of response quality.

Methodology

Problem formulation

At each decision point, the agent sees a system policy, available tools, interaction history, and latest user request and must either answer or emit a tool call with complete arguments. The benchmark holds system policy, current tools, latest request, and gold next action fixed across synchronized views. Only the historical representation changes.

TCR = P(complete correct tool call | gold = CALL)
OCR = P(predicted CALL | gold = ANSWER)
BTA = 0.5 × TCR + 0.5 × (1 − OCR)

TCR = ToolAccuracy × ArgumentExactMatch (conditional on correct tool)

This makes TCR stringent: both tool identity and the full argument object must be correct. BTA then gives equal weight to correct calling and restraint from over-calling.

ContextPollute-Bench

The benchmark is derived from airline and retail APIGen-MT trajectories. Each retained decision point has an untouched Original history, a Polluted history with one misleading but gold-preserving historical trace, and an Oracle State view containing only reliable intent, slots, observations, policy, missing information, and evidence status. Eleven operators cover three families: Decision-State, Entity-Binding, and Interface-Execution interference.

Call examples retain a source tool call as the gold action. Answer examples retain substantive non-tool responses categorized as Clarify, Answer-from-Evidence, or Unsupported. Construction includes deterministic structural validation, operator-specific checks, trajectory-level split isolation, a semantic preservation gate for Answer examples, and Oracle non-leakage/recoverability checks.

Oracle-guided On-Policy Distillation

The teacher sees Oracle State; the student sees Polluted history. The student first generates a rollout. At each student-generated prefix, the student distribution under Polluted context and teacher distribution under Oracle context are compared with token-level reverse KL. The objective uses the union of teacher and student top-16 token supports, temperature 1, four student rollouts per prompt, and no additional gold cross-entropy term.

Student rollout: y ~ πθ(· | polluted)
qS_t = πθ(· | polluted, y<t)
qT_t = πT(· | oracle, y<t)
L_OPD = E[ (1/|y|) Σ_t KL(qS_t || qT_t) ]

The intended mechanism has three separable parts: reliable teacher conditioning, distributional rather than sequence-only transfer, and coverage of states the student actually visits. Table 6 directly tests those components.

Results

History pollution causes paired failures

For Qwen3-1.7B, 32.1% of examples that are correct under Original history become wrong under the paired Polluted view; the flip rate is 29.4% for Call decisions and 40.5% for Answer decisions. Relative to Oracle-correct predictions, the corresponding rates are 40.8%, 37.5%, and 50.8%. These paired flips are the paper’s strongest evidence that pollution redirects an available policy rather than merely exposing generally difficult tasks.

Literal-adoption analysis supports a specific mechanism: under Polluted input the base model adopts injected corrupted literals in 34.8% of same-tool/different-target examples, 20.9% of entity-interleaving examples, and 65.8% of format-drift examples. After Oracle-OPD, adoption on the two entity-binding operators falls to 1.0% and 0.4%.

Main post-training comparison

Oracle-OPD is the strongest same-size 1.7B method on Test-Indist: BTA 0.8703, TCR 0.9132, non-call recall 0.8273, decision accuracy 0.9473, and tool accuracy 0.9824. The BTA advantage over off-policy distillation is +0.0204 with a paired-bootstrap 95% CI of +0.0118 to +0.0295 and reported p<10−4.

Gold-SFT and related hard-target variants learn a highly restrained regime: non-call recall approaches 1.0, but TCR collapses. CALL-only SFT has the opposite problem. Oracle-OPD occupies a more balanced region, indicating that reliable-state soft supervision transfers both execution and call-control behavior.

Transfer and robustness

The exact frozen checkpoints retain most of their performance when reevaluated on Original rather than Polluted histories. The 1.7B Oracle-OPD model scores 0.8703 BTA on Polluted and 0.8450 on Original; OOD TCR is essentially unchanged at 0.7433 versus 0.7450. This argues against a narrow “detect the injected error” correction rule.

Operator-level gains are broad: Oracle-OPD is best or tied on seven of eight Call-side operators, with the largest practical gains on unit/scale drift and entity binding. The method also transfers to Claude-Opus-4.7-regenerated contexts, BFCL, When2Call, and noisy HotpotQA context.

Appendix & reproducibility evidence

The appendices are unusually important to appraisal because they specify benchmark construction, validation, audits, training configuration, execution environment, and transfer evaluations.

Appendix A — Benchmark construction (Tables 9–13)

Five-stage pipeline: trajectory-level split assignment; Call/Answer decision extraction plus pollution generation; standalone structural validation; Oracle State generation/recoverability checks; final split routing. The final record contains original_context, polluted_context, oracle_state_view, current_tools, latest request, gold action, sample kind/subtype, pollution metadata, provenance, and Oracle metadata.

Eight Call-side operators: same tool/other target; entity interleaving; wrong parameter name + error; legacy parameter + apparent success; missing required field; extra parameter; format drift; unit/scale drift. Three Answer-side Decision-State operators cover unsupported completion, decision-irrelevant evidence, and unavailable historical capability. Acceptance validators require the intervention to instantiate the intended distractor while preserving the original source messages and gold next action.

Answer preservation gate: an independent zero-temperature auditor sees Polluted context and current tools and must return NO_CALL with no newly supplied missing items. Oracle checks: reject literal gold-tool leakage, unsupported evidence, and insufficient decision state.

Evaluation & appraisal

Relevance9/10

Directly addresses reliability of tool-using agents under persistent multi-turn state.

Evidence basis
Paired intervention benchmark, tool-call control, state reliability, transfer tests.
Principal limit
Evaluated domains are airline/retail rather than production agent workloads.
What would change the score
Natural production traces and end-to-end task studies would raise confidence.
Novelty8/10

The synchronized Original/Polluted/Oracle design isolates a failure mode that broader tool benchmarks confound.

Evidence basis
Gold-preserving interventions plus Oracle-conditioned on-policy distillation.
Principal limit
Builds on established privileged-information and on-policy distillation ideas.
What would change the score
Independent replication and naturally occurring history-corruption datasets would strengthen novelty.
Method strength8/10

Strong controlled design, trajectory-level splits, audits, ablations, cross-generator evaluation, and bootstrap uncertainty.

Evidence basis
11 operators; 200-item adjudicated audit; 1,000-item cross-audit; held-out gold tools; external benchmarks.
Principal limit
Synthetic pollution and generated Oracle States remain construction dependencies; answer quality is not directly captured by BTA.
What would change the score
Production-history validation and richer answer-quality scoring would raise the score.
Evidence strength8/10

The central causal claim is supported by paired within-example flips and literal-adoption analyses, not only aggregate accuracy.

Evidence basis

Strengths

  • Controlled causal framing: synchronized views keep the current decision fixed, allowing history reliability to be isolated from task variation.
  • Attribution beyond aggregate accuracy: paired flips and corrupted-literal adoption identify how the historical trace redirects behavior.
  • Broad method factorization: Oracle conditioning, soft targets, and student-state coverage are individually tested rather than presented as an inseparable package.
  • Validation effort: deterministic construction checks, a 200-example adjudicated audit, a 1,000-example cross-audit, cross-generator contexts, held-out gold functions, and external benchmarks reduce several obvious benchmark-artifact concerns.
  • Deployment economics are explicit: training is heavier, but the Oracle and teacher disappear at inference; a stronger teacher can improve a smaller deployed student.

Limitations and interpretation boundaries

  • Synthetic core setting: history pollution is generated under controlled operators in two transactional domains. Natural production histories may contain correlated, ambiguous, or state-changing errors that violate the gold-preserving assumption.
  • Next-action focus: the benchmark evaluates a single next decision rather than long-horizon recovery, tool-result evolution, cascading failures, or user correction over an entire episode.
  • BTA does not score answer content: 1−OCR rewards not calling on Answer examples; it does not itself establish that the produced clarification/answer is correct, complete, or safe.
  • Oracle construction is privileged: Oracle States are generated using source information and the gold action during construction, then checked for leakage. This is a legitimate training-time privileged-information design, but obtaining equally reliable state summaries at scale is an implementation dependency.
  • Generalization remains bounded: external BFCL/When2Call/HotpotQA results and Claude-regenerated contexts are useful evidence, but the principal models and domains remain limited. OOD-600 holds out six gold functions with related same-family interfaces, not an unrelated tool family.
  • Reproducibility not independently verified here: the paper describes submitted code, launchers, data splits, prompts, manifests, and environment files, but only the paper itself was supplied for this appraisal.
Bottom line. The diagnosis is convincing enough to treat “which historical state is authoritative?” as a distinct agent-reliability target. The training result is strong benchmark evidence that privileged reliable-state supervision can transfer that behavior into ordinary-history deployment. The next evidentiary step is natural production history, end-to-end task execution, and answer-quality evaluation—not another synthetic operator expansion alone.

Implementation takeaways

Build authoritative state separately from transcript. Maintain typed current intent, entity bindings, validated observations, active tool schemas, and evidence status as first-class state rather than forcing the model to infer authority from raw chronology.
Preserve provenance and state validity. Mark whether observations are current, failed, stale, superseded, or non-state-changing. The paper’s failure examples arise precisely when plausible history remains visible without authority metadata.
Test paired history perturbations. Reliability evaluation should include same-request/same-gold pairs where only irrelevant or misleading history changes. Aggregate tool accuracy alone can hide this failure mode.
Separate call execution from call control. Track complete-call recall, over-calling, tool identity, and argument exactness independently. A model can look “safe” by refusing to call or “capable” by calling too often.
Use privileged state for training, not necessarily deployment. If a trusted state reconstruction can be built offline, it can supervise a model that later consumes normal interaction history. This is the practical attraction of Oracle-OPD.
Do not equate history pollution with prompt injection. The paper targets plausible but non-authoritative traces, not malicious instruction injection. The defenses and threat models overlap only partially.

What not to overclaim

This work does not show that Oracle-OPD solves arbitrary long-context reliability, adversarial prompt injection, production tool safety, or end-to-end agent correctness. It shows a specific and important result: when the current decision is held fixed, misleading historical state can redirect tool-use behavior, and training against an authoritative state representation materially reduces that vulnerability in the tested settings.
