One-page synthesis

Core thesis. Memory substrate choice is regime dependent. Broad retrieval helps long-context factual QA, while sequential decision tasks often benefit from more selective or distilled memory. History length adds another routing constraint because quality and latency scale differently across substrate families.

The paper builds a common harness intended to isolate the memory substrate while holding backbone, prompting, benchmark history, and auxiliary-LLM choices fixed. It spans external flat indices, text records, structural and hierarchical stores, refinement memories, and internal weight or activation mechanisms. The evaluation is unusually broad for this topic because it reports both task quality and operational cost rather than accuracy alone.

The central empirical result is not a new universal winner. M5 Dual-Level Graph is strong on long-dialogue QA, M7 Distilled Strategies leads one ALFWorld setting, and cheap M2 BM25 is competitive or preferable when latency matters, especially on code generation. Retrieval-depth sweeps and an attention probe give a mechanistic explanation: more retrieved content shifts attention from current task context into retrieved memory. That helps when retrieved content contains the answer, but can harm planning when the current observation and admissible actions are more important.

Best use. Treat this as an engineering map for selecting and benchmarking memory substrates, and as evidence that memory routing should consider task regime, retrieval breadth, and history depth.
Main caution. The preprint relies mainly on benchmark point estimates. Main tables do not report confidence intervals or significance tests, reference implementations were modified for M8 and M11, and the main comparison excludes MemGPT, Mem0, and Zep.

Section condensation

Abstract

The authors frame memory as infrastructure for long-horizon agents and ask which underlying substrate should be used under different operating regimes. They evaluate external and internal memory mechanisms under one harness and track both performance and efficiency.

They report regime reversals rather than one dominant method: wider retrieval improves factual QA but can degrade sequential decision-making, and long histories change the cost-quality frontier.

1 Introduction

A 52-system landscape survey motivates the study. The authors find heavy concentration on LoCoMo and LongMemEval, limited efficiency measurement, and strong dependence on GPT-family backbones, which makes existing leaderboards a weak basis for substrate selection.

The contribution is a controlled cross-regime harness with 11 methods and 26 metrics, followed by performance-latency, retrieval-depth, attention, and scalability analyses.

2 Memory Substrates and Configuration

The design space is organized into seven families. External memory includes flat dense/sparse retrieval, gist records, linked notes and graphs, hierarchical trees, and refinement memories. Internal memory includes weight adaptation and activation-based history mechanisms.

Zep, Mem0, and MemGPT are not part of the main controlled table because their production pipelines consume substantially different auxiliary-LLM budgets. Their costs are reported separately.

3 Experiment Design

User-centric evaluation uses LoCoMo and MemoryAgentBench capabilities; agent-centric evaluation uses 134 ALFWorld valid-unseen tasks and 148 BigCodeBench-Hard tasks. Three backbones run through vLLM on four H200 GPUs, with gpt-4o-mini fixed for auxiliary operations and judging.

Ablations sweep retrieval breadth on LoCoMo and ALFWorld and sweep MAB Conflict Resolution history length across 6K, 32K, and 262K tokens. M7, M9, and M10 have design-specific exclusions in some benchmark/model combinations.

4.1 User-centric results

M5 Dual-Level Graph leads LoCoMo and LongMemEval-S across the model bands in the main table, but other capabilities favor different mechanisms. M10 leads Qwen3-8B on MAB LRU, M3 leads Qwen3-32B on LRU and TTL, and M5 is strong on Conflict Resolution.

Cost is decisive. M2 remains inexpensive while structural mechanisms can be tens of times slower. The results support per-capability selection rather than a single memory architecture.

4.2 Agent-centric results

ALFWorld favors mechanisms that suppress irrelevant prior experience. M11 reaches 11.9% task success on Qwen3-8B versus 5.7% for NoMem, and M7 reaches 32.1% on Qwen3-32B versus 22.4% for NoMem.

BigCodeBench-Hard behaves differently: retrieved code can extend the prompt with reusable scaffolding. M5 reaches 20.9% Pass@1 on Gemma, but M2 reaches 19.6% on Qwen3-32B while M5 reaches 16.2%, with much lower latency.

5 Discussion

The performance-latency frontier differs by regime. QA favors structural or hierarchical memory, whereas the agentic frontier includes cheap flat retrieval for code and refinement-based strategy memory for embodied planning.

Increasing top-k raises LoCoMo quality but lowers ALFWorld task success. The attention probe shows why: higher k moves attention toward retrieved memory on both tasks, but the useful information resides in different prompt regions.

5.3 Scalability

On MAB Conflict Resolution, M8 rises from P4 0.32 to 0.51 as history grows to 262K tokens while latency grows from roughly 1 to 10 seconds. M5 rises from 0.28 to 0.48 but becomes costly because graph construction scales with input.

M10 improves from 0.27 to 0.47 but pays linear read cost. M9 remains near 0.18 to 0.22. History depth therefore changes the preferred substrate even within one capability.

6 Related Work and 7 Conclusion

The paper positions its contribution between memory-system design and memory benchmarking, with emphasis on testing the same substrate set across dialogue and agentic regimes.

The authors conclude that routing across heterogeneous substrates is necessary and suggest shifting work from broad read-time retrieval toward stronger write-time distillation or structuring when the task benefits from concise memory.

Strengths

  • Controls the surrounding harness so substrate differences are easier to interpret.
  • Crosses user-centric QA and agent-centric decision regimes instead of staying inside one benchmark family.
  • Measures operational cost as first-class evidence rather than an afterthought.
  • Uses top-k, attention, and history-length analyses to explain why rankings reverse.
  • Documents implementation deviations and excluded production systems instead of hiding them.

Limitations and failure risks

  • Main benchmark comparisons are reported largely as point estimates without uncertainty intervals or formal significance tests.
  • M8 and M11 are not exact replications of the cited reference implementations.
  • MemGPT, Mem0, and Zep are excluded from the main ranking, so the study should not be read as a complete production-stack comparison.
  • The attention probe is narrower than the full benchmark study and should be treated as a plausible mechanism, not definitive causal proof.
  • The paper is an arXiv v1 preprint, and code is described as forthcoming rather than currently available.

Implementation takeaways

Route by task regimeDo not select a memory substrate from aggregate accuracy. Separate factual recall, conflict/update handling, sequential planning, and code reuse because they reward different retrieval behavior.
Treat top-k as a policyRetrieval breadth should be conditioned on whether useful evidence is expected to live in memory or in the current task context. More retrieval is not automatically safer.
Measure write and management costTrack auxiliary calls, tokens, storage, write latency, retrieval latency, and management overhead in addition to end-task quality.
Re-test as histories growA substrate that is acceptable at 6K or 32K history may become too slow or brittle at 262K. Include history-length stress tests in memory benchmarks.
Prefer per-substrate routingFamily labels are too coarse. Two methods in the same family can occupy very different quality-latency positions.
Keep production claims separateUse the production-system cost appendix as context. Do not infer that lighter paper-faithful approximations fully reproduce Mem0, Zep, or MemGPT behavior.
