One-page synthesis

Verdict: Read first. The paper is unusually build-useful for dynamic RAG / document-agent work because it converts retrieval history into an explicit probabilistic state rather than merely accumulating context. The strongest contribution is not “memory” in the generic sense, but the coupling of page-level Bayesian relevance beliefs, uncertainty-aware sampling, query-local episodic notes, and document-structural priors into a retrieval-control loop.

Core thesis. Static top-k retrieval is fragile when evidence is sparse and multi-page; iterative retrieval helps but remains weak if each round behaves almost independently. DocMemo reframes long-document QA as stateful evidence exploration. It maintains three memory layers: Document Schema Memory for persistent structural priors, Page Belief Memory for evolving page relevance, and Question Episodic Memory for query-specific findings, gaps, and rewritten queries. The retrieval policy then combines current visual similarity with sampled page relevance beliefs, uses reasoner feedback to update those beliefs, propagates positive evidence to nearby pages, and adds high-resolution local crops when page-level views are insufficient.

What the source reports. With Qwen3.5-9B and ColQwen2.5, DocMemo reports 71.3% accuracy on MMLongBench-Doc, 81.1% on LongDocURL, and 80.4% on PaperTab. In a same-backbone / same-retriever comparison on MMLongBench-Doc, it reaches 71.3% versus 69.3% for SimpleDoc. Ablations lower overall MMLongBench accuracy to 68.8% without Page Belief Memory or Bayesian updating, 68.5% without all memory modules, and 69.9% without adaptive granularity. Evidence Recall rises from 28.32% in round 1 to 69.56% in round 3; All-Hit Rate rises from 12.90% to 58.05%.

Best-supported value
Dynamic cross-round page state improves evidence recovery, especially when early retrieval misses key pages. The controlled comparison and ablations support this mechanism better than leaderboard-only comparisons do.
Main caution
The strongest claims remain benchmark-bound. Main result tables do not consistently provide uncertainty, several baseline values come from different protocols/sources, and hyperparameter sensitivity is reported on the full MMLongBench test set, leaving the independence of model selection from final evaluation unclear.

Section condensation

Abstract and Introduction

The paper frames long-document DocVQA as an evidence-budget problem: documents may span dozens to hundreds of pages, while the answer depends on sparse text, tables, figures, or layouts. Static retrieval fixes a candidate page set too early; iterative systems can retrieve multiple times but often preserve state through context reconstruction rather than an explicit cross-round retrieval state.

DocMemo’s proposed remedy is a persistent tri-level memory plus probabilistic page selection. The claimed contribution is specifically the transformation of reasoning feedback into page-level retrieval control through Bayesian belief updates, Thompson sampling, locality-aware propagation, and fine-grained visual access.

2. Related Work

The paper distinguishes static retrieval-augmented document understanding from iterative retrieval. Static methods improve candidate recall through multimodal indexing, structure, and cross-page modeling but generally fix retrieval before reasoning. SimpleDoc is presented as the closest iterative baseline, with repeated retrieval but without an explicit state-propagation mechanism.

The memory discussion places DocMemo against general LLM-agent memory systems that store, compress, and reuse historical information. DocMemo narrows the problem to structured multimodal documents and treats page relevance itself as a mutable memory state rather than only storing semantic summaries or interaction history.

3. Method

For a document of N pages and query q, DocMemo runs up to T retrieval–reasoning rounds. Offline, it creates page visual embeddings, page summaries, and a document schema. Online, it maintains Document Schema Memory, Page Belief Memory, and Question Episodic Memory. Page beliefs are Beta distributions initialized from normalized ColQwen2.5 visual relevance with prior strength S; reasoner-labeled useful pages increase α and irrelevant pages increase β.

Positive feedback is propagated to neighboring pages with radius r and distance decay γ. At each round, relevance is sampled from each Beta posterior and fused with current visual similarity using a round-dependent weight λ. An LLM reranks candidates using page summaries plus schema and episodic memory; a VLM reasons over accumulated evidence and can answer, return not_answerable, or produce a refined query plus notes. Dense pages may receive high-resolution local crops for fine-grained reading.

4. Experiments

Evaluation covers MMLongBench-Doc (1,082 questions / 135 documents), LongDocURL (2,325 QA pairs / 396 PDFs), and PaperTab (393 questions / 307 papers). Accuracy is judged automatically by GPT-4.1; the paper also reports Evidence Recall and All-Hit Rate for retrieval behavior. The implementation uses Qwen3.5-9B as the main backbone, ColQwen2.5-v0.2 for visual retrieval, vLLM serving, MinerU for table/figure crops, and a maximum of three retrieval–reasoning cycles.

The main results favor DocMemo across all three benchmarks, with particularly large PaperTab gains. Controlled MMLongBench comparisons under the same model/retriever configuration show smaller but still positive gains. Ablations identify Page Belief Memory, Bayesian updates, Thompson sampling, and adaptive-granularity crops as useful. Iteration analysis shows most recovery occurs by round 2, and a qualitative example demonstrates how query rewriting and page beliefs eventually surface a missed chart page.

5. Conclusion

The authors conclude that structured memory and continuously updated page relevance are more effective than static or stateless iterative retrieval for long-document DocVQA. The source positions DocMemo as a retrieval-control architecture in which persistent structure, dynamic beliefs, and query-local traces jointly shape evidence discovery.

The conclusion is supported for the evaluated benchmark setting. It should not be generalized to broader agent memory, arbitrary long-context tasks, or production deployment without further validation.

Appendix A–C

The appendix materially strengthens reproducibility by publishing hyperparameters, prompt fragments, efficiency/cost data, additional ablations, modality tests, and a direct Thompson-sampling-versus-greedy comparison. The full system uses S=5, λ=[0.0, 0.3, 0.6, 0.6], r=2, γ=0.5, candidate pool 30, reranked pages ≤13, reasoning pages ≤9, and up to five table crops per query.

Additional results show 1.24 average iterations per question, 20.41 s mean VLM latency per call, 33.95 GB peak VRAM, and 96.7% human/GPT-4.1 agreement (κ=0.92) on 300 sampled judgments. The appendix also reports large degradation under OCR-only input and a 2.66-point drop when Thompson sampling is replaced by greedy posterior-mean selection.

Method architecture

Tri-level document memory

1. Document Schema Memory (offline, query-independent)
   • document type/topic
   • section/page-range structure
   • global summary

2. Page Belief Memory (online, query-specific state)
   • per-page Beta(α, β) relevance distribution
   • initialized from visual similarity
   • updated from reasoner useful/irrelevant page labels
   • positive feedback propagated to nearby pages

3. Question Episodic Memory (online, per-question)
   • intermediate evidence summary
   • missing-information analysis
   • refined-query history

Retrieval–reasoning–memory loop

query / refined query
→ visual page relevance
→ sample θᵢ ~ Beta(αᵢ, βᵢ)
→ scoreᵢ = (1 − λₜ)cᵢ + λₜθᵢ
→ candidate pages
→ LLM reranking using schema + episodic memory
→ accumulated evidence set
→ VLM reasoner (+ local crops when useful)
   ├─ answer
   ├─ not_answerable
   └─ refined query + notes + useful_pages + irrelevant_pages
→ Bayesian page-belief update
→ spatial positive-feedback propagation
→ next round (max 3)

Page-belief equations

Initial prior:
αᵢ⁽⁰⁾ = S cᵢ + 1
βᵢ⁽⁰⁾ = S(1 − cᵢ) + 1

Reasoner feedback:
αᵢ ← αᵢ + I[i ∈ useful_pages]
βᵢ ← βᵢ + I[i ∈ irrelevant_pages]

Posterior mean:
μᵢ = αᵢ / (αᵢ + βᵢ)

Spatial propagation for useful page i:
αⱼ ← αⱼ + γ^|j−i|,  0 < |j−i| ≤ r

Listing 1 — Document Schema Memory prompt

Produces doc_type, page-ranged doc_structure, and a 4–6 sentence doc_summary. This makes the structural prior explicit and query-independent.

Listing 2 — Local structure extraction

For long documents, page-summary segments are grouped into thematic page ranges before being merged into the global schema. The prompt explicitly prohibits speculation outside the provided range.

Listing 3 — Page-level feedback

The reasoner emits useful_pages and irrelevant_pages, which become direct positive and negative Bayesian update signals.

Listing 4 — Query update and episodic notes

When evidence is incomplete, the reasoner emits a query that preserves original intent while adding retrieval cues, plus notes describing evidence already found and what remains missing.

Listing 5 — Anti-loop constraint

The prompt forces the reasoner to check whether requested pages or visual elements are already present, reducing repeated retrieval of the same evidence.

Listing 6 — Adaptive-granularity evidence access

The reasoner is told to jointly analyze page images, extracted text, and optional high-resolution table crops. This preserves global page context while restoring local numeric detail.

Evaluation and appraisal

9/10
Relevance

High relevance to agentic RAG, long-document retrieval, explicit state management, and memory-guided evidence discovery.

Limiting factor: narrow task family: long-document DocVQA.

Would rise: validation on broader text-only, web, code, or scientific synthesis agents.

8/10
Novelty

The individual ingredients are known, but the combination of tri-level memory, Beta page beliefs, Thompson sampling, spatial propagation, and query-local traces is a meaningful systems contribution.

Limiting factor: much of the pipeline builds on established retriever/reranker/VLM components.

Would rise: stronger theoretical treatment or evidence that the state representation transfers across tasks.

7.5/10
Method strength

Three benchmarks, controlled same-config comparisons, extensive ablations, cost analysis, and human verification of the judge are substantial strengths.

Limiting factor: main tables lack consistent uncertainty; some baselines are imported; hyperparameter test-set independence is unclear.

Would rise: locked dev/test tuning, repeated-run confidence intervals for all primary comparisons, and stronger independent replication.

7.5/10
Evidence strength

The core mechanism is supported by consistent accuracy gains, retrieval-recall improvements, and targeted component ablations.

Limiting factor: benchmark-only evidence and automatic judging remain indirect proxies for real-world reliability.

Would rise: externally replicated results, user-facing task success, and failure-stratified analysis.

6.5/10
External validity

Three datasets span text, layout, charts, tables, figures, numerical reasoning, and unanswerable cases, which is better than a single benchmark.

Limiting factor: all are long-document QA benchmarks; no enterprise document collections, noisy scanned corpora, or deployment study.

Would rise: evaluation across organizations, document types, languages, and operational environments.

9/10
Implementation value

The paper discloses equations, prompt fragments, hyperparameters, page budgets, costs, latency, storage, and a code repository, making it unusually actionable.

Limiting factor: this appraisal did not independently verify repository completeness or reproducibility.

Would rise: audited code, packaged reproducibility scripts, and end-to-end deployment documentation.

Strengths

  • Mechanism aligned to the failure mode: the design directly addresses early retrieval misses and cross-round state loss instead of merely enlarging the context window.
  • Controlled comparison exists: Table 2 separates method effects from backbone/retriever differences better than leaderboard comparisons.
  • Ablation depth is above average: memory layers, Bayesian update, Thompson sampling, visual granularity, modality, and selection strategy are tested.
  • Retrieval behavior is measured: Evidence Recall and All-Hit Rate reveal whether the system is actually finding missing evidence, not only producing better answers.
  • Judge reliability is checked: human review of 300 examples yields 96.7% agreement and κ=0.92 with GPT-4.1.
  • Implementation details are unusually concrete: prompts, page budgets, retrieval rounds, visual crop limits, tokens, latency, memory, and preprocessing cost are disclosed.

Limitations and unresolved questions

  • Preprint status: peer review and independent replication are not yet available from the source itself.
  • Primary-result uncertainty is sparse: confidence intervals or repeated-run variability are absent from the main benchmark tables, even though ± values appear in appendix ablations.
  • Baseline comparability varies: some main-table baselines are taken from official leaderboards or respective papers; Table 2 is therefore more probative than Tables 1 or 3 for direct causal comparison.
  • Potential model-selection ambiguity: the paper states that S and λ sensitivity analyses were conducted on the full MMLongBench test set. It does not clearly establish whether final defaults were fixed independently of test-set results.
  • Automatic evaluation still matters: 96.7% agreement is strong, but the primary reported metric remains GPT-4.1 binary judging rather than exact-match or a fully human-scored benchmark.
  • Failure taxonomy is limited: the qualitative case is useful, but there is no deep analysis of when page beliefs become confidently wrong, when spatial propagation amplifies a false positive, or how uncertainty behaves under adversarial/noisy documents.
  • Efficiency metric is narrow: 2.40× “relative efficiency” is based on retrieval–reasoning invocation cost, not a full end-to-end cost model including preprocessing, retrieval, reranking, storage, hardware amortization, or wall-clock throughput.
  • Generality remains unproven: the method may be conceptually transferable to other retrieval agents, but the source only evaluates document QA.
Source claim: “Explicitly modeling and continuously updating document exploration states is key to improving long-document reasoning.”
Appraisal: Supported within the evaluated DocVQA setting, especially by controlled comparisons, retrieval-recall trajectories, and ablations. The claim should be narrowed to “improves this class of long-document retrieval-reasoning systems” until cross-task and deployment evidence exists.

Implementation / research takeaways

1. Treat retrieval state as a first-class objectPersist page/entity relevance separately from prompt history. A typed state object can be inspected, updated, logged, and tested.
2. Separate stable and volatile memoryDocument schema can be cached across queries; page beliefs and episodic notes should be query-local and dynamically updated.
3. Preserve uncertaintyA distribution over relevance is more useful for multi-round exploration than a single deterministic score because uncertain pages can still be sampled.
4. Feed reasoning back into retrievalReasoner outputs such as useful/irrelevant evidence and missing-information notes can become explicit control signals instead of hidden chain context.
5. Use local structural priors carefullyNeighbor-page propagation is a cheap way to exploit document continuity, but should be bounded to avoid cascading false positives.
6. Delay fine-grained parsing until neededPage-level retrieval followed by selective table/region crops is more economical than fully parsing every page at maximal resolution.
7. Measure retrieval recovery, not only answer accuracyEvidence Recall and All-Hit Rate expose whether iterative retrieval is actually fixing early misses.
8. Build an anti-loop contractExplicitly record already-seen evidence and instruct the retrieval policy not to request the same pages/elements again unless revisiting is justified.
Do not overclaim. DocMemo is strong evidence for a particular long-document retrieval architecture, not proof that Bayesian memory is universally superior for LLM agents. The paper is best used as a build pattern and experimental reference, not as a general theory of agent memory.
