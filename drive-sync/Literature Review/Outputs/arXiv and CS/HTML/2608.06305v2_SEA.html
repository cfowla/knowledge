One-page synthesis

Core thesis. For exactness-critical long documents whose numeric meaning depends on inherited layout context, pre-chunking plus similarity-ranked top-k retrieval can be the wrong interface. A tool-capable model may do better when it can search the intact converted document, inspect structure, and choose evidence spans after the query is known.

The paper makes this mechanism measurable rather than relying on a generic “agents search better” claim. Its 780-page test document is 86.8% table rows, numeric values repeat 3.68-fold, and the governing unit header is a median 13 lines above a numeric row. A strengthened table-aware chunker reduces unitless 2,000-character chunks from 18.0% to 0.3%, but 27-30% of numeric chunks still lack a fiscal-year header across every tested chunk size. That residual context loss is the main mechanistic argument against query-independent partitioning.

READ exposes deterministic list/outline/grep/read operations over the converted Markdown. On 51 verified questions, it scores 58.8% versus 15.7% for the matched dense baseline, 27.5% for an iterative agent using vector top-k, and 29.4% for hybrid retrieval. A dense sweep finds a much stronger best configuration at 35.3%; READ still leads it by 23.5 points (Holm-adjusted p=0.017). The critical negative result is BM25 at 51.0%: READ is not significantly better. Therefore, the evidence supports “embedding-free retrieval can be better on this document,” not “agentic search beats lexical retrieval.”

Counterweights. READ is not the most grounded system, its ablations numerically outperform the full operation set, and it is more expensive and slower. The benchmark is small, author-built, and expanded after an earlier experiment revealed coverage gaps. External validity is consequently low despite unusually good transparency about those limitations.
Best use. Treat this as a design-and-evaluation paper: a strong reference for retrieval-interface resolution, line-level provenance, conversion-aware benchmarking, failure taxonomies, and steelmanning retrieval baselines. Do not treat it as general evidence to remove vector retrieval from RAG systems.

Section condensation

Abstract

The paper argues that the default long-document RAG contract - pre-partition the document, embed chunks, and return a fixed top-k set - can be structurally mismatched to exactness-critical financial and regulatory documents. Its motivating failure is contextual inheritance: a numeric row can be separated from the header that supplies its unit or fiscal year, while many near-identical values compete in one embedding space. READ (Reliable Embedding-free Agentic Document-search) instead keeps the converted document intact and exposes deterministic lexical search, structural navigation, and bounded span reads so the agent can widen context after seeing where evidence lies.

On one 780-page government financial report and 51 verified questions, READ scores 58.8% exact-figure accuracy versus 15.7% for the matched dense top-k baseline; the best dense setting found in a later sweep reaches 35.3%, still 23.5 points lower. The paper deliberately narrows its claim: BM25 reaches 51.0% and is statistically indistinguishable from READ, so the evidence separates embedding-based from embedding-free retrieval on this document rather than proving that agentic search is superior to lexical retrieval.

1. Introduction

The introduction defines the target class as long, overwhelmingly tabular, exactness-critical documents such as financial statements, audit reports, statutory filings, and regulatory returns. The paper attributes the failure of conventional RAG to three coupled properties: high tabularity, repeated near-identical numbers, and meaning inherited from layout. Its motivating question requires combining two operands 47 lines apart in the same statement; the answer is not printed and therefore cannot be recovered by lookup alone.

The study plan has three parts: measure the document properties rather than assume them; construct a stronger table-aware chunker that carries unit and fiscal-year context to avoid attacking a weak baseline; and compare READ against dense, sparse, hybrid, and iterative vector-search controls under a paired protocol. The contribution framing also adds a conversion-fidelity ceiling and a mechanically checkable groundedness metric.

2. Related Work

The related-work section positions READ against dense/sparse RAG, long-document and spreadsheet retrieval, agentic tool use, and recent direct-corpus-access systems. The authors argue that prior work often adds structure-aware indexes, multi-granular embeddings, reranking, or agent loops while retaining an offline retrieval representation. Their alternative is to expose simple deterministic operations over the converted corpus and let the model decide what evidence span to inspect next.

The paper distinguishes itself from multi-document search work by focusing on structure navigation inside one extremely long tabular file, with binary exactness-sensitive answers and some derived quantities. It also emphasizes a practical difference: the agent searches imperfect PDF-conversion output rather than clean text, making normalization and conversion failure modes part of the retrieval problem.

3. Two Retrieval Interfaces

Interface A is the conventional embedding-mediated top-k pipeline: partition the document, embed each chunk, and rank chunks by query-vector similarity. The paper emphasizes four consequences for the target setting: lossy projection into vector space, a fixed evidence budget, opaque selection rationales, and partitions that can break inherited context because units and fiscal years are declared above the numeric row they govern.

Interface B exposes deterministic SEARCH, OUTLINE, and READ primitives. The agent can search for anchors, inspect document structure, read a bounded contiguous region, then refine or expand. READ is span-addressed rather than chunk-addressed, so evidence boundaries are chosen after retrieval begins. Each tool response is a reproducible function of document text plus arguments, making the sequence of operations an inspectable evidence trail.

4. The Setting, Measured

The testbed is the Gujarat Finance Accounts 2024-25, Volume I, converted to Markdown with pymupdf4llm. The converted corpus has 19,198 non-empty lines, 16,664 table rows (86.8%), 58,791 numeric tokens but only 15,960 distinct numeric tokens (3.68x repetition), and median table width of seven columns. Unit declarations occur above numeric rows at a median distance of 13 lines, p90 26, maximum 143; the unit may be lakh or crore, differing by a factor of 100.

Fixed-size chunking loses this inherited context severely at small sizes: 67.4% of numeric chunks are unitless at 800 characters. A backward-looking table-aware chunker largely fixes unit loss; at 2,000 characters, unitless chunks fall from 18.0% to 0.3%. However, 27.2-30.1% of table-aware chunks remain without a fiscal-year header across a five-fold size sweep. The authors treat this nearly flat residue as the key evidence that some context loss is intrinsic to query-independent partitioning rather than a chunk-size tuning problem.

5. READ

READ is a read-only MCP server over Markdown. The four exposed tools are list, outline, grep, and read; paths are jailed to the corpus root and returned evidence is line-addressable. grep uses normalized matching, while read accepts explicit start/end lines and is bounded to avoid context flooding. There is no embedding model, vector index, or learned retrieval component inside the server.

Normalization is narrow but important on converted tables. The corpus includes split words, emphasis markers, spurious empty cells, page headers, statement-number variants, and thousands separators. Across 12 matching probes, normalization changes the outcome for two: an ungrouped numeric reverse lookup and a phrase split across table cells. Separately, the conversion audit finds 483 artifact instances; 381 numeric rows (3.0%) are affected and 11 rows (0.09%) contain magnitude errors. The authors therefore create a conversion-limited benchmark category rather than charging these irrecoverable errors to retrieval systems.

6. Evaluation Protocol

All systems share Gemini 2.5 Pro as the generator and a common answer format, accounting, and paired question set. Dense retrieval uses BAAI/bge-base-en-v1.5; hybrid retrieval combines dense and BM25 with reranking; the key control is agentic RAG, which gives the same iterative agent a vector top-k tool rather than READ's lexical/structural operations. Retrieval baselines use the table-aware chunker so the comparison does not depend on an easily repairable chunking defect.

The 51-question benchmark spans lookup, arithmetic, aggregation, navigation, unanswerable, and conversion-limited categories. Gold evidence is line-addressed and subjected to mechanical checks for figure presence, table-column consistency via accounting identities where available, and non-occurrence of derived answers. Evaluation uses deterministic exact-figure matching, an LLM judge as a separate signal, mechanically computed groundedness, exact McNemar paired tests, paired bootstrap intervals, and Holm family-wise correction.

7. Pilot Observations

The two-question pilot is presented as mechanism exploration rather than evidence. Dense retrieval repeatedly supplied only part of the motivating question's evidence and therefore abstained, whereas READ found both operands and computed the unprinted difference. The pilot also established that iterative retrieval substantially increases token use and cost.

More importantly, the authors document an analysis-layer bug they almost interpreted as a provenance failure: their section-attribution code mishandled statement headers rendered as table rows. Manual inspection showed the model was correct and the analysis was wrong. This incident motivates the paper's emphasis on raw-line replay and illustrates how an expected model failure can be manufactured by downstream evaluation code.

8. Results

READ achieves 58.8% exact-figure accuracy (95% CI 45.2-71.2) on 51 questions. The matched dense baseline scores 15.7% (8.2-28.0); the paired difference is +43.1 points (95% CI 27.5-56.9; Holm-adjusted p=0.00002). Agentic RAG reaches 27.5%, leaving READ +31.4 points ahead (p=0.012), which is the strongest evidence that iteration alone does not explain the gap. Hybrid scores 29.4% and is also significantly lower than READ. BM25 scores 51.0%, only 7.8 points behind READ, with an interval spanning zero and Holm-adjusted p=1.00.

The mechanism concentrates in numeric lookup: READ scores 70.8% on the 24 single-figure questions versus 12.5% for dense. Dense never surfaces gold evidence on 13 questions versus four for READ and abstains on 11 answerable questions versus one for READ. Yet READ does not dominate all quality axes: groundedness is 58.0%, below BM25 (67.3%) and hybrid (72.0%), and both READ ablations score 66.7% without statistically significant differences. READ is also the most expensive/slow system at $0.058 per question and 31.4 seconds versus dense at $0.023 and 12.7 seconds.

9. Limitations

The main external-validity constraint is severe: one financial report, one PDF converter, one generator backbone, and 51 questions. The measured conversion ceiling, unit-header distances, and lexical behavior may change with other document classes or converters. READ also assumes a tool-capable model and enough surface vocabulary overlap to form useful lexical anchors; settings dominated by paraphrase mismatch may favor dense or hybrid retrieval.

The benchmark is author-built and was expanded after an earlier 25-question experiment exposed coverage gaps. Mechanical gold checks reduce some annotation risk, but the growth was not preregistered and the authors knew the hypothesized weakness of chunk retrieval. Statistical power is limited for small differences; the READ-BM25 gap remains unresolved. READ's lower groundedness than BM25/hybrid weakens any broad interpretability claim, and its higher variable cost may be unsuitable for high-volume use.

10. Conclusion

The conclusion restates the measured structural argument: this report is heavily tabular, contains repeated numbers, and depends on inherited unit context; even a strengthened chunker leaves fiscal-year context missing in roughly 27-30% of numeric chunks. READ replaces query-independent partitioning and similarity ranking with deterministic, replayable document operations and performs much better than dense retrieval on the study benchmark.

The authors explicitly bound the claim. The result does not establish that embeddings are obsolete, dense retrieval is generally weak, or agentic search beats lexical search. BM25 captures much of the gain at lower cost. The supported interpretation is narrower: for this long structured document, embedding-mediated top-k is a poor interface for exact evidence acquisition, and an inspectable embedding-free interface is a viable alternative.

Appendix A. Converter Comparison

Four PDF-to-Markdown backends were evaluated before retrieval-system development. pymupdf4llm was selected because it kept row labels aligned with table figures; cloudconvert collapsed many rows into large joined cells, markitdown detached row labels from numeric rows, and docling did not complete under the test environment. Supporting counts show that seemingly simple fidelity metrics such as digit count or glyph error would have favored a structurally worse conversion.

The appendix is important because Section 5's conversion ceiling depends on the chosen converter. The authors do not present this as a general converter benchmark: the judgement is one-document, non-blinded, and environment-dependent.

Appendix B. Implementation Details

The appendix specifies each MCP operation, normalization rules, chunker mechanics, and model stack. grep returns line numbers that can be passed directly into read; normalized matching generates spaced and squashed forms; the table-aware chunker scans backward for unit and year/as-at headers and caps carried context so it cannot dominate the chunk. Chunker versioning is part of the index cache key.

All systems use Gemini 2.5 Pro via a manually controlled tool loop so calls, arguments, and exposed text are logged. A decoding bug discovered during early runs allowed thinking tokens to consume the output budget and produce empty responses; after two of 175 early cells were affected, thinking was capped at half the output allowance. This is reported as a silent harness failure that could bias systems with different budgets.

Appendix C. Benchmark Details

The benchmark includes 24 lookup, 9 arithmetic, 6 navigation, 5 aggregation, 5 unanswerable, and 2 conversion-limited questions. Difficulty is 32 hard, 13 medium, and 6 easy; 10 answers are derived rather than printed. Evidence extends deep into the report: 14 questions have all evidence after printed page 100, and the widest question spans 3,202 converted lines.

Batch admission requires mechanical checks: every expected figure must appear near a declared gold line; table rows are checked against internal arithmetic identities where available to guard against column-shift annotation errors; and derived answers are searched across the whole corpus so printed values cannot masquerade as arithmetic questions. Thirteen drafted questions that had not cleared checks were excluded.

Appendix D. Dense-RAG Sweep

The authors sweep six dense configurations over chunk size 2,000/4,000 and k=4/8/16, adding 306 completed evaluation cells. Retrieval depth matters more than the tested chunk-size range: at 2,000 characters, moving k from 8 to 16 raises accuracy from 17.6% to 35.3%; chunk-size changes at fixed k stay under four points and are non-monotonic.

READ remains significantly better than all six configurations after Holm correction. Against the best measured dense configuration (2,000, k=16), the margin is +23.5 points (95% CI 5.9-39.2; p=0.017). That setting costs $0.029 per question versus $0.021 at k=8. Chunk sizes below 2,000 were not measured successfully and remain open rather than inferred.

Appendix E. Example Trajectories

The dense example returns eight chunks containing the Revenue Surplus but not the Fiscal Deficit and correctly declines to calculate the requested difference. It takes about 11 seconds and $0.021. The authors use this to show a retrieval-interface failure rather than a generator reasoning error: once the fixed top-k context omits an operand, the generator cannot repair the evidence set.

The READ trajectory takes eight operations: repeated targeted greps, an outline call, and two explicit line reads that widen context after search results are inspected. It returns the correct Rs.30,021.95 crore difference but takes about 49 seconds and $0.097. The trajectory also includes a redundant search, illustrating both the auditability benefit and the extra cost/inefficiency of open-ended tool use.

Algorithms and workflows

Workflow - Embedding-mediated top-k

Input: query q and precomputed chunk embeddings.
Process: partition document offline -> embed chunks -> rank by cosine similarity -> expose exactly k chunks.
Output: similarity-ranked evidence slice.
Failure modes: lost inherited context, near-duplicate numeric confusion, fixed evidence budget, opaque exclusion of competing chunks.
Human/auditability: answer evidence can be inspected, but selection rationale is not reconstructable beyond scores.

Workflow - READ locate-read-refine loop

Input: raw converted document plus user question.
Process: hypothesize lexical anchor -> grep -> inspect location/outline -> read bounded span -> extract or refine -> repeat as needed.
Output: answer plus line-addressed evidence trajectory.
Failure modes: poor lexical anchors, wasted/redundant operations, high variable cost, generator still may overstate unsupported figures.
Governance: deterministic tool calls, root jail, bounded reads, replayable line references.

Workflow - Normalized matching

Input: query and converted line.
Base transform: Unicode NFKC -> remove emphasis markers -> case-fold.
Spaced form: replace table cell boundaries with spaces; collapse whitespace.
Squashed form: remove cell boundaries, whitespace, and thousands separators.
Match: succeed if query occurs in either normalized shadow form.
Failure boundary: cannot restore characters/decimals that conversion physically moved or destroyed.

Workflow - Table-aware chunker

Input: ordered converted lines and target chunk size.
At each boundary: scan backward for nearest unit declaration and nearest fiscal-year/as-at header -> emit them in source order -> cap seed/context line budgets -> append current chunk body -> advance forward.
Safety/reproducibility: forward-only to avoid infinite rewind; chunker version included in index cache key.
Residual failure: fiscal-year header remains absent in ~27-30% of numeric chunks across sizes.

Workflow - Benchmark validation and grading

Question admission: evidence presence check -> table-column arithmetic identity check where available -> derived-answer non-occurrence check.
Scoring: deterministic numeric exactness + independent LLM judge + mechanical groundedness.
Statistics: paired exact McNemar -> paired bootstrap delta interval -> Holm correction.
Failure handling: incomplete/uncleared drafted questions excluded; converter-damaged items labeled separately.

Workflow - Dense sweep

Hold fixed: 51 questions, generator backbone, graders.
Vary: chunk size {2,000,4,000} x k {4,8,16}.
Evaluate: 306 additional cells.
Result: depth is the dominant lever; best measured dense 35.3% at 2,000/k16; READ still +23.5 pp with corrected p=0.017.
Open cell: sub-2,000 chunk sizes not successfully measured.

Workflow - Example trajectories

Dense: one top-k retrieval -> one operand missing -> generator abstains.
READ: several greps -> outline -> further greps -> two bounded reads -> both operands available -> arithmetic answer.
Trade-off: example READ is correct and replayable but ~4.6x cost and ~4.5x latency of dense.
Interpretive value: makes retrieval failure versus reasoning failure visible.

Evaluation and appraisal

Verdict: Read first. The paper is unusually useful for building or reviewing evidence-grounded RAG systems because it turns retrieval failure into measurable document properties and pairs the architecture with reproducibility/audit controls. Trust the narrow within-document findings more than the generalization claim.
Relevance
10/10

Rationale: Directly addresses long-context RAG, agentic retrieval, provenance, and auditable evidence acquisition.

Evidence basis: The paper tests retrieval-interface design and failure analysis on a concrete exactness-critical corpus.

Principal limit: Relevance is high even though the domain is financial rather than biomedical.

Would change with: Would fall if the user only needed generic web or short-document RAG; would rise no further.

Novelty
8/10

Rationale: The combination of inherited-unit measurement, conversion ceiling, and deterministic retrieval-interface framing adds useful empirical structure.

Evidence basis: Unit-header distance analysis, table-aware steelman, conversion audit, and agentic-vector control are integrated into one study.

Principal limit: Direct corpus access and lexical-agent ideas have related precedents, acknowledged by the paper.

Would change with: External replications showing the same mechanism across structured document classes would strengthen novelty.

Method strength

Implementation / practice takeaways

1. Measure the corpus before choosing retrieval. Quantify tabularity, repeated values, inherited headers, and how far context lives from the target row. Use those measurements to choose or reject chunking assumptions.
2. Treat conversion as part of the retrieval system. PDF-to-text errors can set a hard ceiling. Build conversion-damage audits and separate irrecoverable items from retriever failures.
3. Expose deterministic document operations. A minimal locate -> inspect structure -> read span interface can be easier to audit than an opaque similarity ranking, especially when exact evidence provenance matters.
4. Steelman vector baselines. Add missing structural context, tune retrieval depth, and report the best measured configuration. The dense sweep changes the comparison from 15.7% to 35.3%.
5. Separate retrieval failure from generation failure. Log whether gold evidence ever entered context, whether the system abstained despite answerability, and whether stated figures were actually supported.
6. Keep a lexical baseline. BM25 at 51.0% is the paper's most important guardrail against an overly broad “agentic retrieval wins” conclusion.
7. Make trajectories replayable. Store tool arguments, line spans, and result records so unexpected findings can be checked against the raw corpus rather than inferred from aggregate metrics.
8. Budget for agentic cost. Open-ended search may buy evidence coverage at materially higher token, latency, and dollar cost. Add bounded reads, call budgets, caching, and failure-stop rules before production use.
