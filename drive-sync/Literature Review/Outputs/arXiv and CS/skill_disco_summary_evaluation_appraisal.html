One-page synthesis

Core thesis: agents should not repeatedly solve procedurally similar tasks from scratch. In finite-state-machine-like environments, successful traces can be mined for shared parameterized control-flow structures, then compiled into callable, executable, and verifiable skills that reduce reasoning burden and transfer procedural knowledge across models.

SKILL-DISCO frames procedural skill discovery as extraction of reusable PFSM subgraphs from successful traces. The paper’s strongest idea is not simply “store prior workflows,” but “distill shared transition structure, define a typed contract, synthesize executable code, verify it on held-out tasks, and expose it as a skill library.” This matters for agent systems because it separates durable procedural memory from brittle prompt-context memories and makes skill reuse testable before deployment.

Empirically, the method improves success rate and turn efficiency on ALFWorld and WebArena, with especially large transfer gains for smaller models on some settings. The most important caution is scope: the authors explicitly restrict the approach to tasks with reusable executable structure. The method depends on successful traces, competent LLM-based trace normalization and code synthesis, and verification tasks that adequately cover the skill’s possible runtime states.

Section-by-section condensation

Abstract

The abstract identifies a recurring inefficiency in LLM agents: they often solve similar task instances from scratch, incurring unnecessary reasoning cost and long execution traces. Prior work explored workflow reuse and executable skill induction, but the paper argues that it remains underspecified when procedural skills are meaningful and how common structure should be represented across successful traces.

The authors restrict the problem to FSM-defined scenarios and define procedural skills as reusable parameterized control-flow subgraphs. SKILL-DISCO distills PFSM subgraphs from successful traces and compiles them into callable, executable, and verifiable procedural skills; experiments on ALFWorld and WebArena report higher success rates and fewer agent turns across benchmarks and model scales.

1. Introduction

The introduction motivates procedural skill reuse by contrasting repeated independent task solving with accumulated reusable procedures. Existing experience-reuse methods may synthesize workflow or skill artifacts directly from successful traces, but without an explicit structure target the resulting libraries can fragment into redundant, trace-specific routines rather than robust procedural logic.

The paper’s main move is to make the scope explicit: procedural discovery is meaningful in FSM-defined scenarios where transitions are finite and deterministic and successful traces can be treated as paths in an unknown transition graph. The contributions are: formalizing the setting, representing skills as parameterized control-flow subgraphs under parameter binding, introducing a distillation-and-compilation framework, and showing success/efficiency gains with compact skill libraries that transfer across model scales.

2. Preliminaries

The preliminaries define FSM-defined scenarios as finite state/action systems with deterministic transition functions, initial states, and goal states. A primitive operator has input/output spaces, a precondition, and a post-evaluation predicate. Successful traces are finite observation/action records that correspond to an underlying path from a valid initial state to a goal state.

The paper then introduces PFSM-based procedural skill discovery. A PFSM abstracts concrete states and actions into parameterized states and actions, allowing different concrete paths to instantiate the same control-flow pattern. A desirable skill set should have coverage across multiple successful traces, utility for reaching goals, and compactness - neither single-instance overfitting nor trivial primitive-action fragments.

3. SKILL-DISCO

SKILL-DISCO has two phases. The distillation phase approximates the latent lifting function from raw traces to reusable PFSM subgraphs by normalizing raw traces into executable intermediate programs, extracting subgoal-level operations, and clustering fragments that share parameterized control-flow structure. Each cluster is treated as an approximate PFSM subgraph and a candidate skill.

The compilation phase converts each candidate into an executable artifact. It builds a typed skill specification containing signature, parameters, return type, description, behavioral requirements, side effects, and metadata; then it synthesizes Python code and verifies it on held-out tasks for runtime correctness, postcondition satisfaction, and action savings. Skills that fail verification are refined or discarded.

4. Experiments

The experiments ask whether SKILL-DISCO improves end-to-end success and turn efficiency, transfers across model families and scales, is invoked reliably, and depends on both distillation and compilation. The setup uses ALFWorld household tasks and WebArena web-navigation tasks, with strict induction/evaluation splits: 200 ALFWorld train tasks for induction and the 134-task unseen split for evaluation; WebArena’s 812 tasks are split into 406 induction and 406 evaluation tasks.

Against ReAct, CodeAct, AWMoffline, and ASIoffline, SKILL-DISCO improves success rate and reduces average turns in the main GPT-4o experiments. Transfer experiments show that a GPT-4o-induced skill library improves most smaller and larger target models, especially Qwen3.5 models in ALFWorld and Qwen3.5-4B in WebArena. Skill-usage statistics show much smaller libraries than ASIoffline, higher primitive-step compression, and lower execution-error rates.

5. Related Work

The related-work section positions SKILL-DISCO among LLM agents, workflow reuse, experience storage, and executable skill generation. The authors contrast it with ReAct and CodeAct-style agents that do not durably reuse procedural knowledge, and with natural-language experience memory systems such as Reflexion, AWM, and Trace2Skill that leave skills as text interpreted again at inference time.

The paper also distinguishes SKILL-DISCO from tool/workflow generation systems and per-trajectory skill-induction systems such as Voyager and ASI. Its claimed distinction is corpus-level consolidation: repeated operations are semantically clustered into compact executable skills so the library scales with distinct behaviors rather than episode count.

6. Conclusion

The conclusion restates the central claim: procedural skill discovery should make shared execution structure explicit. Skills are formulated as reusable PFSM subgraphs under parameter binding, and SKILL-DISCO distills high-coverage trace structures into executable, verifiable skills.

The empirical conclusion is that ALFWorld and WebArena results support improved success rate and turn efficiency from structurally grounded procedural skills. The conclusion is strongest when read as support for reusable execution structures in procedural agents, not as a universal theory of agent memory.

Limitations

The paper acknowledges three core limitations. First, the method is intended for procedural tasks such as navigation, web automation, and tool use, and it offers no benefit for pure NLP tasks where success depends on linguistic understanding rather than executable procedures. Second, pipeline quality depends on the compiler LLM’s reasoning and code-generation ability; weaker compilers can produce incorrect or overly specific skills.

Third, the method requires successful traces. If a domain has sparse success even for frontier models, there may be too little signal for reliable corpus-level skill extraction. These limitations are central: the approach is best understood as a compiler for recurring procedures observed in successful behavior, not as a general self-improvement method.

Appendices

Appendix A adds token and cost reporting, including pricing assumptions and per-episode token/cost breakdowns. It shows that efficiency is not uniform: ALFWorld generally improves or holds cost nearly flat, while WebArena skill augmentation can increase per-episode cost despite fewer turns and lower output tokens.

Appendix B exposes the prompts for each pipeline stage, which is unusually useful for implementers. Appendix C shows representative compiled skills for ALFWorld and WebArena, illustrating the intended shift from natural-language memory to reusable, state-aware, environment-adaptive executable procedures.

Method and pipeline extraction

Reusable architecture: SKILL-DISCO is best represented as an offline compiler that converts a corpus of successful traces into a compact, verified runtime skill library.

Five-stage pipeline

SKILL-DISCO PIPELINE

INPUT:
  - Successful agent traces from a procedural environment.
  - Primitive environment actions and observations.
  - Induction/evaluation split to avoid evaluating on traces used for skill discovery.

DISTILLATION PHASE:
  1. Trace normalization
     - Convert raw ReAct-style logs into Python-like executable intermediate programs.
     - Preserve primitive actions, observations, order, branches, loops, and task-specific variables.
     - Make deterministic and LLM-driven decisions explicit.

  2. Subgoal-level operation extraction
     - Segment each normalized program into coherent reusable operations.
     - Keep multi-step operations; discard unit-length primitive fragments.
     - Represent each operation with identifier, summary, primitive sequence, and code fragment.

  3. Procedural skill consolidation
     - Cluster operations with shared parameterized control-flow structure.
     - Prefer high-coverage, compact, reusable clusters over trace-specific fragments.
     - Estimate reusability from trace coverage and operation statistics.

COMPILATION PHASE:
  4. Skill specification
     - Create a typed contract: name, parameters, return type, description, preconditions,
       postconditions, side effects, canonical action sequence, abstraction level, expected
       action savings, and confidence score.

  5. Synthesis and verification
     - Generate Python implementation from the contract.
     - Verify runtime correctness, postcondition satisfaction, and action savings on held-out tasks.
     - Refine failed skills up to a retry limit; discard unresolved failures.

OUTPUT:
  - Compact callable skill library with documented signatures and structured return values.

Appendix B - Pipeline prompts

PROMPT / SCHEMA EXTRACTION

Stage 1 — Trace to program transpilation
  - Role: convert raw ReAct traces into structured Python-like programs.
  - Important rule: preserve actions, observations, reasoning, mistakes, and recovery steps.
  - Design pattern: make deterministic control flow explicit and reserve LLM calls for uncertain/adaptive steps.

Stage 2 — Semantic operation extraction
  - Role: group consecutive action/observation pairs into coherent subgoals.
  - Important rule: environment step log is authoritative because code conversion may drop actions.
  - Output: JSON with task_summary and operations.

Stage 3 — Operation clustering
  - Role: group operations by reusable action/observation pattern and semantic goal.
  - Important rule: ignore incidental differences in object, location, page, or task instance.
  - Bias: prefer fewer, larger, uniform groups when in doubt.

Stage 4 — Skill contract definition
  - Role: convert clusters into typed APIs.
  - Contract contains: skill name, description, docstring, typed parameters, return type,
    preconditions, postconditions, side effects, canonical action sequence, abstraction level,
    estimated action savings, and confidence score.

Stage 5 — Skill synthesis
  - Role: synthesize self-contained Python implementation from the contract.
  - Important rules: use only env.step and stdlib, match action syntax, branch on latest observation,
    honor every parameter, append every action/observation pair to process_trace, return structured Dict.

Method

METHOD APPRAISAL

Strengths:
  - Structural target is explicit: reusable PFSM subgraphs, not free-form summaries.
  - Pipeline separates discovery, specification, synthesis, and verification.
  - Skills have structured interfaces and return values, enabling continuation by the caller.
  - Verification screens out skills that fail runtime correctness or postconditions.

Concerns:
  - LLM-driven normalization, operation extraction, clustering, and synthesis can introduce errors.
  - The quality of verification depends on held-out task coverage and environment representativeness.
  - The formal FSM framing may be cleaner than many real-world partially observable or stochastic workflows.
  - Successful traces only capture what worked, not necessarily why other plausible procedures fail.

Failure and generalization analysis

The method’s biggest real-world risks are wrong abstraction boundaries, over-broad skill contracts, under-specified preconditions, insufficient verification coverage, and model misuse of a skill outside its intended state. The paper shows reliability gains versus ASIoffline, but production use would require stronger sandboxing, versioning, permissioning, telemetry, rollback, and negative-test suites.

Main strengths

  • Explicit scope: the paper does not pretend all tasks admit procedural skills; it grounds the method in FSM-defined scenarios.
  • Good abstraction target: skills are parameterized control-flow structures, not merely summaries or trace snippets.
  • Compactness matters: the comparison to ASIoffline and the no-distill ablation show why library size and consolidation are central.
  • Verification loop: compiling and checking skills before library admission is the right operational pattern.
  • Strong implementation clues: prompts, schemas, and representative skills expose enough of the pipeline to reproduce a simplified version.

Main limitations

  • Benchmark scope: only ALFWorld and WebArena are tested; the evidence does not establish broad transfer to arbitrary agents.
  • LLM compiler dependency: trace normalization, clustering, contract writing, and code synthesis depend on LLM competence.
  • Successful-trace dependency: sparse-success domains may not provide enough positive examples for reliable skill mining.
  • Verification depth unclear: the paper reports held-out verification but does not fully establish coverage of all runtime states a skill may encounter.
  • Cost is mixed: WebArena shows success and turn gains with increased cost in reported GPT-4o settings.
  • Governance gaps: production deployment would need permission boundaries, generated-code review, artifact logging, and safety constraints beyond the benchmark harness.

Implementation and practice takeaways

Build-useful takeaway: Adapt SKILL-DISCO as a promotion pipeline for procedural memory: traces should become durable skills only after structural consolidation and deterministic verification.
Build next
A staged skill-promotion pipeline

Start with logs from repeated workflows. Normalize them, extract candidate subgoals, cluster by structure, define typed contracts, synthesize code or deterministic templates, and run verification before any skill becomes callable.

Do not do
Do not store every success as a skill

The no-distill ablation is the clearest warning in the paper: large trace-specific libraries can perform much worse than no skill library.

Measure
Success, turns, tokens, cost, errors

Track the same operational metrics: success rate, turns, input tokens, output tokens, cost, skill count, primitive steps collapsed per call, and execution-error rate.

Add for safety
Negative tests and guardrails

Extend beyond the paper by testing when skills should not run, what states they are forbidden to modify, and how failures are logged.
