One-page synthesis

Core thesis: The paper argues that because current prompted transformer systems process trusted instructions and untrusted content through a shared embedding/attention pipeline, perfect prompt-injection prevention cannot be guaranteed by filters, alignment, or other mechanisms that operate only inside that shared pipeline. The proposed remedy is architectural separation of control and data channels, not simply stronger in-pipeline classifiers.
What is valuable

It names a useful security target, Semantic-Faithful Control, and connects prompt injection to noninterference and code-data confusion. This is a strong framing for RAG systems, agents, tool authorization, memory writes, and policy routing.

What is not established

The paper does not prove that all practical defenses fail equally, nor does it provide a deployable separation architecture. Some empirical evidence is narrow, and the theorem depends on semantic-equivalence, provenance, control-path, and genericity assumptions.

Best practical use

Use it to justify privilege separation, external policy enforcement, hard tool gates, typed channels, sandboxed execution, and blast-radius control in LLM application design.

Bottom line

Read soon / skim deeply. The framing is highly relevant to agent and RAG security, but the formal argument should be read critically rather than accepted as a settled impossibility result.

Section condensation

Abstract

The abstract frames prompt injection as a structural problem rather than a defect that can be fully patched by better training, filtering, or guardrails. The authors define Prompted Action Models, where outputs include not only generated tokens but also control-authoritative actions such as refusal, tool authorization, policy routing, and memory writes. They then define Semantic-Faithful Control as the requirement that those control outputs depend on the semantic content of untrusted input, not on semantically irrelevant representational variation.

The claimed analysis has three pieces: provenance-recovery impossibility under overlapping shared representations, control-path exposure through shared attention/value aggregation, and a finite-coverage invariance gap over large semantic-equivalence classes. The implication is architectural: complete protection requires enforced control separation rather than only better in-pipeline classification or alignment.

1. Introduction

The introduction reviews prompt injection as an LLM-integrated application vulnerability in which adversarial user data is processed alongside system instructions and causes the model to follow attacker instructions. It lists defenses such as instruction tuning, RLHF, guardrail classifiers, perplexity filtering, sandwich defenses, XML tagging, representation engineering, and circuit breakers, then argues that recent jailbreak and adversarial-suffix results show persistent fragility.

The central analogy is to Von Neumann code-data confusion: code and data share memory in classical computers; instructions and untrusted data share embedding/attention pathways in transformers. The paper's main contribution is a formal claim that shared-embedding architectures without immutable provenance enforcement cannot guarantee perfect Semantic-Faithful Control.

2. Formal Framework

The authors define a Prompted Action Model as M = (Σ, d, E, f, A), where a finite vocabulary is embedded into a shared d-dimensional space, and the model maps embedding sequences to distributions over externally observable actions. Prompted input is a concatenation x = (s || u), where s is a trusted instruction prefix and u is untrusted content; each token has provenance, but the shared embedding axiom states that once tokens are embedded, trusted and untrusted vectors inhabit the same representational space without immutable type tags.

Semantic-Faithful Control is defined as invariance of the projected control-authoritative output ΠctrlY(s||u) across semantically equivalent untrusted inputs u and u'. The paper deliberately allows control to depend on the semantic request, such as refusing harmful content, but forbids dependence on semantically irrelevant encoding changes such as obfuscation, base64, homoglyphs, or vacuous adversarial suffixes.

3. Threat Model and Scope

The theorem applies to architectures with shared-space processing, no immutable provenance enforcement, and control-authoritative outputs computed from the shared pipeline. This explicitly includes systems where refusal, tool authorization, routing, and memory-write decisions depend on control-relevant hidden states generated by the same attention/residual computation that processes untrusted input.

The theorem excludes architectures that enforce separation by construction: disjoint trusted/untrusted encoders, typed attention or hard segment masks that structurally forbid control-path contamination, and external policy engines that decide tool authorization or memory writes outside the transformer. The attack classes modeled include indirect prompt injection, unauthorized tool invocation, injected memory/policy writes, and universal adversarial suffixes.

4. The Inseparability Theorem

The proof chain starts with genericity assumptions: untrusted value perturbations can affect control-relevant hidden states, downstream readout is locally nonconstant on those perturbations, and contextual representations of trusted and untrusted content are not completely disjoint. Lemma 1 establishes overlap in raw embeddings because natural language instruction tokens and user-data tokens share vocabulary. Lemma 2 states that semantically equivalent but token-distinct inputs generally produce distinct embedding sequences.

Theorem 3 expresses Bayes-optimal provenance-recovery error as one half of 1 minus the total variation distance between trusted and untrusted representation distributions; perfect recovery requires disjoint supports. Theorem 4 states that if control-relevant nodes attend with nonzero mass to untrusted positions, untrusted content enters control-relevant computation. Lemma 5 adds that finite training, alignment, or adversarial hardening cannot certify invariance over infinite or combinatorially vast semantic-equivalence classes unless architecture enforces it. Theorem 6 combines these pieces to claim no solely in-pipeline mechanism can guarantee perfect SFC.

5. Positional and Segment Encoding Insufficiency

The paper rejects the objection that positional encodings, segment embeddings, delimiters, or special tokens solve the problem. Positional encodings identify location, not immutable provenance, and they do not by themselves prevent untrusted values from entering control-relevant computation. Soft delimiters such as [INST], <<SYS>>, or XML-like tags are ordinary tokens in the shared vocabulary and can be forged in untrusted content.

The authors distinguish these soft markers from immutable provenance channels. An architecture that attaches non-user-writable provenance tags, preserves them through layers, and prevents attention from erasing or forging them would escape the theorem. ASIDE is cited as an early example of instruction/data separation through architectural token transformation.

6. The Von Neumann Isomorphism

The paper maps classical code-data confusion to prompt injection: shared memory corresponds to shared embedding space; machine instructions correspond to system-prompt tokens; user data in memory corresponds to user embeddings; buffer overflows correspond to prompt-injection attacks. Guardrail classifiers and perplexity filters are compared to stack canaries and ASLR: useful mitigations that raise attack cost but do not eliminate the underlying architectural class.

The analogy is explanatory rather than part of the proof. The authors use it to argue that mature prompt-injection defense will require layered controls, including architectural separation, runtime mitigations, sandboxing/privilege controls, and perhaps future representational paradigms analogous to memory-safe languages.

7. Empirical Grounding

The empirical section supplies four forms of grounding. M1 measures vocabulary overlap between instruction corpora and user-data corpora across Mistral-7B, Llama-3.1, and Qwen-2.5 tokenizers. M2 measures hidden-state distribution separation with MMD across layers of Llama 3.1 8B Instruct, using 300 sequences per corpus and bootstrap 95% confidence intervals. M3 tests five prompt-injection techniques against two models under a financial-services refusal prompt and observes no compliance but measurable output-structure changes. M4 discusses abliteration as qualitative support that refusal is encoded in shared representational directions rather than hard-separated safety circuitry.

The strongest empirical support is Table 1 and Table 2/Figure 1, which show vocabulary overlap and non-disjoint hidden-state distributions. The weakest support is M3/M4: M3 explicitly does not demonstrate direct Πctrl refusal flips in that experiment, and M4 is treated by the authors as motivation rather than formal evidence because much of the reporting is community/blog-level.

8. Connection to Existing Results

The paper connects its thesis to representation-level safety work, adversarial robustness findings, prompt-injection formalization, instruction-data separation benchmarks, noninterference, and OWASP LLM Top 10 framing. It positions SFC as a transformer-specific analogue of noninterference: untrusted data should not influence privileged control flow except through authorized semantic channels.

The most practically important connection is to instruction-data separation work and ASIDE. Those sources make the paper's recommendation more concrete: architectural separation is not merely a philosophical endpoint; it is already an active design direction, although not yet a standard deployment pattern.

9. Discussion

The discussion narrows the claim: useful models need not ignore user input, and defense-in-depth remains valuable. The paper's claim is only that shared-embedding systems cannot provide perfect prevention through mechanisms that operate entirely inside the shared representational pipeline.

For deployed systems, the authors recommend treating prompt injection like buffer overflow risk: assume occurrence, limit privileges, sandbox tools, use layered mitigations, and avoid trusting any single guardrail as a complete solution.

10. Conclusion

The conclusion restates the three-part proof: shared representations prevent perfect provenance recovery, shared attention exposes control paths to untrusted content, and finite alignment cannot guarantee invariance over all encodings in a semantic-equivalence class. The claimed result is that prompt injection remains irreducible in shared-embedding architectures without enforced control-data separation.

The proposed path forward is an engineering program: structural separation of instruction and data channels, runtime mitigations, and eventually representational paradigms that eliminate shared-embedding confusion by construction.

CORE PROOF CHAIN
1. Trusted instructions and untrusted content share token embeddings and a representational pipeline.
2. Shared representations do not preserve immutable provenance; perfect provenance recovery requires disjoint distributions.
3. Useful control-relevant nodes attend to user content, so untrusted content enters the control computation.
4. Semantic equivalence classes are too large for finite training/hardening to certify all harmless encodings.
5. Therefore, perfect control invariance cannot be guaranteed by mechanisms that operate solely inside the shared pipeline.
6. Architectural escape hatch: hard separation, typed attention/masks, immutable provenance, or external policy engines.

Verdict: Read soon / skim deeply. The paper is highly relevant for LLM application security, especially RAG and agent harnesses, but the strongest practical value is architectural framing rather than a settled peer-reviewed theorem.

Main strengths

  • Defines the relevant protected surface as control-authoritative behavior, which is more useful for agents than output-only jailbreak framing.
  • Separates “user input can affect behavior semantically” from “encoding tricks can affect privileged behavior,” which is the right security distinction.
  • Provides concrete architectural escape hatches rather than merely arguing for better filtering.
  • Preserves a defense-in-depth message and does not claim mitigations are useless.

Main limitations

  • The strongest claim is an impossibility result, but the proof depends on assumptions whose necessity and sufficiency deserve peer review.
  • Semantic equivalence is difficult to define operationally; different applications may legitimately treat encodings and presentation as security-relevant.
  • M3 shows output changes but not direct strict-SFC refusal flips in the authors' own experiment.
  • The empirical section is narrow: one MMD model, limited hidden-state sampling, and no broad external validation.
  • The Von Neumann analogy is useful but could encourage overclaiming if read as literal equivalence.
Do not overclaim: This source supports the view that prompt injection is structurally difficult to eliminate in shared-pipeline systems. It does not establish that guardrails, RLHF, detectors, prompt wrappers, or monitoring have no value. It also does not prove that every architecture labeled “transformer” is equally vulnerable under every deployment boundary.

Implementation / practice takeaways

Build

Move tool authorization, memory writes, irreversible actions, and sensitive routing into external deterministic policy layers. Treat the model as an advisor, not the final authority, for privileged actions.

Design

Separate trusted instructions, retrieved untrusted documents, user requests, system policy, and tool schemas as typed data structures before model invocation. Avoid relying on text delimiters as security boundaries.

Monitor

Log provenance, retrieved snippets, policy decisions, tool-call candidates, denials, overrides, and model rationales separately. Use audit trails that survive model-context rewriting.

Test

Create adversarial fixtures with semantic-preserving encodings: base64, homoglyphs, nested instructions in retrieved text, fake delimiters, role-play overrides, multi-turn decompositions, and vacuous suffixes.

Avoid

Do not advertise prompt templates, XML tags, “ignore instructions in retrieved content,” or post-hoc detectors as complete prompt-injection prevention.

Read next

Prioritize ASIDE/instruction-data separation work, formal prompt-injection benchmark papers, representation-level refusal work, and practical agent sandboxing / tool-policy architectures.

MINIMAL AGENT SAFETY TRANSLATION
- The LLM may propose a tool call.
- A typed, external policy engine decides whether the call is allowed.
- The policy engine reads structured provenance, user permissions, tool scope, action risk, and retrieved-source trust.
- Retrieved text never directly grants permissions.
- Memory writes require schema validation, provenance labeling, TTL/versioning, and human-review triggers for high-risk categories.
- All denials and overrides are logged outside the model context.
