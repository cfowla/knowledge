One-page synthesis

Verdict: Read soon. The paper is directly useful for designing agent-evaluation harnesses and skill-library governance, but its empirical claims should be treated as benchmark-level and pre-deployment rather than validated production evidence.

Core thesis. Final verifier success is too coarse for agents that use reusable skills. A trajectory can pass an external checker while selecting a distractor skill, skipping required SOP steps, using skills in the wrong order, or omitting final checks. SkillCoach frames reliable skill-use as four trajectory-level abilities: skill selection, skill following, skill composition, and skill-grounded reflection.

Method in one sentence. For each skill-dependent task, SkillCoach derives an initial task-specific rubric from gold skills and oracle materials, judges real rollouts using observable evidence, applies validation-gated local patches, and then uses the best evolved rubric for trajectory diagnosis and rubric-filtered supervised fine-tuning.

Main empirical story. Selected tasks show much larger gold-skill gains than the original SkillsBench pool. Evolved rubrics improve gold-keypoint coverage from 71.56 to 83.70 and filtering consistency from 82.00 to 96.00. Under Gold + Distractors, strong agents retain high final accuracy but show process degradation, especially skill-selection failures. Rubric-filtered SFT improves Qwen3.5-4B from 8.0 to 24.0 final accuracy and Qwen3.5-9B from 14.0 to 32.0, while outcome-only SFT is weaker.

Main caution. The evaluation is selected, benchmark-based, and judge-assisted. The paper reports limited statistical uncertainty, no long-term deployment feedback, and no on-policy RL results. Treat the framework as a strong design pattern, not as established proof that self-evolving rubrics are safe or robust in production.
Best useDesigning process-level agent evaluation, skill-library audits, rubric-gated training data filters, and trajectory QA dashboards.
Do not use forClaims that the framework is production-validated, regulatorily adequate, or superior across non-skill agent tasks.
Key reusable ideaKeep external verifier success separate from observable process quality, then use the process rubric to filter demonstrations.

Section-by-section condensation

Abstract

The abstract positions skills as a reusable operational layer for LLM agents, covering SOPs, domain rules, tool workflows, scripts, and validation routines. It argues that realistic skill repositories create overlapping-skill failure modes that final verifier success cannot diagnose.

SkillCoach is introduced as a self-evolving rubric framework that evaluates trajectories across skill selection, skill following, skill composition, and skill-grounded reflection while keeping the external verifier separate. The authors claim improved evaluator quality, exposure of hidden process failures, and better supervision than outcome-only filtering.

1. Introduction

The introduction identifies a deployment gap: prior work often assumes that once a useful skill exists or is retrieved, an agent can use it correctly. The authors argue that enterprise skill libraries break this assumption because agents can select wrong skills, miss required steps, compose workflows incorrectly, or skip skill-specified validation.

The contribution is a process-level formulation of agentic skill-use plus a self-evolving rubric pipeline. The paper emphasizes two deployment realities: skill-dependent tasks, where gold skills materially improve performance, and distractor-augmented repositories that resemble shared enterprise libraries with overlapping procedures.

2. Related Work

The paper distinguishes its target from work on skill benchmarks, skill generation, retrieval, refinement, lifecycle management, and agent trajectory evaluation. It acknowledges closely related directions such as SkillsBench, SkillLearnBench, SkillFlow, Agent-as-a-Judge, AgentProcessBench, ToolPRMBench, AdaRubric, Autorubric, and Counterfactual Trace Auditing.

The claimed gap is specific: existing approaches do not explicitly ground process rubrics in concrete skill-library structure, including gold skills, distractors, key steps, cross-skill dependencies, and skill-grounded reflection criteria.

3. Method

SkillCoach operates over tasks represented as instruction, target output/final state, executable environment, external verifier, and skill library. The library is the union of gold skills and distractors. Tasks are accepted as skill-dependent only when no-skill success is at most 0.30, gold-skill improvement is at least 0.40, and key-step coverage is at least 0.70.

The process score decomposes into selection, following, composition, and reflection. Selection is a set-level F1 over selected skills and gold skills, with negative abstention when no gold skill applies. Following scores weighted key-step completion with an evidence multiplier. Composition scores ordered dependencies and artifact handoffs. Reflection scores explicit visible checks before submission.

3.4-3.5 Self-evolving rubrics and training

The self-evolving rubric pipeline builds R0 from task instructions, candidate skills, gold/distractor skills, verifier information, and representative rollouts. A rollout agent executes in the real environment; an evidence extractor records skill reads, gold/distractor signals, tool calls, file edits, script executions, artifacts, and validation attempts. Positive judgments for following, composition, and reflection require visible evidence.

Rubric evolution uses calibration rollouts to propose local patches and hidden validation rollouts to accept or reject them. Accepted patches must pass hard gates, improve soft quality, show material improvement beyond judge confidence, and avoid structural violations. Training then retains trajectories only when they pass the external verifier and reach a rubric meta score of at least 0.95.

4. Experiments

The experiments address rubric quality, process-level diagnosis under skill libraries, rubric-filtered training, and distractor-boundary scaling. Rubric quality is evaluated on 50 paired test instances from 10 held-out task families using a human-gold process reference and an independent Gemini 3.1 Pro judge instructed to ignore verifier outcomes.

Agent evaluation shows that gold skills improve final accuracy, but distractors degrade process reliability. The SFT experiment shows that Rbest-filtered trajectories outperform outcome-only trajectories for small Qwen3.5 models. The distractor-boundary analysis isolates skill selection as candidate libraries scale to tens of thousands of skill files.

5. Conclusion

The conclusion restates SkillCoach as a way to measure and train reliable skill-use by separating process quality from external verifier success. The authors argue that evolved skill-grounded rubrics both reveal hidden failures and select better SFT demonstrations.

6. Limitations

The authors acknowledge two main limitations: selected benchmark-derived skill-dependent tasks remain smaller than production repositories, and the training study is offline SFT rather than on-policy RL or deployment feedback.

Additional appraisal limitations include limited reported statistical uncertainty, dependence on LLM-based judges, unclear artifact/code availability in the paper text, and possible sensitivity to task-selection and model-choice decisions.

Core workflow and scoring formulas

SkillCoach execution loop
1. Select skill-dependent task packages using pno <= 0.30, pgold - pno >= 0.40, and key-step coverage >= 0.70.
2. Expose gold skills plus distractors to the agent in an executable environment.
3. Collect observable trajectories: skill reads/invocations, tool calls, file edits, scripts, artifacts, final outputs, and validation attempts.
4. Score process dimensions: selection, following, composition, reflection.
5. Keep the external verifier as a separate post-hoc outcome signal.
6. Evolve rubrics through calibration-based local patches and held-out validation gates.
7. Use Rbest for diagnosis and for filtering verifier-passing trajectories before SFT.
Scoring structure
skill_selection: set-level F1 over selected skills and gold skills; negative abstention when no gold skill applies.
skill_following: weighted key-step completion multiplied by evidence support; unsupported claims do not receive completion credit.
skill_composition: weighted dependency/order/handoff score over required skill or subprocess precedence pairs.
result_reflection: weighted visible pre-submission checks over expected output/schema/task constraints.
aggregate Smeta: default weights selection 0.40, following 0.30, composition 0.20, reflection 0.10, renormalized when a dimension is not applicable.
external verifier sver: separate result in {0,1,not executable}; not part of the process meta score.

Includes 18 training task families and 10 held-out test task families. Each task uses gold skills, two cross-task distractors, and three semantically near but inapplicable distractors.

Defines Smeta and sver separately. This is important because a verifier-passing trajectory can still have poor skill-use behavior.

Prompt components cover key-step extraction, R0 generation, skill-selection evidence boundaries, skill-following judging, composition-order judging, result-reflection judging, and rubric-patch arbitration. Non-prompt components include hard verifier, validation gate, and score aggregation.

Evaluation and appraisal

Bottom line. SkillCoach is a high-value framework paper for agent-evaluation design. Its strongest contribution is the explicit separation of skill-grounded process quality from final verifier success. Its weakest point is validation maturity: the paper does not yet show robust production deployment, open reproducibility, or statistical uncertainty sufficient for strong external validity claims.

Main strengths

  • Correct target. The paper addresses a real failure mode in tool/skill agents: final outcome checks hide wrong-skill selection, skipped SOP steps, and brittle self-repair.
  • Useful decomposition. Selection, following, composition, and reflection map well to operational failure categories that can be logged and audited.
  • Verifier separation. Keeping external verifier success separate from process scoring avoids turning accidental success into a positive demonstration.
  • Implementation detail. The appendix provides enough architecture and prompt structure to guide a prototype without treating the text as a black-box method.
  • Relevant distractor analysis. The library-scaling and semantic-neighbor tests are closer to real enterprise repositories than gold-only skill settings.

Main limitations and red flags

  • Selected-task evidence. The task-dependency filter enriches for settings where skills matter, which is appropriate for the research question but limits generalizability.
  • Judge-assisted validation. Rubric quality is evaluated by an independent LLM judge against human-gold references. That is useful, but it is not equivalent to large-scale blinded human adjudication.
  • Limited uncertainty reporting. Tables report point estimates without confidence intervals, per-task variance, or significance testing.
  • Deployment gap. No long-term production monitoring, compliance auditing, latency/cost analysis, drift handling, or on-policy RL study is reported.
  • Reproducibility gap. The paper gives prompts and gate logic, but the appraised text does not provide enough executable artifacts to independently reproduce all numbers.

Confidence in appraisal

Moderate. The source is internally coherent and reports multiple convergent experiments, but the empirical strength is capped by benchmark selection, LLM-judge dependence, missing statistical uncertainty, and incomplete deployment validation.

Implementation and practice takeaways

Build-useful takeawayFor any SOP/skill repository, log explicit evidence for skill read/invocation, key-step execution, artifact handoff, and final validation rather than recording only final success.
Training-data ruleDo not use all verifier-passing traces as positive SFT demonstrations. Require process-quality gates and reject accidental success.
Rubric design ruleSeparate hard verifiers from rubric judges. A verifier can confirm output validity, but the rubric should check how the agent got there.
Skill-library governanceTrack distractor pressure. Similar but inapplicable skills are more dangerous than obviously unrelated skills.
Evaluation dashboardReport final accuracy alongside selection, following, composition, and reflection scores. A single pass rate is not enough.
Operational caveatSelf-evolving rubrics require validation gates, held-out traces, and destructive-change checks. Ungated self-editing can amplify evaluator drift.

How to reuse this in an agent/RAG evaluation stack

  1. Define a skill as an operational unit with trigger conditions, required steps, expected artifacts, and validation checks.
  2. Create a gold/distractor map for each evaluation task, including near-neighbor skills that should not be selected.
  3. Require observable trace evidence for every claimed key step: file reads, tool calls, script runs, artifact writes, and check results.
  4. Score outcome and process separately; only outcome-plus-process traces should enter training data.
  5. Add validation-gated rubric patching only after a stable baseline rubric exists and after a held-out trace set is available.

What not to overclaim

  • Do not claim self-evolved rubrics are automatically unbiased or safe.
  • Do not claim final task success proves reusable skill-use.
  • Do not assume performance under a 5-distractor setting transfers to a large production skill repository.
  • Do not replace human process-reference construction with LLM judging alone when the workflow is safety-, policy-, or compliance-sensitive.
