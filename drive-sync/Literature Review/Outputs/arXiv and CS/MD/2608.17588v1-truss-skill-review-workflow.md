# TRUSS skill-review workflow extraction

Source: TRUSS: Towards Task-Reliable and User-Safe Automated Agent Skill Generation  
Identifier: arXiv:2608.17588v1  
Primary source: https://arxiv.org/abs/2608.17588

## Source-derived workflow

The paper treats skill admission as an evidence problem tied to one exact artifact version.

1. Freeze the candidate skill package. Record the generation regime and provenance, then assign a content digest.
2. Extract functional claims as usage conditions plus observable effects. Check them against source evidence or open-world knowledge. Source evidence takes precedence when it exists.
3. Define the safety contract before admission. TRUSS uses nine properties: Control Integrity, Access Boundary, Execution Integrity, Lifecycle Isolation, Resource Boundedness, Evidence Integrity, Authority Integrity, Composition Integrity, and Transaction Safety.
4. Resolve what can be checked statically. Turn unresolved but testable criteria into explicit runtime obligations. Return contradictory or untestable criteria for revision.
5. Admit only the exact digest that passed the static gate.
6. Execute the candidate in a Controllable Execution Environment. Mount the skill read-only, isolate host resources, use synthetic task data, disable direct command networking, and route external actions through brokered mock services.
7. Check every requested action before dispatch. Preserve rejected requests as structured blocked events instead of deleting them from the trace.
8. Evaluate function and safety from the same trace. Inspect final task state, completion claims, policy violations, observer results, canary lineage, cleanup, and final environment state.
9. Convert failures into an evidence-bound revision record that points to the artifact span or runtime event that failed. Keep already satisfied criteria as preservation constraints.
10. Any edit creates a new digest and triggers the full static and runtime check again.
11. Certify only when required functional outcomes are established and applicable safety obligations are resolved for the evaluated scenarios. If the revision budget ends first, return the candidate as uncertified with residual findings.

## Pipeline adaptation for our skill-review work

This section is a model-derived adaptation of the TRUSS method, not a reported result from the paper.

For a local skill package such as `SKILL.md` plus scripts, examples, and assets, use the following review contract:

1. Hash the complete package before review. Store the hash with every finding and test run.
2. Convert the skill description into explicit expected behaviors. Each behavior needs an observable pass condition.
3. Run static checks for unsupported claims, hidden executable behavior, broad file or network access, instruction-control risks, lifecycle persistence, resource limits, authority checks, cross-component trust, and external transactions.
4. Send only unresolved but testable claims to runtime checks. Do not use runtime execution to excuse a static contradiction.
5. Run representative normal-use tests and adversarial tests in an isolated fixture. Use mock services or a broker for network, file, credential, and side-effecting actions.
6. Record every attempted tool action, including blocked actions. Keep the request, decision, returned observation, causal parent, scenario ID, and skill hash.
7. Score functional completion and safety from the same run record. A blocked unsafe attempt still counts as a safety failure for the attempted behavior.
8. Link each requested repair to the exact source span or runtime event. Re-run the entire review after any edit.
9. Label the result narrowly. A pass means the skill satisfied the stated checks in the evaluated scenarios. It does not mean the skill is generally safe outside those scenarios.

## Reusable evidence record

A practical review record should keep these fields:

```text
skill_id
skill_digest
review_run_id
functional_requirement_id
safety_property_id
artifact_span
scenario_id
requested_action
broker_decision
returned_observation
causal_parent
expected_state
observed_state
finding_status
revision_id
residual_risk
```

## Benchmark caution

TRUSS reports perfect vulnerability-detection precision and recall on its SkillInject evaluation and a 100% security pass rate on the SkillGenBench controlled probes. Those results come from the evaluated benchmarks and property observers. They do not establish general safety against unseen, adaptive, or uncovered failure modes. The paper itself reports residual attack success after repair and sensitivity to scenario coverage and executor behavior.
