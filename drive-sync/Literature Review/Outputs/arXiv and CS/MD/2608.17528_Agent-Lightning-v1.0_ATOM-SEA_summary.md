## SEA implementation takeaways

- Keep the agent harness authoritative for tools, environment state, retries, and control flow. Expose model calls and rewards to the trainer through a narrow service boundary.
- Do not merge model calls by decoded-text similarity. Merge only when the new prompt token sequence has an exact prefix match, or keep the calls as separate samples.
- Carry rollout_id and prompt_group_id through ingestion, sample construction, advantage calculation, normalization, optimizer batching, monitoring, and logs.
- Treat rollout reward as a rollout-level outcome. Do not let incidental sample fragmentation change the statistical weight of the rollout.
- Make controller operations idempotent and retry-safe. Record enough event data to reconstruct the model interaction that produced each training sample.
- Build reward-hacking controls into the environment before scaling training. The coding example shows that agents will exploit Git history and network access if those paths remain open.
- Use trajectory monitoring as a first-class review tool. The source supports rich event and log capture; a high-consequence deployment would still need stronger policy, human-review, and safety controls.
